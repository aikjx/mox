## 1. 命名归一化

### 1.1 Crate命名

- [ ] 平台基础能力: `mox-platform-{能力}-core`
- [ ] 对接能力层: `mox-{能力}-core`
- [ ] 领域核心: `mox-{域}-{能力}-core`
- [ ] 领域服务: `mox-{域}-{能力}-svc`
- [ ] SDK: `mox-{域}-sdk`
- [ ] 网关: `mox-platform-gateway-svc`
- [ ] 框架: `mox-framework`
- [ ] 基础: `mox-{platform/cloud}-foundation`

### 1.2 类型命名

- [ ] Trait: `{能力}Provider` / `{能力}Factory` / `{能力}Handler` / `{能力}Manager`
- [ ] 实现: `{厂商}{能力}Provider` / `{场景}{能力}Handler`
- [ ] 注册表: `{能力}Registry`
- [ ] 配置: `{能力}Config`
- [ ] DTO: `{动作}Request` / `{动作}Response`
- [ ] 错误: `{能力}Error`
- [ ] 构建器: `{能力}Builder`
- [ ] 枚举: `{状态}State` / `{类型}Type` / `{级别}Level`

### 1.3 文件命名

- [ ] 全部使用 `snake_case`
- [ ] Trait定义: `traits.rs` 或 `{trait_name}.rs`
- [ ] 实现: `{厂商}.rs` / `{场景}.rs`
- [ ] 注册表: `registry.rs`
- [ ] 配置: `config.rs`
- [ ] DTO: `dto.rs`
- [ ] 错误: `error.rs`
- [ ] 模块入口: `mod.rs`
- [ ] 库入口: `lib.rs`
- [ ] 二进制入口: `main.rs`

### 1.4 变量/函数命名

- [ ] 变量/函数: `snake_case`
- [ ] 常量: `SCREAMING_SNAKE_CASE`
- [ ] 类型/Trait: `PascalCase`
- [ ] 生命周期: `'a`, `'b`（短名称）
- [ ] 泛型: `T`, `U`, `K`, `V`（短名称）或描述性名称

## 2. 结构归一化

### 2.1 Crate目录结构

- [ ] 有标准 `Cargo.toml`
- [ ] 有 `src/lib.rs`（库crate）或 `src/main.rs`（二进制crate）
- [ ] 模块按职责分目录
- [ ] 每个子目录有 `mod.rs`
- [ ] 测试在 `tests/` 目录（集成测试）或 `#[cfg(test)]` 模块（单元测试）

### 2.2 lib.rs规范

- [ ] 有crate级文档注释（`//!`）
- [ ] 声明所有公开模块
- [ ] 统一重导出关键类型
- [ ] 有 `prelude` 模块（可选，方便使用）
- [ ] 不导出内部实现细节

### 2.3 模块组织

- [ ] Trait定义与实现分离
- [ ] 多个实现按厂商/类型分文件
- [ ] 配置结构体独立文件
- [ ] 错误类型独立文件
- [ ] DTO独立文件或目录

## 3. 依赖归一化

### 3.1 Workspace依赖

- [ ] 所有依赖在根 `Cargo.toml` 的 `[workspace.dependencies]` 中声明
- [ ] 子crate用 `{ workspace = true }` 引用依赖
- [ ] 版本号统一管理，不重复声明
- [ ] features统一管理

### 3.2 依赖规则

- [ ] 无循环依赖（Rust编译器会报错，但需架构上杜绝）
- [ ] 同层模块之间通过Trait依赖，不依赖具体实现
- [ ] 业务模块不直接依赖其他业务模块的内部实现
- [ ] 基础层（L1/L2）只依赖第三方库
- [ ] 无未使用的依赖（`cargo udeps` 检查）

### 3.3 第三方依赖选择

- [ ] 优先选择维护活跃、社区认可的crate
- [ ] 避免功能重叠的多个crate
- [ ] 关注crate的安全性（`cargo audit` 检查）
- [ ] 关注crate的许可证兼容性

## 4. 扩展归一化

### 4.1 可扩展点

- [ ] 所有可扩展点有Trait定义
- [ ] Trait方法有默认实现（可选，减少实现负担）
- [ ] Trait是对象安全的（可用于 `dyn Trait`）
- [ ] 异步方法使用 `#[async_trait]`

### 4.2 Factory模式

- [ ] 所有可配置创建的实例有Factory trait
- [ ] Factory trait是具体非泛型的（避免trait object调用限制）
- [ ] Factory注册到 `FactoryRegistry`
- [ ] Factory从 `FactoryConfig` 创建实例
- [ ] 配置驱动自动组装（`AutoAssembler`）

### 4.3 注册表模式

- [ ] 所有可注册实例有Registry
- [ ] Registry支持注册/注销/查询/列表
- [ ] Registry线程安全（`Arc<RwLock<HashMap>>`）
- [ ] Registry有健康检查能力

### 4.4 零改动验证

- [ ] 新增AI Provider不需要修改核心代码
- [ ] 新增连接器不需要修改核心代码
- [ ] 新增SSO协议不需要修改核心代码
- [ ] 新增插件不需要修改核心代码
- [ ] 新增协议接入不需要修改核心代码
- [ ] 替换合规实现不需要修改核心代码

## 5. 错误处理归一化

### 5.1 错误类型

- [ ] 使用 `thiserror` 定义业务错误
- [ ] 使用 `anyhow` 处理顶层错误
- [ ] 错误实现 `std::error::Error`
- [ ] 错误可转换为 `PlatformError`

### 5.2 错误码

- [ ] 使用6位数字错误码（`E{6位}`）
- [ ] 前2位分类正确（10系统/20AI/30插件/40政企/50连接器/90集成）
- [ ] 错误码在 `error-code-reference.md` 中登记
- [ ] 不使用未定义的错误码

### 5.3 错误传播

- [ ] 使用 `?` 操作符传播错误
- [ ] 关键路径有错误上下文（`.context()`）
- [ ] 不吞掉错误（`let _ =` 仅在明确不需要时使用）
- [ ] 错误日志包含trace_id

### 5.4 错误响应

- [ ] HTTP错误响应格式统一
- [ ] 包含错误码、消息、分类、trace_id
- [ ] 敏感信息不泄露到错误响应
- [ ] 可重试错误标记 `retryable: true`

## 6. 配置归一化

### 6.1 配置结构

- [ ] 使用 `config-rs` + `serde` 加载配置
- [ ] 配置结构体有 `Serialize`/`Deserialize`
- [ ] 配置有默认值（`#[serde(default)]`）
- [ ] 敏感配置支持环境变量覆盖（`${VAR_NAME}`）

### 6.2 多环境配置

- [ ] 支持dev/test/prod多环境
- [ ] 环境通过环境变量或命令行参数指定
- [ ] 各环境配置差异明确
- [ ] 敏感信息不提交到代码库

### 6.3 配置热更新

- [ ] 支持配置热更新（`ConfigHotReloader`）
- [ ] 热更新有回调通知
- [ ] 热更新不影响正在处理的请求
- [ ] 热更新有错误处理

## 7. 文档归一化

### 7.1 代码文档

- [ ] 所有公开项有文档注释（`///`）
- [ ] 文档注释包含描述、参数、返回值、错误
- [ ] 复杂逻辑有行内注释
- [ ] 示例代码在文档中（`# Examples`）

### 7.2 架构文档

- [ ] `ARCHITECTURE.md` 存在且最新
- [ ] `docs/architecture/` 下有详细文档
- [ ] 架构图清晰准确
- [ ] 模块清单完整
- [ ] 扩展指南完整

### 7.3 README

- [ ] 项目根目录有 `README.md`
- [ ] README包含项目介绍、快速开始、架构概览、文档链接
- [ ] README不包含过时信息

## 8. 测试归一化

### 8.1 单元测试

- [ ] 核心逻辑有单元测试
- [ ] 测试覆盖率达标（核心模块>80%）
- [ ] 测试用例命名清晰（`test_{场景}_{预期结果}`）
- [ ] 测试使用 `#[tokio::test]` 处理异步

### 8.2 集成测试

- [ ] 关键流程有集成测试
- [ ] 集成测试在 `tests/` 目录
- [ ] 集成测试可独立运行
- [ ] 使用测试工具（`mox-platform-test-harness`）

### 8.3 测试质量

- [ ] 测试不依赖外部服务（使用mock）
- [ ] 测试可重复运行（无状态依赖）
- [ ] 测试运行时间合理
- [ ] CI中运行所有测试

## 9. 安全归一化

### 9.1 输入验证

- [ ] 所有外部输入有验证
- [ ] 验证失败返回明确错误
- [ ] 不信任客户端数据
- [ ] 防止注入攻击（SQL/命令/路径）

### 9.2 认证授权

- [ ] 所有API需要认证（公开API除外）
- [ ] 权限检查在业务层
- [ ] 敏感操作需要额外授权
- [ ] Token有过期时间

### 9.3 数据安全

- [ ] 敏感数据加密存储
- [ ] 敏感数据脱敏输出
- [ ] 日志不包含敏感信息
- [ ] 数据主权合规（`DataResidencyController`）

### 9.4 依赖安全

- [ ] 定期运行 `cargo audit`
- [ ] 及时更新有漏洞的依赖
- [ ] 不使用已废弃的crate
- [ ] 关注依赖的维护状态

## 10. 性能归一化

### 10.1 异步编程

- [ ] 使用 `tokio` 异步运行时
- [ ] 异步方法使用 `async/await`
- [ ] 不阻塞异步线程（`spawn_blocking` 处理CPU密集型）
- [ ] 合理使用 `JoinSet` 管理并发任务

### 10.2 资源管理

- [ ] 连接池配置合理
- [ ] 超时设置合理
- [ ] 资源使用后及时释放
- [ ] 内存使用监控

### 10.3 性能监控

- [ ] 关键操作有耗时统计
- [ ] 指标可导出（Prometheus格式）
- [ ] 日志包含性能信息
- [ ] 有性能基线和告警
