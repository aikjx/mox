## 0 · v3.0 升级总览（AI 驱动）

### 0.1 核心跃迁

| 维度 | v2.0（现状） | v3.0（目标） |
|---|---|---|
| **产品范式** | 功能驱动的低代码工作台 | AI 驱动的对话中心 |
| **首页形态** | 三前端各自首页 | 单一 AI 对话中心 |
| **功能入口** | 菜单 / 路由 / 页面跳转 | 四向弹框浮层，AI 按需弹出 |
| **用户心智** | 人找功能 | AI 送功能 |
| **AI 角色** | 被动助手（NL→SQL） | 意图中枢（理解→规划→调度→执行→沉淀） |
| **流程形态** | 用户点按钮、填表单 | AI 编排 Agent，用户确认即可 |

**一句话定义**：用户出思路，AI 多跑腿。用户只需要表达"我要什么"，AI 负责"怎么做、找谁做、做到哪一步"，并且把需要的界面主动送到用户面前。

## 一、平台定位（v2.0 技术底座）

MOX 是一个**mox 模块化系统架构低代码平台**，核心能力四件套：

| 能力 | 说明 | 核心价值 |
|------|------|---------|
| **动态SQL引擎 (DSQL)** | 所有业务SQL在数据库中配置，Jinja2模板渲染，多数据源适配 | 零代码改业务，换数据库只改配置 |
| **自研知识图谱 (KG)** | 实体/关系模型，多跳遍历，与SQL双向融合 | 语义查询，行业知识快速融合 |
| **字段级权限 (RBAC+)** | 角色→菜单→操作→字段四级，可见/可写/脱敏 | 权限控制到字段，合规等保 |
| **AI智能助手** | NL→SQL、SQL优化、业务流程生成、双引擎(规则+LLM) | 自然语言驱动业务配置 |

**设计哲学**：配置驱动 > 代码编写。所有业务逻辑可配置、可导出、可迁移、可复用。

## 三、三层数据架构（核心设计）

### L1: KERNEL 架构内核（跨系统通用，可迁移）

| 模块 | 表名 | 说明 |
|------|------|------|
| SQL模板库 | `dsql_sqls` | 所有业务SQL动态配置，版本管理，Jinja2模板 |
| 数据源配置 | `dsql_datasources` | 多数据库连接配置，中间层适配 |
| 应用注册 | `dsql_apps` | 多租户应用隔离(app_key) |
| 角色定义 | `roles` | RBAC角色 |
| 权限定义 | `permissions` | 菜单/操作/API权限 |
| 字段权限 | `field_permissions` | 字段级可见/可写/脱敏控制 |

**原则**：L1 一次配置，处处复用。新系统部署直接导入 L1，零修改获得全部业务逻辑。

### L2: DATA 业务数据（按 app_key 隔离，可独立迁移）

| 模块 | 表名 | 模块 | 表名 |
|------|------|------|------|
| 产品 | `products` | 新闻 | `news` |
| 案例 | `cases` | 团队 | `team` |
| 发展历程 | `history` | 荣誉资质 | `honors` |
| FAQ | `faqs` | 招聘岗位 | `jobs` |
| 留言 | `messages` | Banner | `banners` |
| 图谱实体 | `kg_entities` | 图谱关系 | `kg_relations` |

**原则**：L2 按 app_key 严格隔离，支持单应用独立导出/迁移。导入时自动重新映射 ID。

### L3: RUNTIME 运行时数据（不导出，系统自生）

| 模块 | 说明 | 不导出原因 |
|------|------|-----------|
| 审计日志 | 所有SQL执行审计 | 新系统自生，避免脏数据 |
| 查询缓存 | Redis热查询结果 | 缓存无持久价值 |
| 会话状态 | 用户登录会话 | 新系统重新认证 |

**原则**：L3 绝不导出，保证新系统干净启动。

## 四、DSQL 动态SQL引擎规范

### 4.1 执行流程

```
用户请求 → API网关(鉴权/权限) → DSQL引擎
  ├─ 1. 按 sql_code 查找SQL模板(带版本)
  ├─ 2. Jinja2 模板渲染(参数绑定/条件分支)
  ├─ 3. 字段级权限过滤(自动注入WHERE/列裁剪)
  ├─ 4. 数据源路由(按datasource配置选择数据库)
  ├─ 5. 执行SQL(参数化查询,防注入)
  ├─ 6. 结果归一化(统一JSON格式)
  ├─ 7. 缓存写入(Redis,按cache_ttl)
  └─ 8. 审计日志(异步写入)
```

### 4.2 SQL模板规范

```sql
-- 模板: product_list
-- 版本: 1
-- 数据源: default
-- 缓存: 60秒
SELECT id, name, category, price, image, summary
FROM products
WHERE 1=1
{% if category %} AND category = :category {% endif %}
{% if keyword %} AND (name LIKE :kw OR summary LIKE :kw) {% endif %}
ORDER BY id ASC
```

### 4.3 多数据库适配

| 数据库 | 适配方式 | 状态 |
|--------|---------|------|
| SQLite | 默认内置 | ✓ 生产就绪 |
| MySQL | datasource配置切换 | ✓ 支持 |
| PostgreSQL | datasource配置切换 | ✓ 支持 |
| Oracle/SQL Server | 中间层驱动适配 | ○ 可扩展 |

**原则**：只需修改 datasource 配置，零代码切换数据库。

## 五、知识图谱引擎规范（自研）

### 5.1 数据模型

```
实体 (kg_entities):
  id, app_key, type, name, properties(JSON), created_at

关系 (kg_relations):
  id, app_key, source_id, target_id, type, properties(JSON), created_at
```

### 5.2 核心能力

- **多跳遍历**：实体→关系→实体→关系...（支持N跳）
- **按类型过滤**：指定实体类型/关系类型
- **属性筛选**：JSON属性条件查询
- **图谱可视化**：力导向图渲染
- **与SQL双向融合**：
  - 图谱导航 → 自动生成关联SQL查询
  - SQL结果 → 自动构建图谱关系
  - 语义查询 → 图谱路径 → SQL执行

## 六、权限体系规范（字段级）

### 6.1 四层权限模型

```
角色 (Role)
  └─ 权限 (Permission)
       ├─ 菜单权限: 可见/不可见
       ├─ 操作权限: 增删改查(CRUD)
       └─ 字段权限 (FieldPermission)
            ├─ 可见字段: 列级白名单
            ├─ 可写字段: 列级白名单
            └─ 脱敏字段: 自动掩码(邮箱/电话/身份证)
```

### 6.2 执行流程

```
请求到达 → 角色识别 → 菜单权限校验
  → 操作权限校验 → 字段权限注入
    → 查询: 自动裁剪SELECT列 + 注入行级WHERE
    → 写入: 校验可写字段 + 自动脱敏
  → 结果返回: 敏感字段自动掩码
```

## 九、数据交换规范 (MXDEF)

### 9.1 文件格式

```json
{
  "format": "MXDEF",
  "version": "1.0",
  "meta": {
    "exported_at": "2026-08-28T10:30:00+08:00",
    "app_key": "mox",
    "layers": {"kernel": true, "business": true, "runtime": false}
  },
  "kernel": {"sql_templates": [], "datasources": [], "apps": [], "roles": [], "permissions": [], "field_permissions": []},
  "business": {"products": [], "news": [], "cases": [], "team": [], "faqs": [], "jobs": [], "messages": []},
  "knowledge_graph": {"entities": [], "relations": []},
  "checksum": "sha256:..."
}
```

### 9.2 标准化规则

| 规则 | 说明 |
|------|------|
| 字段命名 | 统一 snake_case |
| 主键 | 统一 `id` |
| 时间 | 统一 ISO 8601 |
| 布尔 | 统一 true/false |
| 空值 | 统一 null |
| 编码 | UTF-8 无 BOM |
| 敏感字段 | 自动脱敏(邮箱/电话/身份证) |

### 9.3 三大工具

| 工具 | 命令 | 说明 |
|------|------|------|
| 导出 | `python tools/export_data.py` | 支持--app-key/--kernel-only/--business-only/--all/--split/--gzip |
| 导入 | `python tools/import_data.py file.json` | 支持--dry-run/--target-app/--kernel-only/--force/--purge |
| 校验 | `python tools/validate_export.py file.json` | 格式/checksum/外键/脱敏/重复ID检查 |

## 十、前端规范

### 10.1 三个前端应用

| 应用 | 路径 | 说明 | 路由 |
|------|------|------|------|
| 企业官网 | `frontend-ui/mox-website/` | 对外展示+管理中心入口 | home/products/news/cases/about/contact/jobs/admin/store |

| 应用商店 | `frontend-ui/mox-store/` | 应用浏览/安装/发布 | browse/my/publish |

### 10.2 设计规范

- **主题**：深色科技风，金色(#c9a15a)主色调
- **路由**：Hash路由 (`#/home`)，无需服务端配置
- **API**：file://协议自动用 `http://127.0.0.1:8600`，http/https用相对路径 `/api`
- **响应式**：PC/平板/手机三端适配
