# 专家联盟模块化与任务工作台验收（2026-09-05）

本轮以「提交任务 → 执行 → 查看结果」为主线。完成了公共模块拆分、前后端契约对齐、独立服务启动工具和错误状态治理。真实模型分析尚未验收通过：当前执行环境未配置模型，不能把空报告或模拟执行当作成功交付。

## 已落实

- 公共图模型与六维注册表下沉到 `mox-platform-graph-core`；模型提供者、注册与路由下沉到 `mox-platform-model-core`。历史服务路径保留类型再导出，知识图谱与平台接入不再依赖原业务服务实现。
- AI 流程通过 `mox-ai-flow-sdk` 暴露可嵌入能力。知识整合器迁至 `mox-kg-sdk`，Agent 依赖 SDK。仅生成候选的整合操作不再宣称已经保存知识。
- 任务 API 统一解析多层响应信封、任务编号、标题、0–1 进度、日志与 DAG。创建请求使用服务端支持的字段；删除无效的手动专家选择和不受支持的融合策略。
- 任务列表、详情和轮询拆为独立组合函数。请求不会重叠，切换选择不会被旧请求覆盖，重复操作被阻止；网络失败保留最后有效状态。100% 进度不能自动等同成功。
- 配置了远程服务后，超时或连接失败返回错误，不改写为本地空列表，也不产生本地替代任务。结果服务异常不会伪装成「尚未完成」。执行记录明确标注为节点最新快照。
- 执行器修正取消状态；就绪检查区分进程存活与真实模型已配置。无模型时拒绝提交执行，且不创建执行状态。Mock 模式不对工作台声明真实执行就绪。
- 联盟专家模式采用严格模型咨询：模型失败向上传递，不回退为空图报告。保留完整多行最终答案；前端展示专家正文、原始结果，评分标为专家自评分。旧空报告显示无有效分析提示。
- 增加受保护的 `/api/auth/me` 与已有令牌登录。令牌验证后仅保存在页面内存；路由与 HTTP 使用同一认证状态，显式验证令牌不会被旧令牌覆盖。开发模式拒绝任意无效令牌。
- Vite `/api` 代理遵循 `GATEWAY_URL`。移除专家导航中的固定演示人数和无依据的剩余时间估算。

## 本机复现

在仓库根目录执行：

```powershell
./scripts/start-alliance-local.ps1
# 已构建且源码没有变化时可使用 -SkipBuild
```

独立启动网关 33080、调度器 33100、执行器 33200，全部绑定 `127.0.0.1`。状态及日志写到 `target/alliance-local`，不占用旧实例端口。停止本次脚本启动的服务：

```powershell
./scripts/stop-alliance-local.ps1
```

停止脚本检查进程路径、启动时间与 PID，避免停止其他实例。修改服务代码后应先停止本机实例，再重新构建启动，避免 Windows 锁定运行中的 exe。

前端在 `frontend-ui` 目录执行：

```powershell
$env:GATEWAY_URL = 'http://127.0.0.1:33080'
npm run dev -- --host 127.0.0.1 --port 33020 --strictPort
```

打开 `http://127.0.0.1:33020/#/expert-center/tasks`，选择「使用已有访问令牌」。本机启动脚本显式启用开发模式，约定开发令牌为 `dev-secret-token`；这不是生产认证配置。该令牌不会通过此登录入口写入浏览器持久存储。

真实模型按现有服务约定配置 `MOX_LLM_API_KEY`、`MOX_LLM_BASE_URL`、`MOX_LLM_MODEL`，或既有多提供者配置。密钥通过部署环境注入，不写入代码、验收报告或聊天。配置后重启执行器并刷新工作台；「已配置」不保证远程模型在线，实际调用失败仍应显示失败。
