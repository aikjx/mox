六、关键设计决策

  1. 独立轻量 Router，不依赖 scheduler-core：在 llm/router.rs 重新实现 LlmRouter，避免引入 MergedLlmConfig 等复杂依赖和潜在循环依赖。API 与 scheduler-core 对齐，零外部依赖（仅 std）。
  2. 状态机级联修复：record_failure() 采用顺序 if 而非 match，确保 Healthy→Degraded→CircuitBroken 可在同一次调用内完成（threshold=2 时 2 次失败即熔断）。
  3. 向后兼容零侵入：LlmConfig 保留原有字段作为 providers[0] 的兼容视图；无 MOX_LLM_PROVIDERS 时 router=None，complete() 行为完全不变；ExpertExecutorConfig::default() 不变。
  4. from_env_with_router() 工厂方法：返回 (LlmConfig, Option<Arc<LlmRouter>>)，多 Provider（>1）时自动创建 router，单 Provider 返回 None。
  5. 环境变量测试序列化：用 static ENV_MUTEX: Mutex<()> + EnvGuard（drop 时自动清理）解决 std::env::set_var 的并行测试竞争，无需引入 serial_test crate。
  6. 熔断全链路：OpenAiChatClient.complete() → router.select_provider() → 调用 → record_success/failure()；全熔断时返回 "all LLM providers unavailable or circuit-broken"；consultant 检测到该错误立即回退本地（不经过 ReAct 重试）；executor 检测到该错误立即 break（不重试）。
  7. DIP 约束遵守：executor-core 不直接依赖 mox-ai-expert-svc，熔断感知通过错误信息字符串匹配实现（"circuit-broken" / "all LLM providers"），保持依赖倒置架构。

七、后续优化方向（第九轮建议）

高优先级

  • scheduler-core LlmRouter 与 expert-svc Router 统一：消除两套 Router 实现，统一为单一 crate（或让 scheduler-core 依赖 expert-svc 的 router）
  • LLM 响应缓存：对相同 prompt 的 LLM 调用做短时缓存（TTL 60s），减少重复 API 调用和成本
  • Metrics HTTP 端点：在 scheduler-svc 新增 /metrics 端点，输出 AllianceMetrics JSON 快照，对接 Prometheus
  • Fusion 引擎统一：消除 scheduler-core/fusion.rs 和 executor-core/fusion.rs 的重复实现

中优先级

  • 匹配器 Aho-Corasick 词典匹配：将 DOMAIN_KEYWORDS 线性扫描替换为 AC 自动机，领域推断从 O(K×T) 降至 O(T+K)
  • DAG 事件驱动调度：替换轮询模式为事件驱动（节点完成时立即触发下游），消除 ~100ms 调度基线延迟
  • 匹配器结果缓存：对相同 task_description 的匹配结果做短时缓存，高并发场景降低匹配延迟
  • 多 Provider 真实端到端测试：配置 2+ Provider（如 DeepSeek + 备用），验证熔断切换全链路
