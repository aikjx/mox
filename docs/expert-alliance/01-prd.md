# 专家联盟产品需求文档（PRD）

## 1. 产品定位

### 1.1 一句话定义

**专家联盟（Expert Alliance）是 MOX 平台上的多领域专家 Agent 自动协作引擎**——用户提交一个跨领域复杂任务，系统自动识别所需专家、编排协作流程、调度多专家并行/串行执行、融合结果、沉淀记忆，全程可追溯可干预。

### 1.2 解决什么问题

| 痛点 | 专家联盟解决方案 |
|------|-----------------|
| 单个 AI Agent 知识面有限，跨领域任务做不了 | 多专家 Agent 自动协作，覆盖全领域 |
| 专家之间没有关联，不知道该找谁 | 知识图谱驱动匹配，按领域+能力+健康度智能选专家 |
| 多专家结果不一致，不知道听谁的 | 6种融合策略（投票/加权/择优/辩论仲裁/迭代精炼）自动裁决 |
| 协作过程黑盒，出错不知道哪里错了 | 完整 DAG 可视化 + 节点级状态追踪 + 审计日志 |
| 每次都要手动设计协作流程 | 7种协作模式自动选型，Dynamic 模式按任务特征智能决策 |

### 1.3 目标用户

| 角色 | 场景 |
|------|------|
| 平台运营者 | 注册和管理专家 Agent，监控联盟运行状态 |
| 业务开发者 | 通过 API 提交任务，获取多专家协作结果 |
| 领域专家 | 配置自己的 Agent，参与协作任务 |
| 审计合规人员 | 查看协作链路、审计决策依据、追溯结果来源 |

## 2. 核心功能清单

### F-01 任务提交与管理

| 项 | 说明 |
|---|------|
| 功能 | 用户提交自然语言任务，指定协作模式或让系统自动选型 |
| 输入 | 任务描述 + 偏好模式（可选）+ 约束条件（可选） |
| 输出 | 任务 ID + 协作计划（DAG）+ 实时进度推送 |
| 状态 | pending → planning → executing → fusing → completed / failed |
| 对应代码 | scheduler-core/scheduler.rs + executor-core/ |

### F-02 专家智能匹配

| 项 | 说明 |
|---|------|
| 功能 | 根据任务描述自动匹配最合适的专家 Agent |
| 匹配维度 | 领域匹配（30%）+ 能力匹配（30%）+ 健康状态（15%）+ 优先级（15%）+ 历史表现（10%） |
| 过滤条件 | 租户隔离 + 状态=Active + 优先级≥阈值 + 总分≥0.2 |
| 输出 | 排序后的专家列表 + 匹配理由 + 分数明细 |
| 对应代码 | scheduler-core/matcher.rs（RuleBasedExpertMatcher） |

### F-03 协作计划生成

| 项 | 说明 |
|---|------|
| 功能 | 根据匹配的专家和任务特征，自动生成 DAG 协作计划 |
| 协作模式 | 7种：并行 / 串行 / 投票 / 分层 / 辩论 / 迭代 / 动态 |
| 输出 | CollaborationPlan（节点列表 + 依赖关系 + 融合策略 + 权重） |
| 对应代码 | scheduler-core/planner.rs（SimplePlanGenerator） |

### F-04 DAG 执行引擎

| 项 | 说明 |
|---|------|
| 功能 | 按拓扑排序执行 DAG 节点，管理节点状态和依赖 |
| 节点状态 | pending → running → completed / failed / skipped |
| 进度推送 | WebSocket/SSE 实时推送节点级进度 |
| 人工干预 | 支持暂停/恢复/跳过/重试/指定专家 |
| 对应代码 | executor-core/ + 网关 experts_orchestration.rs |

### F-05 结果融合

| 项 | 说明 |
|---|------|
| 功能 | 多专家输出按策略融合为最终结果 |
| 融合策略 | 6种：多数投票 / 加权投票 / 拼接合并 / 择优选择 / 辩论仲裁 / 迭代精炼 |
| 权重来源 | 匹配分 → 尾部融合真权重（不等权） |
| 对应代码 | alliance-core/fusion/strategies/ |

### F-06 专家注册中心

| 项 | 说明 |
|---|------|
| 功能 | 专家 Agent 的注册、发现、健康检查 |
| 注册信息 | 专家 ID + 名称 + 领域 + 能力 + 工具 + 状态 + 健康指标 |
| 分级聚合 | node → rack → cell（10:1:1 心跳聚合） |
| 对应代码 | registry-core/ + registry-svc:3400 |

### F-07 动态路由决策

| 项 | 说明 |
|---|------|
| 功能 | Dynamic 模式下，决策节点根据任务特征自动选择最合适的协作拓扑 |
| 决策规则 | 关键词意图 → 单专家 → 领域广度 → 分数分布 → 默认辩论 |
| 输出 | 决策理由留痕（写入节点描述 + 审计日志） |
| 对应代码 | planner.rs → decide_dynamic_mode() |

### F-08 多轮辩论引擎

| 项 | 说明 |
|---|------|
| 功能 | 正反方多轮辩论，裁判裁决最终结果 |
| 轮次 | 可配置（默认多轮循环） |
| 对应代码 | 网关 experts_collaboration.rs → run_debate() |

### F-09 协作记忆与案例库

| 项 | 说明 |
|---|------|
| 功能 | 协作完成后归档案例，用于后续任务的参考和学习 |
| 记忆分层 | 工作记忆（会话内）→ 会话记忆（跨会话）→ 案例库（长期） |
| 对应代码 | executor-core/ + 网关 experts_session.rs |

### F-10 可观测性

| 项 | 说明 |
|---|------|
| 功能 | 任务执行链路追踪 + 节点级指标 + Prometheus /metrics |
| 指标 | 任务创建数 / 平均匹配延迟 / 节点调度延迟 / 成功率 |
| 对应代码 | scheduler-core/metrics.rs + framework/observability |

## 3. 角色与权限

| 角色 | 权限 | 说明 |
|------|------|------|
| ADMIN | 全部权限 | 平台管理员，可管理所有专家和任务 |
| OPERATOR | 任务提交 + 查看 | 运营人员，提交任务、监控进度 |
| EXPERT_OWNER | 注册/管理自己的专家 | 领域专家，配置自己的 Agent |
| AUDITOR | 查看所有协作记录 | 审计合规，只读 |
| GUEST | 仅查看自己提交的任务 | 普通用户 |

## 4. 关键业务参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 匹配分阈值 | 0.2 | 低于此分不入选 |
| 领域匹配权重 | 0.30 | 评分维度权重 |
| 能力匹配权重 | 0.30 | 评分维度权重 |
| 健康状态权重 | 0.15 | 评分维度权重 |
| 优先级权重 | 0.15 | 评分维度权重 |
| 历史表现权重 | 0.10 | 评分维度权重 |
| 动态路由-极差阈值 | 0.25 | ≥此值→分层 |
| 动态路由-接近阈值 | 0.10 | <此值且≥3人→投票 |
| 动态路由-领域数阈值 | 3 | ≥此值→分层 |
| 迭代轮次 | 3 | 默认迭代模式轮次 |

## 5. 术语表

| 术语 | 定义 |
|------|------|
| Expert（专家） | 一个具备领域知识和工具能力的自治 Agent |
| Alliance（联盟） | 多个专家组成的协作组织 |
| Task（任务） | 用户提交的一个完整工作单元 |
| Node（节点） | DAG 中的一个执行步骤，对应一个专家的一次执行 |
| DAG（有向无环图） | 协作计划的拓扑结构，描述节点间依赖关系 |
| Fusion（融合） | 多专家输出合并为最终结果的过程 |
| Matching（匹配） | 根据任务特征筛选最合适专家的过程 |
| Dynamic Mode（动态模式） | 自动选择最合适协作拓扑的模式 |
| Registry（注册中心） | 专家 Agent 的注册和发现服务 |
