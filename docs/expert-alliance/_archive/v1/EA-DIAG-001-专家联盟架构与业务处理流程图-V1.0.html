二、业务流程图 1 · 任务全生命周期

主链路：提交 → 幂等回放 → 匹配 → 规划 → 派发 → 执行 → 融合 → 结果

1 提交任务
POST /api/alliance/tasks
tenant_id + 描述 + 模式 + 幂等键
2 幂等回放
命中幂等键 → 直接回放既有任务，不重复派发
3 专家匹配
ModularWeightMatcher
描述 → Top-N 专家
4 规划 DAG
6 种协作模式生成差异化 DAG
无环/可达/输入完整验证
5 派发执行
executor 收到 DAG
节点并行/串行按依赖拓扑
6 节点执行
调用专家 · 超时/重试(≤3)/替代/降级
7 结果融合
6 策略按模式匹配
加权投票/置信度/堆叠/辩论/MapReduce/迭代
8 QA 与回读
质量评估 · state_sink 持久化
执行状态/融合结果跨重启读回
resume 推进状态 toggle-done 完成 skip 跳过未终态节点 cancel 优雅终止（所有节点 <2s） 重试（指数退避） 降级（无模型 → MODEL_NOT_CONFIGURED，不伪装成功）

人工干预走调度器干预 API（resume/skip/toggle-done/cancel），干预后经状态机仲裁校验合法性；执行记录标记为节点最新快照，未配置真实模型时如实返回错误而非空报告。

三、业务流程图 2 · 任务状态机与仲裁

主推进链（合法转换）与终态（不可离开）

已创建未规划

Running
已派发执行

Succeeded
终态 · 结果可读
Failed
终态 · 可重试重建
Cancelled（终态 · 优雅终止） Skipped（节点级终态 · 人工跳过）

仲裁规则（scheduler-core update_task_status / can_transition_to）

规则行为证据位置
转换表仲裁非表内转换 → warn 日志 + 拒绝 + 保持当前状态scheduler-core/src/scheduler.rs
终态不可离开Succeeded/Failed/Cancelled 不再接受任何转换TaskStatus::can_transition_to
幂等并发绑定两请求同键并发 → 后者回放前者任务并终止派发bind_idempotency_key

五、业务流程图 4 · 多活租约选主 / 故障接管 / 配置注册

3 主故障
租约过期 / 心跳中断
4 从接管
备实例续租 → 从持久化状态接管任务
