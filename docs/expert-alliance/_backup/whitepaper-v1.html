01

架构总览：四层运行态与三权分立

专家联盟不是单体，而是一条"接入—编排—执行—注册"的四进程链路；其治理哲学是把实体、关系、版本三件事彻底拆开，各管一段、互不越权。下方拓扑为生产多进程形态（MOX_ALLIANCE_REMOTE_MODE=auto）。

接入层 gateway :3080

统一对外入口：REST / SSE、JWT 鉴权、SHA-256 审计哈希链、内联专家逻辑（11 文件 9924 行）。会话、专家 CRUD、图谱查询均在此进程内。

编排层 scheduler :3100

任务排队、模块化权重专家匹配、协作计划 DAG 生成、HA 租约选主。只负责"派活与排队"，不管执行细节。

执行层 executor :3200

DAG 逐节点执行、节点调度、结果融合落盘（WAL SQLite）。读路径由网关直连本进程取节点与融合结果。

注册层 registry :3400

专家登记、可用性登记、node→rack→cell 10:1:1 分级心跳聚合（入流降 100 倍）。经网关代理消费，不直接对前端。

三权分立：实体 / 关系 / 版本各归其位

存储管实体

专家、会话、预约、任务等实体记录归嵌入式 SQLite：网关 experts 表 + scheduler/executor 任务库 alliance_tasks.db。实体的增删改由存储层单点持有。

openuft 管关系

专家之间的关系网络（graph_nodes / graph_edges / graph_meta）独立于实体管理，支持全量 rebuild 与 8 条只读查询；关系不随实体表被随意改写。

演化管版本

Schema 版本（PRAGMA user_version=1）、HA 租约任期、审计哈希链负责时间维度：谁在什么时刻改了什么、重启后能否恢复，由演化层统一记账。

03

归一化架构要点

六条贯穿全栈的工程纪律：它们不是装饰，而是 CURRENT V1.1 与 08/09 反复用 文件:行号 锁定的事实。

协议先行

proto/ 4 个契约 crate（common / scheduler / executor / registry-proto）先于实现落地；DTO 与 trait 抽象在契约层定型，svc 只做装配。registry-proto 为 2026-09 归一化新增。

纯算法与 IO 分离

mox-alliance-core 纯函数无 IO（DAG 拓扑 + 融合策略），core 层业务逻辑无状态；IO 副作用全部下沉到 svc 与 sdk，可单测、可替换。

SM4 全链路加密

一键开关 MOX_API_CRYPTO=sm4，data 走 gzip + SM4-GCM，6 处挂载点（gateway / scheduler / executor / registry / bridge / remote-sdk）。2026-09 证明 6/6 通过；生产须显式注入 MOX_API_CRYPTO_KEY。

registry 10:1:1 分级心跳

aggregation.rs 把 node→rack→cell 心跳按 10:1:1 聚合，入流降约 100 倍；POST /api/registry/aggregated-heartbeat 为真实端点。主动探活默认关（N5），生产建议开。

HA 租约选主

LeaseStore / LeaderElector / SqliteLeaseStore + fencing epoch。请求路径无状态可任意 LB，对账/接管这一单点职责用租约限定在 leader；MOX_ALLIANCE_HA_MODE=on 显式开启，且强制 STORAGE_MODE=sqlite。

桥接可替换

scheduler 经 ExecutorBridge trait 调 executor，可替换实现；网关通过 re-export 复用 SDK 的 RemoteAllianceClient，不存在第二份实现（G4 后端已归一）。

7 种 DAG 协作模式（AllianceMode）× 6 种融合策略（FusionStrategy）

协作模式（planner.rs:81-91 七条 match 分支全覆盖）：

Sequential 串行 Parallel 并行 Debate 辩论 Hierarchical 层级 Iterative 迭代 Voting 投票 Dynamic 动态决策

融合策略（mox-alliance-core/fusion/strategies/）：

confidence_weighted debate iterative map_reduce stacking weighted_vote

注意：05-data-model 曾把模式与策略混淆成 9 值——以代码为准，模式 7 种、策略 6 种；代码里不存在条件分支执行节点。

生产档 prod · 内网试点 / 生产集群
  • MOX_INTERNAL_TOKEN 4 进程同值（openssl rand -hex 32）
  • MOX_API_CRYPTO=sm4 + 注入 MOX_API_CRYPTO_KEY(32 hex)
  • MOX_DEV_MODE=0 · MOX_DISABLE_DEV_TOKEN=true
  • MOX_ALLIANCE_STORAGE_MODE=sqlite（scheduler+executor 共享卷）
  • MOX_AUDIT_HMAC_SECRET 必改默认值
  • MOX_ALLIANCE_REGISTRY_PROBE_ENABLED=1
  • 多副本：MOX_ALLIANCE_HA_MODE=on + 共享 sqlite PVC
本地 / 开发档 dev · 单机联调 / CI
  • MOX_DEV_MODE=1 放行内部鉴权
  • MOX_API_CRYPTO=off 明文便于抓包
  • MOX_ALLIANCE_REMOTE_MODE=off 全进程内
  • MOX_ALLIANCE_STORAGE_MODE=file（仅快照）
  • MOX_AUDIT_SINK=noop 不落审计盘
  • 不设 INTERNAL_TOKEN / HMAC_SECRET（用默认）

docker-compose（单机 / 内网试点）

仅 gateway 映射 3080；scheduler / executor / registry 只 expose 不暴露宿主。scheduler 与 executor 共享 alliance-data 卷，指向同一 alliance_tasks.db——任务真源一致的前提。每个服务配 healthcheck。

k8s（多副本 / 生产集群）

gateway 对外 Service（LB/NodePort/Ingress）；三 svc 仅 ClusterIP。只有 scheduler 开 HA 多副本，且 strategy: Recreate（sqlite 单写者）+ 共享 RWX PVC。敏感值走 Secret/Vault，勿裸提交。

部署后一致性检查清单（逐项验证开关真生效）

  • 进程存活：curl 四个 /health；gateway 返回 JSON，body 的 dependencies.scheduler/executor 应为 up。
  • 鉴权链路：不带 token 直连 :3100 期望 401；带 Bearer $TOKEN 期望非 401。/health、/metrics、/leadership 是公开白名单，勿拿来断言鉴权。
  • SM4 生效：带 x-mox-crypto: sm4-gcm+gzip 头请求，响应应为信封密文 {crypto:{alg,zip,nonce,ct,tag}}。
  • 存储模式：alliance_tasks.db 与其 -wal 副产物存在；scheduler 与 executor 指向同一文件。当前无 user_version，以库文件 + wal 判定。
  • HA 选主：curl :3100/leadership，两副本中恰好一个 role=leader（仅 HA_MODE=on 有意义）。
  • /metrics 格式差异：gateway 是 Prometheus 文本；scheduler/executor 是 JSON 快照（N7），抓 Prometheus 需写适配层。
  • 审计日志：experts-audit.ndjson 每行一个对象、含 HMAC 签名；触发一次操作后有新行。
