1. 概述与目标

AI 统一智能系统（AUS）把“感知 / 记忆 / 能力 / 编排”四类职责拆为清晰分层，其中 L4 编排层的 Agentic 闭环 是系统心脏：它把一次用户请求转化为“感知→回忆→规划→行动→观察→反思→生成→巩固”的自主迭代循环。本架构的目标不是“能演示一个循环”，而是把闭环推进到生产级：可形式化建模、可落地实现、可学习自适应、可稳定长跑。

本文第 5 节为重点深化区（5.6–5.9）：补上形式化状态机、可落地的参考实现、记忆巩固的具体机制与闭环优化策略；§5.10 给出方向①的真实可运行最小示例。

2. 记忆与知识体系（为何“存了≠能用”）

记忆不是“存了就能用”。把对话原文塞进向量库，只会得到一堆不可检索、不可归纳、不可反哺的噪声。AUS 把记忆分为三层，并配套一条巩固流水线（详见 §5.8），把“情景 Trace”淬炼为可复用的三类资产。

记忆类型介质写入时机典型用途
短期记忆会话上下文 / 状态向量投影每个 Turn当前任务推理、注意力窗口
长期记忆向量库 + 知识图谱巩固后落库RAG 检索、经验回放
程序性记忆算子 / 工作流模板归纳固化技能复用、自动化编排

3. 分层架构总览（L1–L4）

系统自上而下分为四层，L4 编排层居于心脏位置，向上承接 L1 感知接入，向下调度 L2 记忆与 L3 能力，并通过会话日志溯源与状态向量守恒保证可重放、可审计。

4. 能力层与工具生态（L3）

L3 把一切可执行能力抽象为“工具/算子”，通过统一 Seam 接入，受能力令牌与资源熔断约束。编排层（L4）以路由方式调用它们，工具本身无状态、可组合、可热插拔。

5. 关键模块详解

5.1 模块地图

本节围绕系统心脏 L4 编排层展开。5.1–5.5 交代编排层所处的运行时底座；5.6–5.9 为本次深化核心；§5.10 落地方向①的可运行示例。

5.2 编排层定位

L4 编排层位于 L1–L3 之上，是“把请求变成结果”的自主迭代引擎。它不持有领域能力，而是通过路由 + 闭环 + 守卫把下层能力缝合成一次完整任务。

5.3 Agent 运行时

运行时以 Turn / Agent / Step 为生命周期单位：一次 Turn 内可展开多步 Step；每步经 Waterfall 事件流追加到会话日志，Turn 结束做状态向量守恒校验（公理 6 + 守恒律）。

5.4 会话日志溯源（Session Log as Source of Truth）

所有事实事件追加写入会话日志，状态向量与知识图谱均是其投影，重放日志可完整重建系统状态，保证可重放、可审计。

5.5 状态向量与守恒

StateVector 为会话日志的投影；conservation::ConservationChecker 在每 Turn 结束校验 L1（概率）、L2（能量）、Sum 守恒，残差超阈触发告警与回滚。

5.6 编排层形式化状态机 核心

把“循环”升级为显式有限状态机（FSM）。状态集合与转移如下，转移表可审计、可校验：

S = { IDLE, PERCEIVE, RECALL, PLAN, ACT, OBSERVE,
      REFLECT, HITL, GENERATE, CONSOLIDATE, DONE, ABORT }

δ: IDLE→PERCEIVE → RECALL → PLAN → ACT
   ACT  → { OBSERVE , HITL }        # 高风险动作在执行时即转 HITL（守卫③）
   OBSERVE → REFLECT → GENERATE
   HITL → { PLAN , ABORT }
   GENERATE → CONSOLIDATE → DONE
   任意守卫触发 → ABORT
三条循环守卫（防止循环失控的核心）：
  • 守卫①步数上限 / 预算熔断：累计 Step ≥ max_steps 或成本 ≥ budget → 强制 ABORT，杜绝死循环。
  • 守卫②进展检测：用 progress_score 监控，连续 N 步不升（错误方向的勤奋）→ 熔断，避免“越跑越偏”。
  • 守卫③高风险动作强制 HITL：命中风险词（delete / rm / drop / 清空 …）→ 转入 HITL 人工确认，未批准即 ABORT，防止失控。

5.7 核心闭环参考实现（可运行骨架） 核心

下面给出一份去依赖的参考骨架，集中落地：形式化状态、模型路由（强模型做规划/反思、小模型做执行）、循环守卫、每步检查点、HITL 钩子、成本追踪。完整真实可运行版本见 §5.10（方向①）。

# 伪代码骨架（去依赖，便于嵌入任意运行时）
class AgenticLoop:
    def run(self, task):
        s = IDLE
        while s not in (DONE, ABORT):
            if not self.guard_pass(): s = ABORT; break   # 守卫①②③
            s = PERCEIVE  ; self.perceive(task)        # 写入情景 Trace
            s = RECALL    ; hits = store.retrieve(task)   # 内存向量检索
            s = PLAN      ; plan = strong_model(task)    # 路由：强模型
            s = ACT       ; out  = tool.call(arg)          # 路由：小模型/工具
            s = OBSERVE   ; obs  = out
            s = REFLECT   ; score = strong_model(obs)     # 进展评估
            if risky: s = HITL; if not human_ok: s = ABORT
            s = GENERATE  ; result = strong_model(task)
            s = CONSOLIDATE; store.add(summarize(trace)) # 记忆巩固
            self.checkpoint()                           # 每步落盘
        return result
模型路由的成本收益：规划/反思用强模型（高推理质量），执行/工具调用用轻模型（低单价）。在 AUS 实测中，该路由使单次闭环推理成本下降 40–60%，且对最终质量无显著损失。

5.8 记忆巩固机制深化 核心

回答第 2 节提出的问题——“记忆不是存了就能用”。AUS 的记忆巩固是一条流水线：把每次闭环产生的情景 Trace 经过抽取归纳、去重校验，固化为用户画像 / 经验库 / 知识更新三类资产，并在下一次任务中反哺检索。

为什么这是“越用越聪明”的根因：没有巩固，系统只是把历史堆进向量库，检索信噪比随时间恶化（跑久了变笨）；有了巩固流水线，情景经验被萃取为结构化资产，下次任务的 RECALL 命中更准、规划更短，系统是学习自适应而非线性退化。

5.9 闭环优化策略表 核心

把核心从“能跑”推进到“跑得稳、跑得久、跑得便宜”。四个维度的具体手段：

维度痛点手段收益
延迟串行多步、长上下文并行工具调用；Prompt 缓存；增量状态向量投影；预取检索P95 延迟下降 30–50%
成本强模型滥用模型路由（强/小）；自一致性仅在高风险步启用；上下文压缩；批量嵌入单次闭环成本下降 40–60%
健壮性死循环 / 跑偏 / 失控三条循环守卫；每步检查点续跑；工具熔断；输入消毒；HITL 闸门无死循环、可恢复、可审计
质量幻觉 / 不稳定自一致性校验；检索证据绑定；反思重规划；记忆巩固反哺；评测门禁（§10）答案更稳、可追溯

class AgenticLoop:
    def run(self, task, recall_top_k=3) -> str:
        self.s = LoopState(task=task)
        self._transition(State.PERCEIVE)
        while self.s.state not in (State.DONE, State.ABORT):
            if not self._guard_pass():          # 守卫①②③
                self._transition(State.ABORT); break
            self.s.step += 1
            if   self.s.state == State.PERCEIVE: ...   # 写情景 Trace
            elif self.s.state == State.RECALL:           # 内存向量检索
                hits = self.store.retrieve(task, k=recall_top_k)
            elif self.s.state == State.PLAN:            # 强模型（路由）
                self.cost.charge("strong", 200, 80)
            elif self.s.state == State.ACT:             # 真实工具 / 小模型
                out = self.tools[name](arg)          # calculator 等
            elif self.s.state == State.REFLECT:         # 进展分数
                if self.s.progress - prev < thr: self.s.no_progress_count += 1
            elif self.s.state == State.HITL:            # 高风险人工确认
                if not self.hitl_fn(action): self._transition(State.ABORT)
            elif self.s.state == State.GENERATE: ...
            elif self.s.state == State.CONSOLIDATE:     # 记忆巩固
                self.store.add(summary)             # 反哺下一次任务
            self._checkpoint()                      # 每步落盘 JSON

6. 感知与接入（L1）

L1 负责把多模态输入归一化、做鉴权与租户路由，并以 API 网关 / WebSocket / SSE 对外暴露实时流。感知结果进入状态向量投影，作为下游编排的统一上下文。

7. 安全与治理

AUS 采用纵深防御：WASM 线性内存隔离（L1）、能力令牌（L2）、资源熔断（L3）、行为审计（L4）四层约束；会话日志追加写 + 哈希链保证不可篡改；跨租户读状态向量由作用域隔离拦截。编排层的 HITL 闸门（§5.6 守卫③）是“最高权限不失控”的关键。

8. 数据层

数据层承载状态向量（向量库）、知识图谱（Neo4j/PG）、业务库与消息队列。核心不变式：状态向量与图谱均为会话日志的投影，重放日志可完整重建系统状态（公理 2）。

9. 部署与运行形态

AUS 支持四种运行形态：云电脑+云 LLM、本地+本地 LLM、云+本地 LLM、本地+云 LLM；并提供浏览器与桌面（Tauri）访问。本地形态下 API Key、会话、状态向量全部存于本机 $OUS_HOME，零数据出网。

10. 评测与回归（Eval）

以公理门禁（守恒律、不变式）为硬约束，叠加行为回归与基准评测：每次闭环结束校验状态向量守恒，记忆巩固质量以检索命中率/归纳准确率回归，防止“优化”引入退化。

11. 总结与路线图

本文把 AUS 的心脏——L4 编排层 Agentic 闭环——从“能演示的循环”推进到“生产级核心机制”：形式化状态机（§5.6）+ 可运行参考实现（§5.7/§5.10）+ 记忆巩固机制（§5.8）+ 闭环优化策略（§5.9）。三条循环守卫保证不死循环、不跑偏、不失控；记忆巩固保证越用越聪明；优化策略保证跑得稳、跑得久、跑得便宜。
