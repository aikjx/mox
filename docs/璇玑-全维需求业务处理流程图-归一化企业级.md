## 0 · 归一化总纲（Single Source of Truth）

四条不可妥协原则，是"整理优化 / 归一化 / 企业级"的唯一解释基准。

1. **归一化**：四类流程图（业务/算法/权限/资源）在内存里是**同一个 `FlowGraph`**，差异仅体现于节点/边的 `Dimension` 着色与约束。物理节点唯一，维度只是标签，"改一个节点，全维同步"天然成立。
2. **全维**：每个节点同时被**双璇玑十四维**（业务七维 + 开发七维）评估；优化结论必须同时满足全维约束，不做单维最优而牺牲其他维。
3. **最优算法处理**：最终求解交给 flow-ai 已验证算法栈（冒险分析并行化 + CPM 关键路径 + RCPSP 资源调度 + 冲突自动修复 + Dijkstra 关系网最短路）。本层只翻译约束，不重造算法。
4. **可治理**：多租户隔离、RBAC 权限、不可篡改审计、流程版本与审批、SLA/成本预算——出码/执行前必须过治理闸门。

**一句话定位**：七个（+七个）领域专家在归一化 IR 上并行诊断，裁决器按"权限/安全优先"全维归一，flow-ai 引擎做已验证最优求解，⛨璇玑验证网关与治理闸门把关后出码——一张图，全维最优，企业可治理。

## 1 · 全维需求业务处理主流程图

8 阶段、4 道强制闸门。任意闸门拒绝即阻断出码，无降级旁路。

| 阶段 | 名称 | 动作 | 关键产物 |
|---|---|---|---|
| S1 | 需求接入 | 关图 `REQ` 根（D01~D13 / R01~R08）经 `Bind` 六维骨架接入，带租户/主体/RBAC 上下文 | `Requirement` 节点 |
| S2 | 归一化 | `auto_dimension` 维度着色；租户配额→`ResourcePool` 上限；解析为唯一 `FlowGraph`(base) | 归一化 IR |
| S3 | 双璇玑并行诊断 | 插件化运行时 `run_experts` 并行派发 14 位专家，各出 `ExpertOpinion` | 14 × Opinion |
| S4 | 归一化裁决 | `reconcile` 按优先级合并约束→`ReconciledPlan`（注入 Guard/Mutex 边 + ExpertRule + 冲突日志） | `ReconciledPlan` |
| S5 | flow-ai 最优求解 | `optimize`：CPM + RCPSP + 伪依赖剪除 + 冲突修复 + 代码生成 + LLM 算力路由 | `OptimizationReport` |
| S6 | ⛨ 璇玑验证网关 | `verify` 5 项阻断级数学/语义检查，最高权限 | `AlgoVerification` |
| S7 | 治理闸门 Govern | 审计哈希链 + 版本状态机 + SLA + 成本预算 + RBAC 审批 | `GateResult` |
| S8 | 出码 / 出图 | `emit`：代码工程 + 拓扑快路径 + 可视化 + 指标 | 代码/拓扑/指标 |

**4 道闸门（控制点）**

- **G0 归一化闸门**：IR 必须可拓扑排序（DAG）；维度着色完整；孤儿/悬空边为 0（对齐关图 GR-E1/E2）。
- **G1 裁决闸门**：硬约束（Blocking 级）一律落地，优先于一切软约束（保证权限/安全不可被性能优化绕过）；同优先级冲突平手升级为 `Risk(Blocking)` 交人工/审批。
- **G2 ⛨ 璇玑否决（最高优先级）**：任一阻断级检查失败 → `vetoed=true` → 治理闸门强制 `Blocked`。任何 RBAC/合规结论均不可覆盖。专家 `veto=true` 级风险、裁决冲突升级亦并入否决。
- **G3 治理闸门**：`approved = !algorithm_veto ∧ status.can_emit() ∧ blocking==0 ∧ sla_ok ∧ budget_ok`。五条件任一不满足即拒；未批准版本仅允许 dry-run。

## 2 · 双璇玑十四维专家矩阵

业务璇玑（七维）+ 开发璇玑（七维）并行、互不依赖。优先级：Permission/Security > Resource > Data > Business > Observability > Algorithm（开发七维参与同优先级仲裁）。

| 维度 | 璇玑 | 专家 | 核心职责 | 典型产出 | 属性 |
|---|---|---|---|---|---|
| Business | 业务 | 业务专家 | 领域规则、分支完整性、失败兜底 | 缺 else 警告、必走审批分支 | 软 |
| Algorithm | 业务 | 算法专家 | 关键路径瓶颈、复杂度、缓存 | 缓存/拆分建议、`Suggestion::Offload(tier)` | 软 |
| Permission | 业务 | 权限专家 | RBAC、越权、合规脱敏 | `MustGuard(desensitize)`、`Risk(Blocking)` | 硬 |
| Resource | 业务 | 资源专家 | 算力/连接池/并发，配额翻译 | `ResourceCap(browser,1)`、`MustSerialize` | 硬 |
| Security | 业务 | 安全专家 | 注入、PII 外发、越狱 | `MustIsolate`、`Risk(Blocking)` 泄露 | 硬 |
| Data | 业务 | 数据专家 | 血缘、schema 漂移、幂等 | `MustOrder`（血缘保序） | 硬 |
| Observability | 业务 | 可观测专家 | 埋点/追踪/告警 | `MustAudit`、关键路径埋点 | 软 |
| Architecture | 开发 | 架构专家 | 模块边界、耦合、六维绑定一致性 | 架构偏离、绑定断链告警 | 软 |
| Security_Code | 开发 | 安全代码专家 | 源码级注入/越权/硬编码密钥 | `Risk(Blocking)` 源码漏洞 | 硬 |
| Code_Quality | 开发 | 代码质量专家 | 可读性、复杂度、重复 | 质量分、重构建议 | 软 |
| Performance | 开发 | 性能专家 | 热点、分配、并发安全 | 性能分、瓶颈标记 | 软 |
| Testing | 开发 | 测试专家 | 覆盖率、断言、边界 | 测试缺口、强制单测建议 | 软 |
| Documentation | 开发 | 文档专家 | 注释、README、TraceMatrix | 文档缺口（PT-DOC） | 软 |
| Maintainability | 开发 | 可维护性专家 | 变更影响面、腐化趋势 | 可维护性分、重构优先级 | 软 |

**归一化收口**：MCP 工具 / Skill / Loop / LLM 不是外接插件，而是归一化 IR 的**第一类公民**，参与与企业内部节点完全相同的全维约束与最优求解。

## 3 · 全维通过关系图（六维绑定 + 十四维镜头）

关图六维绑定是唯一可追溯链：**REQ → FUN → BIZ → ALG → TSK → COD**（`Bind` 边，导出 TraceMatrix）。任意核心节点须可达某 REQ 根（GR-E6 偏离治理）；十四维镜头叠加于同一物理节点。

- 业务七维镜头（Biz/Alg/Perm/Res/Sec/Data/Obs）与开发七维镜头（Arch/SecCode/CodeQ/Perf/Test/Doc/Maint）并列审视同一物理节点。
- 外部能力归一化落点：MCP→`FlowNode(Task,Http/Shell)`+tags；Skill↔拓扑网快路径；Loop→`LoopStart/End`+回边；LLM→`ModelTier` 路由。

## 4 · 全链路可靠可控矩阵

每一层都有明确的"控制点 / 检查项 / 权威级 / 失败动作"。可靠性来自分层闸门，可控性来自审计链与版本状态机，明确性来自可机读报告。

| 链路层 | 控制点 | 检查项 | 权威级 | 失败动作 |
|---|---|---|---|---|
| S1 需求接入 | 关图 REQ 根 / Bind | REQ 可达性（GR-E6）、悬空边（GR-E2） | 关图规范 | 偏离挂账，增量阻断 |
| S2 归一化 | G0 闸门 | IR 可拓扑排序、着色完整、孤儿=0 | 流水线 | 拒绝进入诊断 |
| S3 双璇玑诊断 | 专家并行派发 | 14 专家确定性 Opinion；`veto` 级风险 | 各专家（只读） | `veto=true`→并入璇玑否决 |
| S4 归一化裁决 | G1 闸门 | 硬约束优先落地；冲突升级 Blocking | 裁决优先级 | 平手升级交人工/审批 |
| S5 最优求解 | flow-ai optimize | CPM/RCPSP/Dijkstra；CodeGen | 引擎（已验证） | 收益不可信仅告警 |
| S6 ⛨ 璇玑 | G2 网关（最高） | topology/data_dep/conflict（阻断）+ gains/code_rt | **最高权限** | `vetoed`→强制 Blocked |
| S7 治理 | G3 闸门 | 审计哈希链 + 版本机 + SLA + 预算 + RBAC | 治理层 | 5 条件任一不满足即拒 |
| S8 出码/出图 | emit 许可 | 仅 `Approved` 且 `!algorithm_veto` | 审批状态机 | 未批准仅 dry-run |

**⛨ 璇玑 5 项检查**（任一阻断级失败即否决）：
1. `topology`（阻断）：原始节点全保留 + 真数据依赖可达性守恒
2. `data_dep`（阻断）：剪除伪依赖不破坏真数据依赖；并行层无 RAW 冒险
3. `conflict`（阻断）：0 阻塞冲突 + 异常边落点有效
4. `gains`（软）：speedup≥1 且并行不慢于串行
5. `code_rt`（软）：代码⇄流程图往返一致（仅告警）

**审计链（可控性底座）**：`AuditEvent{who,when,flow,decision,diff}` 追加写；哈希链 `prev_hash→hash`，`verify()` 防篡改；版本状态机 Draft→Review→Approved→Deprecated；RBAC `run/edit/approve/view-audit` 四权分离；多租户 `namespace` 隔离 + 配额→`ResourcePool` 上限。

## 5 · 关图承载与 CI 门禁（可追溯闭环）

- **六维绑定承载**：REQ 根（D01~D13 / R01~R08）经 `Bind` 边绑定到主责 crate 入口（`crates/*/src/lib.rs`），再细化 REQ→FUN→BIZ→ALG→TSK→COD 六维一一绑定，导出 TraceMatrix。偏离检测（GR-E6）：核心节点不可达任何 REQ 根即视为无需求溯源。基线覆盖率 96.6%，绝对下限护栏 `COVERAGE_FLOOR=90.0`。
- **CI 强制合规 8 项**（非零即阻断）：①图纳入版本管理且非空 ②无悬空边(GR-E2) ③无重复 id(GR-E4) ④所有边带 evidence(GR-E3) ⑤核心节点无孤儿(GR-E1) ⑥无未建模隐性依赖(GR-E6) ⑦文档引用全部有效(GR-E7) ⑧新变更 sync 漂移=0(GR-E8)。

**闭环总结**：需求有根（REQ）→ 处理有归一化 IR → 优化有已验证引擎 → 正确性有 ⛨ 璇玑最高权限否决 → 出码有治理闸门与审计链 → 演进有关图同步漂移门禁。任一层均可机读、可复核、可阻断。
