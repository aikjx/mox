# 低代码全维配置控制与运行边界（ADR-18）

> 2026-10-01 · 状态Proposed · 范围：低代码文档与目标设计，未改变运行拓扑或既有契约。

<a id="decision"></a>
## 决策建议

配置控制面负责编制/校验/编译/发布，运行面消费不可变版本快照并调用注册能力；逻辑边界先内嵌现有服务，不据此新建配置微服务。复用meta/DSQL/module-core与前端Schema CRUD，以显式版本适配连接。

业务配置定义纯数据对象、能力ID和受限表达式；不远程下发JavaScript函数、任意SQL或任意插件加载地址。安全约束、预算上限和服务端资源授权不接受普通配置覆盖。页面本地PageSchema的函数引用通过受控绑定适配，不冒认为网络JSON。

全维配置由 `docs/standards/lowcode-dynamic-configuration.md#dimensions` 定义20个类别。各目录维护其拥有的契约接缝，语义只维护一份；设计完成/代码完成/运行验证/发布就绪分开判定。版本闭包和任务快照支撑确定性；配置回滚、数据库迁移、外部补偿分别设计与验收。

## 备选与权衡

| 备选 | 取舍 |
|---|---|
| 从零建立通用低代码引擎 | 重复已有能力；先复用，适配器只补齐必要接缝 |
| 所有业务以任意脚本配置 | 不可稳定校验/授权/迁移；只开放受限声明和注册能力 |
| 所有变更立即热生效 | 运行任务失去可复现语义；默认新任务生效，迁移单独设计 |
| 每目录复制完整schema | 字段、状态与覆盖规则易漂移；主题拥有者+引用关联 |

## 后果与接受条件

引入schema/compiler/release/任务版本管理与适配工作；需要一个真实组合样例验证，而不是仅证明JSON可保存。LC-Q01–12是配置发布与交付出口，容量/恢复目标按实际部署档测量。组织评审后才将Proposed改Accepted；未形成会签不宣称已批准。
