⚙ 8 大核心处理模式

每一条都对齐 MOX 现有代码能力，Key 同构 / SHA-256 去重 / 引用计数 GC / Provider 抽象四个地基锚点可直接复用放大。

01

三级冷热存储 + 全局去重

热(0-30天)SSD EC 4+2 / 温(30-365天)HDD EC 8+3 / 冷(>365天)磁带归档。Key = hash.slice(0,2)+'/'+hash 从 FS→S3→全球多 Region 一字不改。SHA-256 跨租户全局只存 1 份。

MOX 锚点：chunk-backend.js Key 同构 + file-store.js 引用计数
02

256 哈希分片元数据

路由表：bucket + hash[0:2] → shard_id(0..255) → TiKV Region leader。一致性哈希 1024 vnode，扩容只移动 1/N 数据。绝不回源对象存储做 List，全靠 Catalog 索引层回答。

禁忌：按 user_id 连续分片会头部热点 99% 压 1 片
03

批流一体 + 计算下沉

Spark 万核并行批处理 + Flink exactly-once 流处理。100TB 全表扫描：传统拉到计算节点要 1000 分钟+占满出口；改 S3 Select 存储端过滤掉 99% 行再走网络，同结果成本 1/100。

MOX 的 /file/analyze、/chunk/verify 必须改写成 MR Job
04

一致性哈希 1024 虚拟节点

新增物理节点 → 只迁移 1/N 的 vnode hash 段 → 对象桶不改名 → 只在 Catalog 改 shard 归属指向。再均衡速度：每 1PB ≤ 24h，期间双写旧+新，读写完全不受影响。

分片偏差必须 ≤15%，>25% 立刻补 vnode/加节点
05

EC 12+4 跨 AZ 容错

三副本 3× 成本 vs EC 12+4 仅 1.33×，容忍任意 4 盘/2 节点/1 AZ 故障。10ZB 规模下省 16.7ZB 物理盘 = 省 50 亿人民币。故障是常态不是例外，每周混沌演练断 AZ/拔盘/断专线。

RPO=0 双写热数据 + EC 温冷数据 = 成本与安全最优解
06

去重压缩 + 行列混存

端侧 Zstd level 3 压缩率≈2.5×，省 60% 存储费。元数据/报表/分析类数据用 Parquet + Zstd + Iceberg 列存，相比纯 JSON 同样 1PB 体积缩小 8-12×，查询加速 50×+。

MOX 锚点：chunk-hash 层已实现内容寻址去重
07

生命周期成本铁律

写入即标级(预期寿命/访问频率/敏感度 3 tag) → 30天IA / 365天归档 / 7年磁带自动降级。冷数据解档要 12h 且收费，禁止习惯性全表扫冷层——一次 10PB 解档账单百万级。

T3 加权平均成本必须 ≤ ¥0.035/GB·月，高于此数说明策略错了
08

37 项 SLO 全链路可观测

Metrics(Prometheus+Thanos)：吞吐/p50/p95/p999延迟/分片偏差/EC修复队列/跨域延迟。Logs(ClickHouse 30天热+S3冷)：每次操作留 req_id/sha256/size/shard_id/region/status/latency。Traces(OTel+Jaeger)：p999 慢请求一眼定位瓶颈层。

每一个操作都可问责、可追溯、可审计
