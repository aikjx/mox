# 专家联盟模块化归一与证据治理（ADR-17）

> 状态：**Proposed（架构目标待实施评审；文档整理已获本轮授权）**
> 日期：2026-10-01
> 范围：专家联盟与 docs 架构关联；不改变现有接口、端口、数据库或运行拓扑。
> 关联：`docs/enterprise/29-跨域依赖规则与架构一致性治理-ADR-09.md#2-五条核心依赖规则the-five-rules`、`docs/enterprise/35-模块化单体到微服务演进预案-ADR-16.md#1-当前架构定位`。

## 背景

同一领域存在当前实现、旧目标设计、部署模板、近期修复总账和多套总纲。入口指向已归档路径，产品规范与近期完成记录冲突。继续新增并列“最高权威”或立即全微服务拆分，会扩大事实漂移和运维负担。

<a id="decision"></a>
## 决策建议

1. 现状按主题来源和日期裁决，代码与运行证据支撑事实；导航图谱不替代事实源。状态总账记录近期增量，不把旧快照静默当实时事实。
2. 保留网关/调度/执行/注册混合运行形态，先划清逻辑模块、契约、数据主源，再以瓶颈证据决定部署拆分。
3. 产品设计用需求→流程→模块→契约→质量场景→证据关联；预览、代码完成、运行验证、发布就绪分别登记。
4. 任务控制状态与执行事实由各自模块拥有；图谱/检索为可重建投影。可靠事件按必要场景引入，不强制全量事件溯源。
5. 复用现有装配与链接门禁；全目录盘点通过确定性脚本生成，保留图源与显式引用，不编造语义边或质量分数。

## 备选与取舍

| 备选 | 优点 | 不采用理由 |
|---|---|---|
| 再建一份替代所有源文件的总架构 | 阅读集中 | 复制接口/状态/端口，形成新的竞争权威 |
| 立即全部拆为微服务 | 理论上可独立扩容 | 本轮无容量收益和恢复成本证据；契约/数据边界尚需收口 |
| 全量改写/迁移历史文档 | 表面统一 | 历史是只读证据，路径是契约；会破坏既有工作和溯源 |
| 只列目录，不分析流程 | 成本低 | 无法回答业务如何完成、失败如何恢复和是否更优 |

## 后果与验收

增加两份互补设计视图和可复跑盘点；维护者继续在原主题源更新事实，其他文档只引用。新目标会带来契约、恢复和用户验证工作，当前文档完成不等于这些实施完成。

批准实施前，对 `docs/expert-alliance/18-modular-product-design.md#roadmap` 中任务逐项评审；P0场景失败阻断发布。未来改变拓扑或持久化时记录替代ADR，保留本记录。文档关联验证与待办证据统一归档到 `reports/`。
