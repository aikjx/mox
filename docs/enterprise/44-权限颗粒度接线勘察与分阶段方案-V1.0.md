## 3. 五条可复现越权路径（只报不改，未做真机利用；3080 本轮 DOWN）

1. **自授角色**：`/api/system/role/:id/roles`、`/api/system/user/:id/roles`、`/api/system/role/:id/menuPerms`、`/api/system/role/:id/dataPerms` 全部在台账里（`--check` 逐条点名），即"改别人权限"这件事本身不受权限约束。
2. **任意租户**：任何 `/api/tenant*`、`/api/system/*?tenant_id=…` 传什么就用什么（`resolve_tenant` 的 `Ok(input)` 末支）。
3. **任意用户视角**：`/api/system/permissions?user_id=X` 直接返回 X 的角色与权限（`system/permission.rs:25`），可用来枚举他人权限集。
4. **开发令牌即管理员**：`auth.rs:182-191` 在 `dev_mode && !disable_dev_token` 下把 `dev-secret-token` 解析成 `roles: ["admin"]`。这是设计（本地开发），但它与"接口层无守卫"叠加后，一条头就能穿透整个系统管理面。
5. **无痕变更**：第 9 行死码意味着上面四条即便发生，也不会有 `iam_oper_log` / `iam_audit_log` 记录。

## 6. 分阶段方案（每期一条可判定的验收，顺序不可倒）

**① 身份先进 handler，再谈权限**
把 `ApiAuth(user)` 补进台账里那批 handler 签名；`resolve_tenant` 改成"必须是 token 里 `tenant_id` 或经校验的成员关系"，取消 `Ok(input)` 末支；`/api/system/permissions` 的 `user_id` 只取 token。
验收：`--identity` 的绑定分母从 4/92 起增，且台账逐条变 STALE（收口一条必须**删条目**，不许写 0）。

**② 接口级守卫上线（用现成的注册表）**
`permission_middleware`（`api_permission/middleware.rs:25`）与 `build_api_permission_router`（`api_permission/api.rs:494`）已实现且零引用——接线它们，按 `iam_permission` 的资源/动作做判定，缺权限回 403 信封。
验收：`--check` 的 GROWN 只在"新端点未登记守卫"时红；每收口一批，门禁 LEDGER 少一批；另加一枚"摘掉中间件挂载"的变异体必须让集成测试红（防止"注册表填了没人读"第三次发生）。

**③ 菜单两端打通**
后端 `system/permission.rs:35` 的 `"menus": []` 改为按 `get_user_permissions` 结果查 `iam_menu`（DDL `:177`）；前端 `TheSidebar.vue:24` 的数据源从 `MODULE_SIDEBAR_CONFIG` 常量换成 `permission.store.menus`（`generateMenus()` 已有，只缺消费者）。
验收：以一个非 admin 角色登录，可见项集合 = 服务端返回集；`generateMenus` 出现 ≥1 个 `.vue` 消费者（可用一条 grep 棘轮钉住）。

**④ 数据范围与字段级各有牙**
列表 handler 调 `evaluate_data_scope`（`repo.rs:1099`）；字段级先定义"哪一档"（建议按 `iam_data_permission` 现有列，不新造表）。
验收：同一账号在不同 `data_scope` 下，同一列表端点的行数不同；`canAccessDept` 类判定出现真实调用者。

**⑤ 审计复活 + 前端错误语义**
`create_oper_log` / `create_audit_log`（`repo.rs:2538,:2889`）接到②的权限变更与登录失败路径；`api/http.js:155-158` 的 `mox:auth-failed` 目前没有监听者（本轮 grep：只有派发处 + `api/README.md:57` 文档行），要补全局登出监听；403 不在 `http.js:162-175` 的分支里，需单独成档（"无权限"不该长得像"网络错误"）。
验收：改一次角色 ⇒ 审计表多一行；401 ⇒ 真的跳登录页；403 ⇒ 面板显示"无权限"而非重试。

## 7. 本轮落库的仪器（唯一有牙的产物）

`scripts/gate/check-admin-endpoint-guards.py`：判敏感前缀 `/api/system,/api/tenant,/api/admin,/api/security,/api/sso` 下"接线 router 的 handler 函数体内是否出现 `require_admin(` / `check_permission` / `has_role(`"，命中集与 LEDGER **双向相等**（多＝新债 GROWN，少＝台账过期 STALE），分母格三条（`.rs`=97 ≥40、接线对=405 ≥250、敏感对=92 ≥40）。

本轮实测读数：`.rs` **97**，接线 (path,handler) 对 **405**，敏感对 **92**，已带授权判定 **4**，裸放行 **88**（=台账 88 条，逐条在档案 [1]），未接线 router 声明 **8**（`build_approval_router`，`system/approval.rs:386` 零调用者；同 8 条路径在 `system/mod.rs:530` 以限定名再注册一遍），解析盲区 **0**。

`--selftest` **10 例**（G1 已守卫不红／G2 裸放行全红／G3 匿名 `/api/auth` 正对照／G4 判集塌缩被拒／G5 同一文件内邻接不得让函数体溢出／G6 同名不同体按声明处解析／G7 无法消歧必须显式报 AMBIGUOUS／G10 零调用者 router 不计债／G8、G9 失败路径必须打印证据）。

反证（纯内存 patch，磁盘未动，档案 [5]）：撤一条登记 ⇒ rc=1 `GROWN 1 条`；塞一条假条目 ⇒ rc=1 `STALE 1 条`；复原 ⇒ rc=0；把 `fn_body` 退化成固定 6000 字符窗 ⇒ G5 FAIL。

仪器本轮自咬出的三个缺陷（都已修，写在这里是为了下轮别把它们当"债务涨了"）：
1. 固定字符窗取函数体 ⇒ 邻接的 `require_admin` 被当成自己的守卫（假阴）；
2. 同名 fn 全局首见者 ⇒ `security::revoke_api_key`（`system/security.rs:87`，带守卫）被 `auth.rs:61` 的同名方法顶掉（假阳，曾虚报 1 条债）；
3. 失败路径只 return 不打印 ⇒ 门禁红得无声无息（G8/G9 见证）。
另记一条元教训：**G5 的夹具若拆成两个文件，窗口变异体照样绿**——见证必须复现"同一份文本里的邻接"这一真实形状，否则"有反证例"是假的。
