## 2 · 真并行 · 高性能多线程（用户「最伟大高性能，多线程」）

### 2.1 双璇玑十四维专家派发：串行 → rayon 真并行

| 位置 | 原实现 | 现实现 |
|------|--------|--------|
| `mox-expert/src/expert.rs::dispatch` | `iter().map()` **串行**（注释谎称"并行派发"） | `par_iter().map()` **rayon 并行** |
| `mox-expert/src/harness.rs::run_experts` | `iter().map()` **串行**（注释谎称"并行执行"） | `par_iter().map()` **rayon 并行**（保留原序，结果确定性不变） |

- 依赖：`mox-expert/Cargo.toml` 新增 `rayon = "1.8"`（本地缓存 v1.12.0，离线可解析，`Cargo.lock` 已收录）。
- 验证：`cargo test -p mox-expert` 全绿（并行后结果与串行一致，`experts/`、`pipeline.rs` 契约测试不受影响）。

### 2.2 WebSocket 广播：生命周期级持锁 → 每次发送短持锁

| 位置 | 原问题 | 现实现 |
|------|--------|--------|
| `runtime/src/handlers/governance.rs`（veto/state/ping 三处广播循环） | 循环外一次性 `lock().await` 后**在整个生命周期持有写锁跨 await**，阻塞其他发送者 | 每次 `send` 前获取锁、发送后立即 `drop`，**短持锁不跨 await** |

### 2.3 复核结论

- 知识图谱 PageRank / 中心性 / 社区 / 最短路径为小图（34+ 节点）单线程算法，无并行承诺，串行合理（非假并行）。
- 全仓无其他"注释声称并行、实现串行"的假并行（扫描确认）。

## 6 · 诚实声明（剩余边界）

1. **crates.io 不可达**（沙箱策略 403）：NATS/RabbitMQ 无法引入依赖真实实现，按"禁伪代码"原则删除；若部署环境需要消息队列审计，基于稳定的 `AuditSink` trait 在部署侧接入即可。
2. **S3 端到端需真实存储**：SigV4 签名与 HTTP PUT 路径已真实实现并通过构造测试验证（无 aws-sdk 占位），但完整端到端上传需 MinIO/COS 等真实端点（`AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` 环境变量）。
3. **rayon 全局线程池默认 CPU 核数**：专家并行度由 rayon 全局池决定，默认 = 逻辑核数；如需受限可用 `RAYON_NUM_THREADS` 环境变量。
4. **审计持久化**：`/api/audit` 仍为进程内 `MemoryAuditSink`（重启清空）；`OUS_AUDIT_SINK=log` 可开启日志镜像，S3/Syslog 持久化链路由 mox-expert `audit::` 提供。
