# 资源知识主源与存储适配归一（ADR-19）

> 2026-10-01 · 状态：Proposed · 文档设计，尚未实施或组织会签。

<a id="decision"></a>
## 决策建议

系统策略、云盘资源、对象内容、知识版本、加工、图谱与检索分别维护自己的主源，以精确版本引用与可重建投影贯通。云盘是目录/版本/共享产品，OSS是对象提供方；二者不合成一个巨大存储对象。复用现有网关KB主链与存储契约，适配独立KB/旧RAG模型，暂不删除旧实现或强换数据库。

## 原因与取舍

现有网关KB已持久化对象但挂图为独立内存实例；独立KB SQLite类型不同；企业文件元数据仍有内存/样例路径；storage/switch并不改变业务对象定位。立刻换库或新建一体服务不能自动修复授权、版本和恢复问题。

| 选择 | 建议 | 重评条件 |
|---|---|---|
| 一份目录/文件/图/向量大表 | 分所有权、共享引用和授权策略 | 无需强制同库；先验证事务/投影 |
| OSS等同通用path-style S3 | 每提供方能力与地址/认证契约独立验收 | 官方兼容变化或真实部署差异 |
| 全量内容都进图 | 图保存关系/证据引用与必要投影 | 查询样例证明需要额外正文投影 |
| 立即外置向量/消息/图服务 | 先已有存储+可靠事件意图+可重建索引 | 容量、可用性或隔离测量证明收益 |
| 切提供方后旧对象自动换盘 | 新写默认与存量迁移分开 | 永远保留位置版本与对账证据 |

## 后果与接受条件

需要资源/版本/位置映射、加工及删除job、发布指针、授权检索和提供方真实测试。允许图与索引延迟，但主源撤权立即阻断访问；恢复优先业务元数据与对象清单，索引可重建。接受本ADR之前核定旧数据租户归属、保留策略、真实后端能力、迁移回退和首个业务样例证据。
