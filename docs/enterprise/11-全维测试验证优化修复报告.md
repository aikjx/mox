## 6 · 本轮新闭环：RBAC + 审计中间件全链路挂载（原"已建未挂载"边界）

**原边界**（v1.0 诚实声明）：`rbac_middleware.rs` 实现完整 RBAC/审计但未以 `.layer()` 挂载进请求管线，鉴权仅由网关 `OUS_API_TOKEN` 承担，六角色权限矩阵在运行时不可区分。

**本轮完成**（2026-08-18）：

| 修复项 | 内容 | 落点 |
|--------|------|------|
| 认证主体模型 | 新增 `Principal`（token_id/roles/tenant），认证层一次解析写入请求扩展，授权层直接读取，杜绝两层解析口径不一致 | `rbac_middleware.rs` |
| 令牌注册表 | `TokenRegistry`：`OUS_API_TOKEN` 恒为 Admin；`OUS_RBAC_TOKENS=令牌:角色[:租户]` 多组配置，配置即启用**严格模式**（仅注册表内令牌可认证） | `TokenRegistry::from_env` |
| 全覆盖权限映射 | `required_permission` 兜底未登记路由（GET→ViewFlow，变更→EditFlow），消除原 `from_route` 对已实现接口的假 404 | `rbac_middleware.rs` |
| 审计双写 | 放行 `allowed` / 拒绝 `forbidden` 均写签名审计事件（HMAC-SHA256），修复 `MemoryAuditSink` 异步锁丢弃事件缺陷 | `AuditSink::write` |
| 三层管线 | CORS → `auth_middleware`（认证写主体）→ `rbac_audit_middleware`（授权+审计）→ `standardize_response` | `main.rs` |
| 审计查询面 | 新增 `GET /api/audit`（admin/auditor 专属），返回全部访问审计事件；`/api/logs` 信封化为 `{logs:[...]}` | `main.rs` + `openapi.rs` |
| RFC 9457 语义完善 | 业务失败"资源不存在"类错误由 400 修正为 404 + `NOT_FOUND` 错误码 | `api_standard.rs` |
| 安全收紧 | 兼容模式移除"任意非空令牌→Viewer"兜底，未知令牌一律 401 | `extract_roles_from_token` |

**端到端验证证据**（真实服务器 `operator-server` + HTTP 实测）：

| 场景 | 兼容模式 | 严格模式 |
|------|:---:|:---:|
| 无令牌访问受保护接口 | 401 ✅ | 401 ✅ |
| viewer 写操作（register） | 403 ✅ | 403 ✅ |
| viewer 只读 | 200 ✅ | 200 ✅ |
| 未登记前缀令牌 | 401 ✅（收紧后） | 401 ✅ |
| 任意未登记令牌 | 401 ✅ | 401 ✅ |
| OUS_API_TOKEN（恒 Admin） | 200 ✅ | 200 ✅ |
| editor 写操作 | — | 200 ✅ |
| auditor 读 /api/audit | — | 200 ✅ |
| viewer 读 /api/audit | 403 ✅ | — |
