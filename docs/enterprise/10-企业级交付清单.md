## 四、对外交付边界（已知约束，诚实声明 · 对齐 18 §十一 风险治理）

- **治理 8 闸门（GR-STD）全量接进门禁（2026-08-17 本轮补齐）**：G1 守恒 / G2 零孤儿 / G3 租户合规 / G4 SLA / G5 成本 / G6 敏感度 / G7 状态机 / G8 灾备 全部生效，任一未过即 `GateResult.approved=false` 并写入审计原因。原仅落地 G1/G2/G4/G5/G7 五项的缺口已闭合。
- **租户策略分层（I-06，已交付）**：`GovernContext.tenant` 驱动 `TenantPolicy` 维度严格度差异化；强合规租户（政务/金融）强制 G3 租户合规 / G6 敏感度 / G8 灾备，普通商业租户沿用默认策略。前端融合工作台可按"普通/强合规"一键切换复现。
- **产物来源追溯（I-07，已交付）**：上架算子包固化 `source_flow_id` / `source_task_id` / `dual_acceptance` / `ProvenanceMetrics`（关键路径前/后、加速比、冲突数、专家均分），下游复用/审计可一键查证资产来源与收益。
- **网关 RBAC + 访问审计全链路生效（2026-08-18 本轮闭环，原"已建未挂载"边界消除）**：`auth_middleware`（令牌认证→Principal 扩展）→ `rbac_audit_middleware`（六角色授权 + 放行/拒绝双写签名审计）→ `standardize_response` 三层管线已挂载；`OUS_RBAC_TOKENS=令牌:角色[:租户]` 严格模式 + 兼容模式双支持；新增 `GET /api/audit` 审计查询面。端到端实测：兼容/严格两种模式 11 项探针 + 5 项 E2E 集成测试全部通过（viewer 写 403 / viewer 读 200 / 未登记令牌 401 / OUS_API_TOKEN 恒 Admin 200 / auditor 读审计 200）。
- **双验收联动门禁（I-05，已交付）**：`/mox/publish` 强制要求「需求侧任务 Done ∧ 融合侧璇玑验证通过（算法未否决且 8 闸门放行）」二者同时满足才可上架，否则返回 blocked 原因与 8 闸明细。
- 守恒量 C 为节点自报，闸门查内部自洽，不对照真实代码/需求规模（已在 `07`/`08` 标注，诚实声明为边界）。
- **业务流程升级为 10 BP（原 8 BP）**：新增 BP-9 P9 判重闸门与 BP-10 文档同步治理；原 8 条流程的边界已被横切流程全覆盖，无遗留缺口。
- **M0 全域归一化阶段边界**：`platform/backend-node/`（Node 边缘入口）规划在 M0 更名为 `platform/edge-node/` 并瘦身至 4 文件；当前仍以兼容模式运行，交付承诺在 M0 验收（2026-08-31 前）完成。参见 05 路线图 M0 L2 验收。
- **AI 引擎 M3 统一编排边界**：当前 `/ai/engine/metrics` 已路由可用，但 M3 才要求 P95 AI 查询延迟 ≤ 1000ms；M0~M2 阶段允许延迟基线为 2000ms，对外 SLO 不做此承诺。参见 05 M3 L2 验收。
- 三联盟治理模式为**文档与流程级铁律**，未强制要求独立部署的三联盟软件界面；所有联盟决策可通过 PR 签字 + 06 映射表 + 07 All-01~04 证据链完成，M7 生态阶段才交付外部联盟接入门户。
