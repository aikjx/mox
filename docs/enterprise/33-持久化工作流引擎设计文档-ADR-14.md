# 持久化工作流引擎设计文档（DURABLE EXECUTION ENGINE · ADR-14）

> **文档身份**：企业级持久化工作流引擎（Durable Execution Engine）的总设计。解决当前 `mox-flow-primiflow-svc` 缺少状态持久化、故障恢复、长时运行支持的核心缺口，对标 Temporal / Dagster / Airflow 的 durable execution 范式。
> **版本**：v1.0 ENT（2026-08-26 · 开发专家联盟）
> **权威链**：`18` TOP-MASTER > `02` 架构七视图 > **本文件(ADR-14)**
> **关联 ADR**：ADR-09(跨域依赖)、ADR-13(API层契约)、ADR-15(voice独立化)

---

## §1 问题诊断与设计目标

### 1.1 当前缺口（WHY DURABLE EXECUTION）

| 缺口 | 现状 | 影响 |
|------|------|------|
| **无状态持久化** | 工作流执行状态仅在内存中，进程重启即丢失 | 长时工作流（>1分钟）无法可靠运行 |
| **无故障恢复** | 算子执行失败后无自动重试/补偿机制 |  transient error 导致整个工作流失败 |
| **无事件溯源** | 执行轨迹不完整，无法回放/审计 | 无法满足企业级审计要求 |
| **无定时调度** | 工作流只能即时触发，不支持 cron/延迟 | 无法实现定时任务、SLA 超时处理 |
| **无并发控制** | 同一工作流实例可能被重复执行 | 数据一致性风险 |

### 1.2 设计目标

| 目标 | 验收标准 |
|------|----------|
| **Durable Execution** | 工作流状态持久化到数据库，进程崩溃后可从上次检查点恢复 |
| **至少一次执行** | 每个算子至少执行一次（At-Least-Once），幂等算子保证 Exactly-Once 效果 |
| **长时运行支持** | 支持运行时间 > 24 小时的工作流（等待外部事件、人工审批） |
| **重试与补偿** | 支持指数退避重试、Saga 补偿事务、死信队列 |
| **事件溯源** | 所有状态变更以事件形式持久化，支持回放和审计 |
| **可视化追踪** | 每个工作流实例的完整执行轨迹可查询、可可视化 |
| **水平扩展** | Worker 节点可水平扩展，任务队列支持分片 |

### 1.3 设计原则

1. **命令查询职责分离（CQRS）**：写入侧通过事件溯源，读取侧通过物化视图
2. **事件溯源（Event Sourcing）**：工作流状态 = 所有事件的 fold，不直接修改状态
3. **Saga 模式**：长事务拆分为多个本地事务 + 补偿操作
4. **幂等性优先**：所有算子必须设计为幂等，重试不产生副作用
5. **非阻塞 IO**：等待外部事件时不占用线程，使用 async/await + 事件唤醒

## §3 事件溯源设计

### 3.1 事件类型

| 事件类型 | 描述 | 触发时机 |
|----------|------|----------|
| `WorkflowStarted` | 工作流启动 | 创建实例时 |
| `ActivityScheduled` | 算子被调度 | 运行到某个算子时 |
| `ActivityStarted` | 算子开始执行 | Worker 领取任务时 |
| `ActivityCompleted` | 算子执行成功 | Worker 返回结果时 |
| `ActivityFailed` | 算子执行失败 | Worker 返回错误时 |
| `ActivityRetried` | 算子重试 | 重试策略触发时 |
| `TimerStarted` | 定时器启动 | 工作流等待时 |
| `TimerFired` | 定时器触发 | 到达定时时间 |
| `SignalReceived` | 收到外部信号 | 外部调用 signal API |
| `WorkflowCompleted` | 工作流完成 | 所有算子执行成功 |
| `WorkflowFailed` | 工作流失败 | 不可恢复错误 |
| `WorkflowCancelled` | 工作流取消 | 外部调用 cancel |
| `CompensationStarted` | 补偿开始 | Saga 回滚时 |
| `CompensationCompleted` | 补偿完成 | 所有补偿操作完成 |

### 3.2 事件存储表结构

```sql
CREATE TABLE workflow_events (
    event_id        UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    instance_id     UUID NOT NULL,           -- 工作流实例 ID
    sequence        BIGINT NOT NULL,          -- 事件序列号（单调递增）
    event_type      VARCHAR(64) NOT NULL,     -- 事件类型
    payload         JSONB NOT NULL,            -- 事件数据
    timestamp       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE(instance_id, sequence)
);

CREATE INDEX idx_events_instance ON workflow_events(instance_id, sequence);
```

### 3.3 状态重建（Fold）

工作流当前状态 = 所有事件按 sequence 排序后的 fold：

```rust
fn rebuild_state(events: &[WorkflowEvent]) -> WorkflowState {
    let mut state = WorkflowState::initial();
    for event in events {
        state.apply(event);  // 纯函数，无副作用
    }
    state
}
```

## §4 持久化与恢复

### 4.1 检查点机制

- **每完成一个 Activity** 后持久化一次状态（事件已写入 Event Store）
- **长时等待**（Signal/Timer）时释放协程，不占用资源
- **进程恢复**时，从 Event Store 加载所有事件，重建状态，从上次中断处继续

### 4.2 任务队列

| 队列 | 用途 | 实现 |
|------|------|------|
| **Activity Task Queue** | 待执行的算子任务 | Redis List / PostgreSQL SKIP LOCKED |
| **Timer Queue** | 待触发的定时器 | Redis Sorted Set / PostgreSQL 定时扫描 |
| **Signal Queue** | 待处理的外部信号 | Redis Stream / PostgreSQL |
| **Dead Letter Queue** | 重试耗尽的失败任务 | PostgreSQL 表 |

### 4.3 重试策略

```rust
pub struct RetryPolicy {
    pub max_attempts: u32,        // 最大重试次数（默认 3）
    pub initial_interval: Duration, // 初始间隔（默认 1s）
    pub backoff_coefficient: f64,  // 退避系数（默认 2.0）
    pub max_interval: Duration,     // 最大间隔（默认 60s）
    pub non_retryable_errors: Vec<String>, // 不可重试的错误类型
}
```

### 4.4 Saga 补偿

- 每个 Activity 可定义对应的 **Compensation Activity**（回滚操作）
- 工作流失败时，按逆序执行已完成 Activity 的 Compensation
- Compensation 本身也支持重试
- 补偿失败进入 Dead Letter Queue，需人工介入

## §5 与现有系统的集成

### 5.1 现有算子迁移

当前 `mox-flow-operator-core` 中的算子需要适配 Activity 接口：

```rust
// 现有算子 trait
pub trait Operator {
    fn execute(&self, input: &OperatorInput) -> Result<OperatorOutput, OperatorError>;
}

// 新 Activity trait（持久化引擎）
#[async_trait]
pub trait Activity: Send + Sync {
    async fn execute(&self, ctx: &ActivityContext, input: Value) -> Result<Value, ActivityError>;
    async fn compensate(&self, ctx: &ActivityContext, input: Value) -> Result<(), ActivityError> {
        Ok(())  // 默认无补偿
    }
    fn is_idempotent(&self) -> bool { true }  // 默认幂等
}
```

### 5.2 PrimiFlow 集成

- `mox-flow-primiflow-svc` 作为 Workflow Definition 的解析器和编译器
- PrimiFlow DAG 编译为引擎可执行的 Activity DAG
- 数据流绑定通过引擎的上下文传递

### 5.3 与 kg/ai 域的交互

- 图谱查询、AI 推理等外部调用封装为 Activity
- 通过 `mox-kg-sdk` / `mox-ai-sdk` 调用（不直接依赖 svc）
- 长时 AI 推理通过 Signal 机制异步回调

## §6 开源对标

| 维度 | 本方案 | Temporal | Dagster | Airflow | 差距 |
|------|--------|----------|---------|---------|------|
| 持久化模型 | 事件溯源(PG) | 事件溯源(Cassandra/PG) | 元数据库(PG) | 元数据库(PG) | ✅ 对齐 Temporal |
| 执行语义 | At-Least-Once + 幂等 | At-Least-Once | At-Least-Once | At-Most-Once | ✅ 对齐 |
| 长时运行 | 支持(Signal/Timer) | 支持(Signal/Timer) | 支持(传感器) | 有限支持 | ✅ 对齐 |
| 重试补偿 | 指数退避+Saga | 指数退避+Saga | 重试+重试策略 | 重试+清除 | ✅ 对齐 |
| 水平扩展 | Worker分片 | Worker分片 | Worker进程 | Celery Worker | ✅ 对齐 |
| 可视化 | 执行轨迹+DAG | Web UI | Dagit UI | Web UI | ⚠️ 需自建UI |
| 语言支持 | Rust(原生) | Go/Java/Python/TS | Python | Python | ✅ Rust原生优势 |
| 生态成熟度 | 新建 | 成熟(CNCF) | 成熟 | 成熟(Apache) | ⚠️ 生态差距 |

**结论**：核心架构与 Temporal 100% 对齐（事件溯源 + durable execution + Saga），Rust 原生实现具有性能优势。差距在可视化 UI 和生态成熟度，可通过对接 Grafana/Temporal UI 弥补。

**决策**：不自研完整 Temporal 替代，而是实现**轻量级 Durable Execution 内核**（事件溯源 + 任务队列 + 状态机），满足本项目需求。如需更复杂的工作流编排，后续可评估接入 Temporal Rust SDK。

## §8 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 事件溯源性能（事件量大后重建慢） | 实例启动慢 | 快照机制（每 N 个事件存一次快照） |
| 幂等性难以保证 | 重试产生副作用 | Activity 接口强制 is_idempotent()，代码审查 |
| 与现有 PrimiFlow 集成复杂 | 迁移周期长 | 适配层包装，新旧引擎并行，逐步迁移 |
| 分布式一致性（多 Worker） | 任务重复执行 | 任务队列 SKIP LOCKED + 租约机制 |
