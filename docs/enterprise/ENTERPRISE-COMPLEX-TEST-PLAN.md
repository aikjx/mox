# MOX 企业级超复杂场景测试流程

> 版本：v1.0 | 日期：2026-09-11 | 基准：国家电网 + 小米集团复杂度
> 目标：验证 MOX 系统能否管理超大型复杂企业的所有 OA 与企业数据库

---

## 一、测试场景设计

### 场景 A：国家电网级超大型央企

**企业规模**：
- 员工：150 万人+
- 法人层级：总部 → 6大区域分部 → 27省公司 → 300+地市公司 → 2000+县公司
- 专业子公司：国网信通、国网电商、国网新能源、国网装备、国网物资等 20+
- 业务域：电网调度、输电、变电、配电、营销、物资、财务、人力、安监、科技

**组织架构特征**：
```
国家电网总部（法人1）
├── 华北分部（区域法人）
│   ├── 北京电力公司（省法人）
│   │   ├── 城区供电公司（地市法人）
│   │   │   ├── 西单供电所（县级）
│   │   │   │   ├── 运维一班（班组）
│   │   │   │   └── 营销一班（班组）
│   │   │   └── 海淀供电所
│   │   └── 通州供电公司
│   ├── 天津电力公司
│   └── 河北电力公司
├── 华东分部
├── 华中分部
├── 西北分部
├── 东北分部
├── 西南分部
├── 国网信通产业集团（专业子公司）
│   ├── 国网信通亿力科技
│   ├── 国网信通继远软件
│   └── 国网信通中电普华
├── 国网电子商务有限公司
├── 国网新能源控股有限公司
└── 国网物资有限公司
```

**管理复杂度**：
- 多级法人独立核算，但人事/财务/物资集中管控
- 区域分部有一定自主权，但重大事项需总部审批
- 专业子公司与省公司平级，但业务上有指导关系
- 员工可能同时属于省公司编制和项目组（矩阵式）
- 审批层级最多 7 级（班组→供电所→县→地市→省→区域→总部）

### 场景 B：小米集团级科技集团

**企业规模**：
- 员工：3 万人+
- 业务线：手机、IoT、互联网服务、汽车、金融、新零售
- 生态链企业：400+ 投资/控股企业
- 组织模式：事业部制 + 项目制 + 生态链协同

**组织架构特征**：
```
小米集团（总部）
├── 手机事业部
│   ├── 产品部
│   ├── 研发部（硬件/软件/测试）
│   ├── 供应链部
│   └── 销售部
├── IoT 事业部
│   ├── 智能硬件部
│   ├── 智能家居部
│   └── 生态链管理部
├── 互联网服务事业部
│   ├── MIUI 部
│   ├── 云服务部
│   ├── 广告部
│   └── 游戏部
├── 汽车事业部（独立法人）
│   ├── 整车研发部
│   ├── 三电系统部
│   ├── 智能驾驶部
│   └── 制造部
├── 金融事业部（独立法人）
│   ├── 支付部
│   ├── 信贷部
│   └── 保险经纪部
├── 新零售事业部
│   ├── 小米之家
│   ├── 线上电商

│   ├── 财务部

    ├── 石头科技（扫地机器人）

**管理复杂度**：

- 生态链企业管理：投资关系 + 业务协同 + 品牌授权
- 独立法人与非独立法人混合：汽车/金融是独立法人，其他是事业部
- 审批流程灵活：项目制审批可跨部门、跨法人

### 维度 5：复杂审批流程

| 测试项 | 国家电网场景 | 小米集团场景 | 验证方法 | 预期结果 |
|--------|-------------|-------------|---------|---------|
| 多级串行审批 | 设备采购：班组→供电所→县→地市→省→总部（7级） | 预算申请：组员→组长→总监→VP→CEO（5级） | 审批流程定义 | 逐级流转，每级可驳回 |
| 会签（All） | 重大投资需财务部+审计部+法务部全部同意 | 产品发布需产品+研发+测试+市场全部同意 | approval_policy=All | 全部通过才进入下一步 |
| 或签（Any） | 值班审批：三个值班经理任一通过即可 | 代码评审：两个评审人任一通过即可 | approval_policy=Any | 一人通过即进入下一步 |
| 顺序签（Sequential） | 先部门经理审批，再分管领导审批（有顺序） | 先产品经理确认，再研发负责人确认 | approval_policy=Sequential | 按指定顺序审批 |
| 多数通过（Majority） | 技术委员会评审：5名委员3名通过即可 | 晋升评审：5名评委3名通过即可 | approval_policy=Majority | 超过半数通过 |
| 驳回重提 | 审批被驳回后，申请人修改后重新提交 | 同上 | reject + resubmit | 重新走审批流 |
| 驳回到起点 | 严重问题直接驳回到发起人，跳过中间环节 | 同上 | reject_to_start=true | 直接回到起点 |
| 加签 | 审批人认为需要额外意见，临时加签一人 | 同上 | 加签操作 | 加签人审批后回到原流程 |
| 转签 | 审批人出差，委托他人代审 | 同上 | 转签操作 | 受托人审批有效 |
| 抄送 | 审批结果抄送给相关人员（无审批权） | 同上 | CC列表 | 收到通知，不影响流程 |
| 超时自动处理 | 审批超时24小时自动通过或升级 | 同上 | timeout_seconds | 超时触发预设动作 |
| 条件分支 | 金额<1万部门审批，1-10万省审批，>10万总部审批 | 预算<10万部门审批，>10万VP审批 | 决策步骤+条件表达式 | 按条件走不同分支 |

## 三、最复杂企业级测试流程（端到端）

### 测试流程 1：国家电网-重大设备采购全流程

**场景**：某省公司采购一批变压器，金额5000万，需7级审批+多部门会签

```
步骤1：需求发起（县公司运维班）
  ├─ 登录系统（SSO）
  ├─ 切换到"XX县公司"租户视角
  ├─ 填写采购需求（设备类型/数量/技术参数/预算）
  ├─ 上传技术规范书附件
  └─ 提交审批 → 流程启动

步骤2：供电所审批（或签：3个副所长任一）
  ├─ 副所长收到待办通知
  ├─ 查看需求详情+附件
  ├─ 审批通过（或驳回，填写意见）
  └─ 流程进入下一步

步骤3：县公司审批（会签：生产副经理+财务主任全部同意）
  ├─ 生产副经理审批技术可行性
  ├─ 财务主任审批预算可用性
  ├─ 两人全部通过 → 进入下一步
  └─ 任一人驳回 → 回到发起人

步骤4：地市公司审批（串行：运维部主任→分管副总）
  ├─ 运维部主任审核技术规范
  ├─ 分管副总审核整体方案
  └─ 进入下一步

步骤5：省公司审批（条件分支：金额>1000万走重大采购流程）
  ├─ 系统自动判断金额5000万>1000万
  ├─ 触发重大采购流程：物资部+财务部+审计部+法务部会签
  ├─ 4部门全部通过 → 进入下一步
  └─ 任一部委驳回 → 回到省公司物资部修改

步骤6：区域分部审批（或签：2个区域副总任一）
  ├─ 区域副总审核跨区域影响
  └─ 进入下一步

步骤7：总部审批（多数通过：5名总部采购委员会委员，3名通过）
  ├─ 5名委员分别评审
  ├─ 3名及以上通过 → 审批完成
  └─ 不足3名 → 驳回

步骤8：审批完成后自动动作
  ├─ 自动生成采购订单（写入物资系统）
  ├─ 自动生成财务凭证（写入财务系统）
  ├─ 自动通知供应商（通过电子商务平台）
  ├─ 自动归档审批记录（审计日志）
  └─ 抄送：相关部门负责人

验证点：
✅ 7级审批流程正确流转
✅ 会签/或签/顺序签/多数通过策略正确
✅ 条件分支按金额触发不同流程
✅ 驳回可重提，驳回到起点正确
✅ 跨系统数据同步（物资/财务/电商）
✅ 审计日志完整记录每步操作
✅ 数据权限：各级只能看到自己权限范围内的数据
✅ 超时提醒：每级审批超时自动提醒/升级
```

### 测试流程 2：小米集团-跨部门项目立项全流程

**场景**：立项"小米汽车智能座舱"项目，涉及汽车/手机/IoT/互联网多部门，预算5000万

```
步骤1：项目发起（手机部产品经理，虚线汇报到汽车项目组）
  ├─ 登录系统
  ├─ 主部门：手机部产品组
  ├─ 兼职部门：汽车智能座舱项目组（虚线）
  ├─ 填写立项申请（项目名称/目标/范围/预算/周期/团队）

## 七、结论

### MOX 系统企业级能力评估

| 维度 | 评分 | 说明 |
|------|------|------|
| 多租户管理 | ★★★★★ | 完整的租户模型+隔离+配置 |
| 组织架构 | ★★★★★ | 支持无限层级+多类型+多部门兼职 |
| 权限管理 | ★★★★★ | 功能/数据/字段/接口四维权限+角色继承 |
| 审批流程 | ★★★★☆ | 4种审批策略+条件分支，需可视化设计器 |
| OA集成 | ★★★☆☆ | 框架完整，需补充主流系统适配器 |
| 专家联盟 | ★★★★★ | 多智能体编排+知识图谱+算法联盟，行业领先 |
| 性能扩展 | ★★★★☆ | Rust高性能，需分布式部署验证 |
| 易用性 | ★★★☆☆ | 后端强大，前端需补充低代码设计器 |

**总体评估**：MOX 系统在**后端架构能力**上已达到企业级标准，特别是多租户、权限矩阵、审批引擎、专家联盟等核心能力非常完整。在**OA系统集成**和**前端低代码工具**方面需要进一步增强。

**国家电网级超大型企业**：核心管理能力可支撑，但需补充：①主流ERP/OA系统适配器 ②分布式部署方案 ③移动端审批 ④电子签章 ⑤报表设计器。

**小米集团级科技集团**：核心管理能力可支撑，矩阵式管理和跨部门协作是强项，需补充：①生态链企业管理模块 ②项目管理深度集成 ③产品研发全流程管理。
