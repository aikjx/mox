## 2 · 企业计划（Enterprise Plan）收口

> 下列为企业级落地计划，逐项对应"已完成"的实际交付，不列未实现的空目标。

### 2.1 企业级需求架构（Plan A — 已达成）
- 需求（`01`）与架构（`02`）经 `06` 映射表双向绑定，形成"需求→架构→模块→代码"可追溯闭环。
- 全维需求经 `07` 大白话明确 + `08` 自动化明确，铁律（双收口、无旁路、不做无用扩展）已写入 `05` DoD。
- **交付物**：`00`~`09` 九份 enterprise 文档集，统一治理（`00-INDEX`）。

### 2.2 融合门禁工作流（Plan B — 已达成）
- `primiflow-fusion verify` 作为 CI 门禁：守恒(R07)+零孤儿(A4)+GR-STD 治理 8 闸门，非零退出码阻断合并。
- 与协作治理的 `FR-TASK-05 DoD 门禁` 在 `/publish` 处 AND 闭合（双验收）。
- **交付物**：`crates/primiflow-fusion`（44 passed / 0 failed，2026-08-18 实测），CI 卡点可用。

### 2.3 权限功能归一化（Plan C — 已达成）
- 权限/安全作为最高优先级维度，在裁决(`reconcile`)、闸门(`govern`)、璇玑(`verify`)三处一致生效。
- 越权写被自动化安全护栏拦截（`sensitive_write_is_blocked` 测试通过）。
- **交付物**：`crates/mox-expert` 权限归一化 + RBAC 四权分离 + 审计链。

### 2.4 全维自动化处理（Plan D — 已达成）
- 前端 `MoxFusionView.vue` → `POST /api/optimize` → `mox_optimize` 全自动 8 步闭环。
- 无旁路参数、未声明角色仅授 `viewer`（修复旧版硬编码 admin 漏洞）。
- **交付物**：`crates/mox-expert/src/{server,pipeline}.rs` + 端到端测试。

### 2.5 开发璇玑真分析落地（Plan E — 已达成，2026-08-17）
- **问题**：开发七维专家此前多为"字符串伪分析"占位（如循环依赖检测 `has_circular_dependency` 永远 false、SQL 注入靠 `code.contains("SELECT")` 误匹配）。
- **修复**：7 个开发专家（architecture/security_code/code_quality/performance/testing/documentation/maintainability）全部改为**消费 `CodeUnit` 预分析真字段**——
  - 安全：`hardcoded_secret` / `sql_injection_risk` / `weak_hash` / `n_plus_one`（强否决）
  - 架构：真 DFS 循环依赖检测 + `coupling` 耦合度 + 依赖深度拓扑
  - 质量/可维护：`cyclomatic_complexity` / `duplication_score` / `comment_lines`
  - 性能：`n_plus_one` / `has_outdated_deps` / 复杂度
  - 测试：`test_coverage` / `uncovered`
  - 文档：`has_doc` / `is_public`
- **验证**：`cargo test -p mox-expert` 全绿（含 14 维契约、端到端、越权拦截），全 workspace 编译通过；开发璇玑十四维不再"占位"，真正参与全维分析。
- **交付物**：`crates/mox-expert/src/experts/{architecture,security_code,code_quality,performance,testing,documentation,maintainability}.rs`。

### 2.6 后端统一到 Rust + 前后端契约打通（Plan F — 已达成，2026-08-17）
- **问题（"乱"的根因）**：同一套后端（璇玑全维治理 + 算子市场 + 自动化 + MCP + 知识图谱）在仓库里被实现了**两遍、两种语言**——
  - `backend/`（Node/JS 早期原型，Express，`mox.js` 还是 `hashStr` 造假分数的玩具级）
  - `crates/runtime`（Rust Axum 企业级后端：RBAC/限流/OpenAPI/WS/MCP/优雅关闭，治理内核为真静态分析）
  - 此外 `crates/mox-expert/src/server.rs` 又是一份**与主后端并行的独立 server**（还 `include_str!` 了已删除的 `frontend/mox.html`，导致整库编译失败）。
- **修复（双收口：消除并行服务、无旁路、不引入无用扩展）**：
  1. 删除 `backend/` 整个 JS 原型目录——逻辑已被 `crates/runtime` 完整覆盖，前端 `MoxFusionView` 契约（`/api` + `OUS_API_TOKEN`）与 Rust 完全一致，删后无死链（根 README、docs/enterprise、frontend、start.sh 均无引用；根 Cargo.toml members 仅 `crates/*`）。
  2. `mox-expert/src/server.rs` 缺失的 `mox.html` 依赖改为内联占位页（保留独立 `mox serve` 演示能力，不删文件、不维护两份前端）。
  3. **前后端契约断点修复**（核心）：
     - `mox_optimize` 请求体 `flow` 由强类型 `FlowGraph` 改为宽松 `serde_json::Value`，handler 内 `normalize_flow_to_graph` 归一化——修复前端 `{nodes,edges}` 蓝图被 422 拒绝的真实 bug（与 `mox_publish` 行为对齐）。
     - `mox_optimize` 返回注入前端友好字段 `governance.score`/`governance.gate`/`optimization.metric`/`optimization.algorithm`（纯契约适配层，不改治理内核），修复 `MoxFusionView` 显示空值的断点。
     - `mox_health` 修复重复 key bug（`"mox"` 写两遍）并补全 14 维双联盟专家清单。
- **验证**：`cargo build -p runtime` 0 error；`cargo test -p mox-expert -p runtime` 全绿（mox-expert 146 passed / 0 failed、runtime 全量通过）；端到端冒烟 `/api/mox/optimize` 与 `/api/mox/publish` 均返回真实治理数据（含 `governance.score`/`gate`/`optimization.metric`/`algorithm`/`optimized_graph`），`MoxFusionView` 三步闭环（归一化→治理结论→一键上传算子市场）打通。
- **交付物**：`crates/runtime/src/main.rs`（`/api/mox/optimize|publish|health`）、`crates/mox-expert/src/server.rs`（占位页）、删除 `backend/`。
