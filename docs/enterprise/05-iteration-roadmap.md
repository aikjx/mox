## 1. 持续改进机制（Process）

| 节奏 | 活动 | 产出 |
|------|------|------|
| **每次 PR** | 行为/接口/权限变更须同步 `01/03/04` + 变更记录 | 文档不漂移 |
| **双周迭代** | 领取 backlog 项 → 实现 → 测试 → bump 次版本 | 增量可验证 |
| **季度架构评审 QAR** | 核对 `02-architecture` 与代码事实偏差（沿用 `enterprise-architecture-analysis` 校验法） | 架构不腐化 |
| **发布 ENT** | 文档集全量评审（RACI）通过 → 主版本 bump | 企业级发布 |

**原则**：发现缺陷 → 登记 `BR-/GAP-` → 进 backlog → 修复 → 回填追踪矩阵 + 变更记录（GAP 闭环）。

## 4. 企业级「完成定义」（Definition of Done）

一份文档/一项功能达到企业级，须同时满足：

- [ ] **需求可验证**：每条 FR/NFR 映射代码或测试，GAP 有双向断言（`01` §追踪矩阵）。
- [ ] **架构多视图一致**：业务/信息/应用/技术/安全/集成/部署视图无矛盾（`02`）。
- [ ] **设计可追溯**：模块→文件→接口契约明确（`03`）。
- [ ] **流程可闭环**：生命周期 FSM + BR 目录覆盖（`04`）。
- [ ] **安全可审计**：RBAC/作用域/审计链/威胁模型齐备且经测试。
- [ ] **质量门禁**：`cargo clippy` 零告警、`cargo test` 全绿、集成测试覆盖越权路径。
- [ ] **可观测**：关键路径指标可采集（NFR-08 落地后）。
- [ ] **文档同步**：变更在合并前同步，变更记录留痕。
- [ ] **全维双收口（铁律，见 `07`）**：任何功能须先过 `07` §3 双闸门——①业务流程图归一化（唯一 `FlowGraph` + 六维绑定 + 过 G0）；②开发璇玑全维分析验证（`run_experts` 14 专家无 `veto` + 璇玑 `vetoed=false` + 治理 `approved=true` + `primiflow_fusion::full_gate` 全绿）。**未经双收口的功能一律退回，禁止无验证扩展、禁止模糊需求、禁止给闸门加旁路**。

## 7. 迭代路线图（建议排期）

```
迭代 1（已完成 ✅）：I-01 持久化 + I-02 审计 WAL + I-03 配额
   → 达成「可投产」（数据不丢、有审计、有边界）

   → 达成「企业级全维度开发完成」里程碑（见 `09`）：双璇玑十四维 + 四闸门 + 归一化 + 全维自动化处理，全部经测试验证
   → 本轮（2026-08-17）已补齐 I-05 双验收联动 / I-06 租户策略分层 / I-07 产物来源追溯 / 治理 8 闸门全量门禁

迭代 4+：I-12~I-14 演进（灾备/多模态/分片）
```
