五、待用户拍板（第 3 项 P0）：Expert 模式定位

现状（实测）：Expert 模式下专家节点实际走的是本地璇玑 mox_optimize()（14 专家诊断 + 治理闸门，mock 下节点 score=1.000/0ms），并非外部真实 LLM 流式推理。若预期「Expert 模式 = 真实 LLM 的 ReAct 推理 + 工具调用 + 流式输出」，则当前属未实现。

两个方案供选择：
① 本地璇玑即终极 Expert（推荐短期）：把 mox_optimize 的 14 维诊断结果作为节点产出继续用，融合结论即为「多专家 + 本地诊断」结论，本轮已跑通；无需外部 Key，成本 0，离线可用。
② 接入真实 LLM：Expert 节点改为调用外部大模型（如豆包/OpenAI）做 ReAct + 工具调用（当前工具绑定能力 P0 也未接线）。需要 LLM API Key、成本与延迟预算，且 LlmRouter（626 行）现在 0 运行时调用点，需一并接通。

请确认采用哪个方案，再据此决定是否把 ReAct/工具调用纳入本域开发范围。
