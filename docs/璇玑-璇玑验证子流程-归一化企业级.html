S6 · ⛨ 璇玑验证网关（Xuanji Verification Gate）

子流程标准：AA-STD-V1.0 §1/S6 权威级：最高权限（不可被 RBAC/合规覆盖） 源：xuanji-expert/src/verify.rs + pipeline.rs 位置：S5 flow-ai 求解 之后 · S7 治理 之前

1 · 子流程位置与触发

⛨璇玑在 flow-ai 求解之后、治理闸门之前插入；所有检查均为数学/语义正确性判定，任何 RBAC / 合规 / 权限专家结论都不可覆盖。

S5

flow-ai 最优求解

产出 OptimizationReport：optimized_graph / plan.removed_edges / plan.layers / conflicts / gains / code
→
S6

⛨ 璇玑验证网关

verify(before, opt) 5 项检查 + 并入 expert_veto / escalated_conflict → AlgoVerification
→
S7

治理闸门 Govern

读取 algorithm_veto：若 true → 强制 Blocked，任何权限/合规不可放行
G2最高权限否决：vetoed = any(c.blocking ∧ ¬c.passed) ∨ expert_veto ∨ escalated_conflict。任一阻断级检查失败 → 治理闸门必须 Block（记录 algorithm_veto）。

2 · 五项检查（并行 · 归一化合并）

每项检查输出 Check{name, passed, blocking, detail}；阻断级（blocking）失败才触发否决，软级仅告警不阻断。

① topology 阻断

原始节点全部保留（允许新增 guard/handler）；真数据依赖（写→读共享变量）的可达性必须保持——被挪动导致"读早于写"即语义破坏。普通控制边/伪依赖并行化合法。

② data_dep 阻断

对每条被剪除边：若为真依赖，after 中必须仍存在 u→*v 可达路径；并行层内不得出现同写-读且同层无先后的 RAW 冒险。

③ conflict 阻断

优化后 0 阻塞级冲突；异常边（Exception）落点必须为 Guard / Handler / End（异常归档/终止）。悬空异常边即失败。

④ gains 软

speedup ≥ 1.0 且并行调度耗时 scheduled_ms ≤ sequential_ms + 5%。并行反而更慢属收益虚假，仅告警。

⑤ code_rt 软

代码⇄流程图反向解析工具节点数一致（仅 emit_code 时检查）；未生成代码则跳过。结构未识别仅告警，不阻断。

真依赖判定：u.write_set ∩ v.read_set ≠ ∅ 即 v 必须读到 u 的写；其余为可安全剪除的伪依赖。

3 · 否决归约与联动

S6 不只消费自身 5 项检查，还并入 S3/S4 上抛的两类最高优先级否决源。

否决源来源阶段触发条件归约结果
vetoed（自身）S6 verify任一阻塞级检查 passed=false三者任一为 true → vetoed=true → S7 强制 Blocked
expert_vetoS3 双璇玑诊断任一专家 Risk{veto=true}（如生产/敏感数据越权写）
escalated_conflictS4 归一化裁决同优先级维度约束冲突无法仲裁 → 升级 Blocking

输出契约 AlgoVerification

  • checks: Vec<Check>（5 项 + 可能并入）
  • all_passed：全部通过
  • vetoed：是否否决（最高权限）
  • summary：人类可读结论；否决时标注"⛨ 算法否决：N 项阻断级检查未通过"

与 S7 治理的接口

  • S7 接收 algorithm_veto 作为首个判定项
  • approved = !algorithm_veto ∧ can_emit() ∧ blocking==0 ∧ sla_ok ∧ budget_ok
  • 即使 S7 的 RBAC/合规/SLA 全部通过，algorithm_veto 仍强制 Blocked
  • 审计链记录 gate/blocked（PostGate 瀑布切面）

4 · 设计要点（为何可靠可控明确）

  • 可靠：语义级守恒（拓扑/数据依赖/冲突三项阻断级），优化器任何"加速但破坏语义"的输出都会被拦截，正确性不被性能优化污染。
  • 可控：最高权限不可覆盖，且否决被写入审计链；与 S7 治理、S4 裁决、S3 专家风险形成多重否决源联动。
  • 明确：每项检查产出可追溯 detail（失败即给反例，如"真实依赖 u→v 被破坏"），summary 一句话定位否决原因。
  • 仅翻译、不求解：⛨璇玑只做"优化后图 vs 优化前图"的守恒校验，真正的并行/关键路径/调度仍由 flow-ai 完成。

闭环：S5 求解 → S6 ⛨璇玑守恒校验（最高权限）→ S7 治理（审计+版本+SLA+RBAC）→ S8 出码。任一层否决均可机读、可复核、可阻断。
