一、测试验证发现并修复的 3 个真实缺陷

#缺陷根因修复级别
1 节点上下文丢失
LLM 收到空查询而否决		 planner.rs::make_node 生成节点时 description 只有「金融分析专家 (并行)」占位，从不携带任务描述；build_consult_query 用 node.name+node.description 构建查询 → LLM 只看到「请给出最终专家结论」→ 正确否决 make_node 增加 task_description 参数，5 种计划模式（并行/串行/分层/辩论/迭代）全部把任务描述拼入节点 description；新增单测 test_node_description_embeds_task_description P0
2 react.rs 中文截断 panic
节点 4 次重试全 panic → 任务 failed		 推理轨迹摘要用 &line[..80] 按字节切片，切断多字节 UTF-8 中文字符 → end byte index 80 is not a char boundary panic；每个节点 panic 4 次重试全失败 改为字符安全的 truncate_chars()（按 char 计数截断），mox-ai-expert-svc 164 项单测全过 P0
3 匹配器误判
数学任务选成图像专家		 字符 bigram 下通用词「计算」（计算机视觉）+「分析」（场景分析）让 vision 专家 overlap_hits=2 → infer_domains 推断 ["image","vision"] → required_domains 硬过滤只剩 vision 可选 → 错误专家被选中。用真实内置专家文本复现确认 ①新增 GENERIC_CJK_BIGRAMS，description_overlap 不计入通用词命中；②lexicon_match → lexicon_match_all：关键词自身全部 token 命中才计证据，支持「动态规划/时间复杂度/斐波那契」复合词；③补全数学领域词典（算法/递归/复杂度/数列/导数/积分等 20+ 词）；④词典证据权重 +2。新增回归测试 infer_math_domain_algorithm_task（用真实专家文本断言推断 mathematics 且不含 image/vision） P0

四、LLM 咨询模块架构（本轮新建）

路径：platform/domains/ai/svc/mox-ai-expert-svc/src/llm/

文件职责关键设计
chat.rsDIP 抽象 ChatClient trait；生产 OpenAiChatClient 走 OpenAI 兼容 /chat/completions（reqwest blocking）；测试 MockChatClient 按脚本逐轮推进+调用计数；LlmConfig::from_env() 探测 KeyDIP 可替换
tools.rsTool trait + 注册表；内置 calculate（自研递归下降表达式求值器，支持 +-*/^ 括号一元负号，无 eval）、now、expert_lookup（回调注入，生产用静态 10 专家表）安全求值
react.rsReAct 循环：解析 <tool_call>{json}</tool_call> → 执行工具 → 观察结果回喂；max_rounds=3 默认、max_tool_calls=8；输出含 final_answer/rounds/tool_calls/trace/truncatedReAct
consultant.rsLlmExpertConsultant 实现 ExpertConsultant：按 prefer_expert 映射专家角色构建系统提示，ReAct 结果归一化为 ConsultReport（steps=推理轨迹、score 解析「结论评分」缺省 0.75、vetoed 解析「是否否决」行）；LLM 调用失败或无 Key 回退本地 ExpertServiceImpl优雅降级

环境变量配置

  • MOX_LLM_API_KEY → DEEPSEEK_API_KEY → OPENAI_API_KEY（探测顺序）
  • MOX_LLM_BASE_URL（DeepSeek 默认 https://api.deepseek.com）、MOX_LLM_MODEL（默认 deepseek-chat）
  • MOX_LLM_MAX_ROUNDS（≤20，缺省 3）、MOX_LLM_TIMEOUT_MS
  • MOX_LLM_ENABLED=false 强制禁用；default_consultant() 保持本地向后兼容（flow-bridge/data-catalog 仍用它）
