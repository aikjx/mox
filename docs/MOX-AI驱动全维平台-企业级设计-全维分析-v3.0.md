## 0 · 执行摘要（结论先行）

MOX 已具备企业级低代码底座（DSQL / KG / RBAC+ 字段权限 / AI 助手 / 应用商店 MXAP），但要成为**最伟大的产品**，必须完成一次范式跃迁：

> **从「功能驱动的工作台」跃迁到「AI 驱动的一切由 AI 送上门」——首页只有一个东西：AI 对话中心；所有其他功能不再以独立页面存在，而是以「弹框浮层」从对话中心弹出。**

| 跃迁维度 | 现状（v2.0） | 目标（v3.0） |
|---|---|---|
| 首页形态 | 三前端各自首页（官网/控制台/商店） | **单一 AI 对话中心**，所有前端收敛为一个入口 |
| 功能入口 | 菜单 / 路由 / 页面跳转 | **四向弹框浮层**（侧/顶/底/中），AI 按需弹出 |
| 用户心智 | 用户找功能（人找功能） | AI 送功能（功能找人） |
| 使用模式 | 点按钮 → 填表单 → 看结果 | 说需求 → AI 调度 Agent → 执行 → 对话式迭代 |
| 复杂流程 | 用户自己拆步骤、点多次 | AI 自动编排、Agent 全维封装、一键完成 |
| 产品闭环 | 功能 → 使用 | 对话 → Agent → 执行 → 结果 → 沉淀 → 上架（数据飞轮） |

**三大核心结论**：
1. **架构布局需优化**：从「三前端三首页」收敛为「一对话中心 + 弹框体系」，前端模块按弹框归属重构。
2. **业务处理流程需优化**：所有业务流程封装为 Agent（DSL 即商品），用户只出思路，AI 多跑腿；关键节点人机协同。
3. **技术底座保持 Rust 全维自研**：现有 workspace 已对齐，新增 `对话编排 / Agent 运行时 / 意图调度` 三个核心域，不引入 Python 运行时。

## 1 · 核心哲学：一切由 AI 驱动

### 1.1 一句话定义

> **用户出思路，AI 多跑腿。** 用户只需要表达"我要什么"，AI 负责"怎么做、找谁做、做到哪一步"，并且**把做需要的界面主动送到用户面前**。

### 1.2 三个根本转变

| # | 转变 | 说明 |
|---|------|------|
| T1 | **人找功能 → AI 送功能** | 用户不再在菜单里找"哪个功能能帮我"，AI 理解意图后直接把对应界面/Agent 弹出 |
| T2 | **多页面 → 单对话** | 首页只有 AI 对话中心；所有次级界面以弹框覆盖在对话之上，用户永不离开对话上下文 |
| T3 | **点操作 → 说意图** | 用户输入的是意图而非点击；AI 拆解为 Agent 编排并自动执行 |

### 1.3 设计原则（不可妥协）

1. **对话即入口（唯一）**：首页 = AI 对话中心，没有功能菜单、没有分类导航。
2. **弹框即导航**：所有功能入口 = 从对话中心弹出的浮层；弹框方向由「功能属性」决定（见 §3.2）。
3. **AI 主动**：不止被动响应，还要主动推送（异常预警、任务提醒、机会发现）。
4. **透明可治理**：AI 做了什么、调了哪个 Agent、花了多少 Token，全部可查（右侧流程/DSL 视图 + 治理台）。
5. **人机协同**：低风险全自动，高风险必须人工确认（Human-in-the-loop）。

### 2.2 差距分析（距"最伟大产品"）

| 差距 | 现状问题 | 优化方向 |
|---|---|---|
| **G1 · 入口分散** | 三个前端（mox-website / mox-console / mox-store）三个首页，用户要在多入口间跳转 | 收敛为单一 AI 对话中心；官网/控制台/商店变为弹框或路由面板 |
| **G2 · 功能导航旧范式** | 菜单+路由+页面跳转，用户需要学习系统结构 | 四向弹框体系，AI 按需弹出 |
| **G3 · AI 是被动助手** | 现有 AI 助手主要做 NL→SQL/优化，是被动问答 | 升级为「意图中枢」：理解→规划→调度 Agent→编排→执行→沉淀 |
| **G4 · 流程未商品化** | 商店分发的是应用（MXAP 子系统），业务流程本身不可作为 Agent 上架 | 流程封装为 Agent DSL（即商品），与 MXAP 打通 |
| **G5 · 对话无记忆闭环** | 对话/历史缺乏跨会话长时记忆与知识沉淀 | 增加 mox-memory：偏好/决策/知识库 RAG |

## 3 · 架构设计布局优化

### 3.1 总体布局：一中心 + 弹框体系

```
┌──────────────────────────────────────────────────────────────┐
│                    AI 对话中心（唯一首页）                        │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  顶部：极简（Logo · 全局搜索 · 通知 · 用户）                │  │
│  │  ────────────────────────────────────────────────────  │  │
│  │  AI 问候 + 待办提醒（AI 主动）                            │  │
│  │  ────────────────────────────────────────────────────  │  │
│  │  中央大对话输入（"你想做什么？"）                          │  │
│  │  常用意图建议（文字，非按钮墙）                            │  │
│  │  ────────────────────────────────────────────────────  │  │
│  │  最近对话（可续接）· AI 主动推送便签                       │  │
│  └────────────────────────────────────────────────────────┘  │
│              ▲ 弹框从四向覆盖上来，不离开对话                  │
│   ┌──────────┴──────────┐                                    │
│   │ ① 右侧弹框 (Drawer)  │ ← Agent 商场 / 我的应用 / 知识库   │
│   │ ② 顶部弹框 (Top)     │ ← 全局搜索 / 快捷指令 / 通知       │
│   │ ③ 底部弹框 (Bottom)  │ ← 文件上传 / 参数表单 / 执行进度    │
│   │ ④ 中心弹框 (Modal)   │ ← 敏感确认 / Agent 详情 / 付费      │
│   └─────────────────────┘                                    │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 四向弹框导航规范（弹框 = 功能入口）

| 弹框 | 方向/形态 | 承载功能 | 触发时机 | 企业级考量 |
|---|---|---|---|---|
| **Drawer** | 右侧滑出（约 360-480px） | Agent 商场、我的应用、知识库、设置、历史会话 | 点右上角、或 AI 说"需要安装 Agent"时自动弹出 | 可停靠（Dock），多级抽屉 |
| **Top Sheet** | 顶部下拉命令面板 | 全局搜索（Cmd/Ctrl+K）、快捷指令、通知中心 | 快捷键 / 点顶部搜索 | 类 VS Code 命令面板心智 |
| **Bottom Sheet** | 底部上滑 | 文件上传、参数表单、执行进度、结果确认 | AI 需要用户输入/确认时 | 移动端友好；桌面端可转居中 |
| **Modal** | 居中弹窗 | 敏感操作确认（发邮件/删数据/付费）、Agent 详情、签署 | 高风险操作、展示详情 | 必须强确认 + 审计记录 |
| **Toast/便签** | 悬浮角落 | AI 主动推送（异常预警/任务提醒） | AI 发现问题时 | 可忽略、可一键转对话 |

**设计准则**：
- 用户**永不离开对话上下文**——弹框弹出时对话流可见、可继续。
- 弹框方向由功能属性自动决定（规则引擎），开发者无需手配。
- 弹框内容可由 AI 动态生成（如"帮你找到 3 个可用 Agent，需安装哪个？"→ 右侧 Drawer 自动弹出候选列表）。
- 弹框支持多实例并存（多任务并行），可收起为悬浮胶囊。

### 3.3 前端收敛（对齐现有 frontend-ui）

| 现有前端 | v3.0 归属 | 说明 |
|---|---|---|
| `mox-website`（官网） | 对外营销页，独立保留 | 不纳入对话中心（对外公开） |
| `mox-console`（控制台） | 收敛进对话中心 → 管理能力以 **Drawer + Modal** 呈现 | 管理员/开发者视角 |
| `mox-store`（商店） | 收敛进对话中心 → 商场以 **Drawer** 呈现 | 用户视角，AI 可代用户安装 |
| （新）对话中心 SPA | 唯一首页 | 统一登录后首个落点 |

### 3.4 后端模块化优化（对齐现有 workspace，纯 Rust）

在现有 8 大 domain 基础上，强化/新增三个核心域：

```
platform/domains/
├── ai/                       # 现有：意图核心 + agent/flow/expert 服务
│   ├── core/mox-ai-intent-core   # 升级：意图分类→实体提取→任务拆解→Agent 匹配
│   ├── svc/mox-ai-agent-svc      # 升级：Agent 运行时调度（编排、checkpoint、人机协同）
│   └── svc/mox-ai-flow-svc       # 升级：对话→DSL→执行流水线
├── flow/                     # 现有：flow-operator/primiflow
│   └── core/mox-flow-operator-core  # 强化：Agent DSL 编译、节点图执行、断点续跑
├── market/                   # 现有：应用商店模板
│   └── svc/mox-market-template-svc  # 扩展：Agent 商品化（DSL 即商品，与 MXAP 打通）
└── platform/
    ├── core/mox-dsql-core     # 不变（数据访问底座）
    ├── core/mox-kg-core       # 不变（知识底座）
    └── core/mox-connector-core# 强化：企业连接器（ERP/飞书/钉钉/邮件）
```

**新增横切能力**（可在现有 foundation 域下加 crate）：
- `mox-observability`：已有 → 扩展 Agent 全链路追踪 + Token 成本归因。
- `mox-iam-core`：已有 → 扩展 RBAC+ 到 Agent/DSL 级（谁能用哪个 Agent、哪些数据）。
- `mox-memory`（建议新增）：跨会话记忆 + 企业知识库 RAG + 偏好学习。
- `mox-billing`（建议新增）：Agent 计量、配额、计费钱包、开发者分成。

### 3.5 部署形态

- 服务端：现有 `mox-server` + 网关（单二进制能力已具备）。
- 私有化：保留 DSQL/KG 全能力，数据不出域（对齐现有 L1/L2/L3 三层数据架构）。
- 桌面端：现有 voice-desktop 能力可扩展为「对话中心桌面壳」。

## 4 · 业务处理流程优化

### 4.1 用户主旅程（对话 → 结果 → 沉淀）

```
① 说需求（对话中心）
   │
   ▼
② AI 理解意图（mox-ai-intent-core）
   │  分类 / 实体提取 / 歧义澄清（最少追问）/ 任务拆解
   ▼
③ AI 匹配与调度 Agent（mox-ai-agent-svc + market）
   │  本地已装 → 直接调用；商场有 → 弹 Drawer 建议安装；无 → 通用能力兜底
   ▼
④ 计划预览 + 用户确认（Bottom Sheet / 对话内卡片）
   │  低风险：免确认直跑；高风险：必须确认
   ▼
⑤ 执行（mox-flow-operator-core）
   │  右侧实时流程图/DSL 视图 · 每步输入输出/耗时/Token · 可随时插话
   ▼
⑥ 结果输出 + 对话式迭代
   │  "改成XX" "再加XX" "发给XX" → 立即调整
   ▼
⑦ 记忆沉淀 + 触发下游（mox-memory）
   │  偏好/决策入记忆 · 可建议"以后每周一自动做"
```

### 4.2 Agent 全生命周期（流程 → 商品 → 治理）

```
开发者：编排 DSL（mox-flow-operator-core）
   │
   ▼
封装：输入/输出 Schema + 权限 + 错误处理 + 版本 + 元数据（全维封装）
   │
   ▼
测试/沙箱 → 灰度 → 审核 → 发布上架（mox-market，MXAP/Agent 包）
   │
   ▼
用户：对话触发 → AI 调度 → 安装/调用 → 计费（mox-billing）→ 评价
   │
   ▼
监控：全链路追踪 + 成本 + 成功率（mox-observability）→ 迭代/下线
```

### 4.3 人机协同边界（关键决策表）

| 操作类型 | 示例 | 模式 | 确认要求 |
|---|---|---|---|
| 只读查询/生成 | 查数据、生成周报初稿 | 全自动 | 免确认 |
| 写操作（低危） | 存草稿、更新配置 | 全自动 | 免确认，留审计 |
| 对外交互 | 发邮件、发消息、发布 | **半自动** | 必须人工确认（Modal/对话确认） |
| 资金/删除/敏感 | 付费、删库、批量改 | **半自动** | 双重确认 + 审批链 |
| 高风险决策 | 营销策略、法务结论 | **咨询模式** | AI 给多方案 + 利弊，人决策 |

## 5 · 全维最优模式

### 5.1 三层调度模型

```
L1 对话层（mox-ai-intent-core）   意图→计划（自然语言）
L2 编排层（mox-ai-agent-svc）    计划→Agent 序列（DSL 图）
L3 执行层（mox-flow-operator-core） DSL→节点执行（并行/分支/循环/人机协同）
```

### 5.2 AI 主动性分级

| 等级 | 行为 | 触发 |
|---|---|---|
| R0 被动 | 只响应 | 默认 |
| R1 提醒 | 待办/会议/到期 | 定时/规则 |
| R2 预警 | 数据异常/流程卡点 | 指标监控 |
| R3 建议 | "要自动生成吗""要不要装这个 Agent" | 行为学习 |
| R4 代办 | 在授权范围内自主完成 | 用户显式授权 |

> R4 必须受企业级「授权边界」约束：哪些操作可代办、预算上限、随时可撤销。

### 5.3 可观测与成本（企业刚需）

- 每个 Agent/节点：耗时、Token、模型、费用（`mox-observability` + `mox-billing`）。
- 多级预算：企业→部门→项目→个人；超支自动预警/熔断。
- 模型路由：简单任务用小模型，复杂用大模型（成本与效果平衡）。
- 全量审计：谁在何时调了哪个 Agent、看过哪些数据、做过什么操作（对接 RBAC+）。

## 6 · 开源对标结论（调研摘要）

> 调研结论：MOX 的差异化空白明确——**「对话即入口 + Agent 即商品 + 企业级治理」三合一**，当前开源生态无完全对标物。

| 开源项目 | 定位 | 可借鉴 | 许可证（商用注意） |
|---|---|---|---|
| AutoGPT Platform | 可视化 block 构建 + Agent 市场 + 计费 | 构建器+市场+计费闭环 | Apache 2.0 ✅ |
| Dify | 企业 LLMOps + Agentic Workflow | Workflow Studio、RAG 管道 | 修改版 Apache ⚠️ |
| n8n | 工作流自动化 + Agent 节点 | 节点调试交互 | fair-code ⚠️ |
| LangGraph | 多 Agent 状态机（代码优先） | 状态图/checkpoint/人机协同思路 | MIT ✅（仅参考，不引入 Python 运行时） |
| AgentVerse | Agent 注册表/市场（npm for AI） | artifact 模型/语义版本/MCP/审计 | MIT ✅（已归档，借鉴设计） |
| 联通万悟 wanwu | 企业级多租户智能体平台 | 多租户/纳管/模板广场 | Apache 2.0 ✅ |
| Langfuse / Opik | Agent 可观测 | 追踪/成本/评测 | MIT / Apache ✅ |

**选型红线**：凡做商用 SaaS 的底座优先 MIT / 纯 Apache 2.0；fair-code 与修改版 Apache 只做参考设计，不直接依赖。
**自研边界**：对话体验 + Agent 商品化闭环自研（护城河）；LLM 推理、数据库、浏览器内核为外部依赖，不叫"集成平台"。

## 7 · 分阶段落地路线图

| 阶段 | 目标 | 关键交付 |
|---|---|---|
| **P1 对话中心**（1-2 月） | 首页收敛为 AI 对话中心 + 四向弹框骨架 | ✅ 对话中心 + 右侧 Agent 流程/DSL 面板已落地（见 §9）；顶部命令面板已存在；待补底/中弹框组件库 |
