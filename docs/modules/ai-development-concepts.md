# AI 开发工具概念区分（Trae 生态为主，一眼分清）

很多人混淆：Agent、Skill、Rule、MCP、Prompt、Agent-JSON、Custom Model、RAG，本质是分工不一样，一层套一层。

## 大白话比喻：把 AI 想象成一个程序员打工人

- **Prompt** = 临时口头吩咐（一次性，对话说完就没）
- **Rules** = 公司规章制度，贴墙上，上班全程要看（常驻上下文）
- **Skill** = 工作手册/操作流程，要用的时候才拿出来翻（按需加载，不占 token）
- **MCP** = 工具设备：键盘、git、浏览器、数据库、终端（给 AI 动手干活的能力）
- **Agent** = 完整岗位角色：后端工程师、测试工程师，把 Rules + Skill + MCP + 模型打包成一个岗位
- **RAG / 知识库** = 参考资料柜，查文档、查旧代码
- **Model** = 大脑本身，智商、理解力

## 表格对比（核心区分）

| 概念 | 核心作用 | 什么时候加载 | 存哪里 | 适合放什么内容 | 不适合放什么 |
|------|---------|------------|--------|--------------|-------------|
| **Prompt** | 临时提示，单次对话指令 | 每轮对话输入，说完消失 | 聊天框 | 当前这一轮要做的事 | 长期规范、复杂流程 |
| **Rules**（.trae/rules/*.md） | 硬性约束、编码铁律 | 对话全程常驻，一直占上下文 token | 项目 .trae/rules / 全局 rules | 编码规范、禁止行为、简短铁律 | 几十步长流程，大篇幅文档 |
| **Skill**（SKILL.md） | 多步骤工作流、专业方法论 | 触发才加载，用完释放，不常驻 | .trae/skills/*/SKILL.md | 调试流程、代码审查、需求拆解、git 提交流程 | 简单的一行禁令（丢 rules） |
| **MCP Server** | 外部工具调用能力 | Agent 启动时连接，工具按需调用 | mcp.json | 读文件、git、终端、浏览器、数据库 | 业务逻辑、提示词、流程 |
| **Agent**（agents.json） | 角色配置包，组装上面全部东西 | 切换 Agent 时整体生效 | agents.json | 指定模型、开启哪些 MCP、默认 rules、可用 skills | 不要写大段提示词在里面 |
| **RAG / 知识库** | 读取私有文档、旧代码、外部资料 | 需要检索时才读取片段 | 知识库目录 | 项目文档、接口文档、历史方案 | 强约束规则、操作流程 |
| **Model** | 推理、理解、生成 | 所有对话底层 | 模型配置 | — | 业务逻辑，不能改模型本身 |

## 最容易混淆两组

### Rules vs Skill

- **Rules**：铁律，时时刻刻生效，比如"禁止裸 delete"，每一行代码都要遵守。缺点：写多了暴涨 token，拖慢 AI，会稀释指令。
- **Skill**：一套完整干活流程，比如"系统化调试 bug"，只有你要调试 bug 的时候才启用。用完就丢掉，不占 token。

**口诀：短硬约束放 rules；长流程、多步骤工作放 skill。**

### Skill vs MCP

- **Skill**：告诉 AI「应该怎么思考、步骤是什么」（思维流程，提示词层）
  - 例：调试 skill：1 收集报错 2 复现 3 看日志 4 定位根因 5 写修复方案
- **MCP**：给 AI「可以干什么动作」（工具能力层）
  - 例：filesystem MCP：可以读文件；terminal MCP：可以执行命令

两者配合：skill 定义步骤，MCP 提供工具去执行步骤。skill 不能直接操作文件，必须靠 MCP。

## Trae 里完整工作链路（看懂这个就全部通透）

1. 切换 Agent：读取 agents.json，选定大模型，开启指定 MCP 工具
2. 加载全部 rules：rules 全部塞进系统 prompt，常驻内存
3. 用户发提问 → AI 判断：这件事要不要调用某个 skill
   - 需要 → 动态加载对应 SKILL.md 进入上下文；不需要就不加载
4. Skill 里流程需要读文件/跑命令 → 调用 MCP 服务完成操作
5. 输出结果，skill 对话结束后就从上下文卸载；rules 还留在里面

### 常见错误用法

- 把几十行工作流程写进 rules → token 爆炸，AI 变迟钝。
- 把硬性编码规范写进 skill → 不触发 skill 的时候，约束直接失效。
- 想用 skill 读写文件，但是没开 filesystem MCP → skill 写得再好，AI 也没法读代码。

## 实操选型口诀（直接照抄决策）

遇到一件事，判断放哪里：

- 任何时候都必须遵守，不管做什么任务 → 放到 **rules**
  - 示例：编码规范、禁止裸 SQL、注释必须中文
- 做某一类任务才需要的一套步骤 → 做成 **skill**
  - 示例：调试 bug、代码评审、写单元测试、生成 commit 信息
- 需要访问外部资源（读文件、跑终端、访问 github） → 开启对应 **MCP**
- 想把一整套配置打包，一键切换角色 → 新建 **Agent**，绑定 rules、可用 MCP
- 只是这一次聊天的临时要求 → 直接聊天框输入 **prompt**
- 需要读取大量旧文档、历史方案 → 使用 **RAG 知识库**

## 和其他 AI 工具横向对比（避免混淆外面概念）

- Cursor 的 Rules ≈ Trae 的 rules
- Cursor Agents ≈ Trae Agent
- Cursor MCP 完全兼容 Trae MCP 协议
- Devin / Open-Agent：Agent = 角色 + 工具；没有 Skill 这种按需加载机制，全部塞 prompt
