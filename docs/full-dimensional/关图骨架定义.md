## 3. 六维绑定骨架（REQ→FUN→BIZ→ALG→TSK→COD）

本骨架以 **Bind 边** 将 REQ 根绑定到其主责 crate 入口代码节点（`crates/*/src/lib.rs` 或 `src/main.rs`），
作为「需求→代码」首层可追溯链。后续 P3 在 `flow-ai::primitive` 之上建立完整 Registry，
把 Bind 细化为 REQ→FUN→BIZ→ALG→TSK→COD 六维一一绑定，并导出 TraceMatrix。

首版绑定锚点示例：`Requirement:D01 --Bind--> CodeFile:crates/operator-core/src/lib.rs`

## 4. 偏离检测规则（关图规范「需求锚定与偏离治理」）

`info-graph deviate` 以 REQUIREMENT 节点为根，做**无向可达性 BFS**：

- **GR-E6 偏离/隐性依赖**：核心实现节点（CodeFile/Script/Data/Interface/Function/Business/Runtime，非外部）
  不可达任何 REQ 根 → 视为无需求溯源，即偏离信号。
- **GR-E7 需求未分解**：REQ 根无任何出边（未绑定任何实现）→ 需求悬空。

报告输出：需求根数、核心节点数、已对齐数、偏离数、覆盖率(%)。

### 首版偏离清单（22 项，供 P1/P2 清零）

- 测试文件：`runtime/tests/runtime_integration.rs`、`xuanji-expert/tests/debug_opt.rs`、`xuanji-expert/tests/expert_unit_tests.rs`
- CI/校验脚本：`scripts/ci.py`、`start.sh`、`verify_axioms.py`、`verify_tests.sh`、`verify_tests.ps1`、`snake.py`
- 前端孤立：`frontend/vite.config.js`、`frontend/src/types.js`、`frontend/src/router/index.js`
- 独立后端：`primiflow/backend/engine.py`、`primiflow/backend/main.py`、`docs/ai-architecture/agentic_loop_minimal.py`
- 数据孤岛：`ddl.sql` 未挂接任何 crate，连带其 6 张表（PROJECTS/CONVERSATIONS/TOPOLOGYS/ASSETS/ARTIFACTS/TRACE_LINKS）成孤岛

## 5. 如何使用（工具链）

```bash
# 1) 重建代码级图（可选）
tools/info-graph/target/release/info-graph build --root . --out graph.json

# 2) 注入 REQ 根 + 绑定骨架 → 企业级关图
tools/info-graph/target/release/info-graph skeleton \
  --graph graph.json --spec guantu.req.json --out graph.enterprise.json

# 3) 校验（孤儿/悬空/缺证据/孤岛）
tools/info-graph/target/release/info-graph validate --graph graph.enterprise.json

# 4) 偏离检测（需求对齐覆盖率）
tools/info-graph/target/release/info-graph deviate  --graph graph.enterprise.json

# 5) 导出可视化
tools/info-graph/target/release/info-graph export  --graph graph.enterprise.json --format mermaid
```

## 7. CI 门禁（P5 交付 · `tools/guantu_gate.py`）

以信息关联关系图为唯一基准，在 CI（`.github/workflows/graph-gate.yml`，push/PR 触发）中强制「变更必须同步图」。流程：

1. `build` 重建代码级图 → `graph.json`
2. `skeleton` 注入 REQ 根 + 六维绑定骨架 → `graph.enterprise.json`
3. `validate` 采集硬违规（GR-E1 孤儿 / GR-E2 悬空 / GR-E3 缺证据）+ `deviate` 采集需求对齐偏离（GR-E6）
4. **首次运行**：把当前全部已知问题签名 + 当前覆盖率固化为基线 `.guantu_baseline.json` 并放行（避免对存量孤儿/偏离做「打地鼠」式阻断）；基线须入库以支撑跨提交漂移检测。
5. **后续运行（相对基线门禁）**：
   - 漂移——当前问题集相对基线不得出现「新增」项（新增孤儿/信息孤岛即 `exit 1` 阻断合并）；
   - 覆盖率回归——不得低于已固化基线覆盖率（允许 0.05 浮点容差）；
   - 绝对下限护栏 `COVERAGE_FLOOR=90.0`。

自动豁免（派生代码不强制溯源需求根）：路径含 `target/`、`node_modules/`、`frontend/dist/`、`.workbuddy/`、`examples/out/` 等；诚实保留项白名单 `ALLOWED_DEVIATIONS`（如 `snake.py` 游戏 demo）。

> 当前基线（实测）：8 项已知问题 + 覆盖率 **96.6%**（含 melody2score/core 两处孤儿、DATA_R1S~R4S 四张数据表未挂接需求根，均为已知债务，仅阻断「新增」）。

本地复跑：`python3 tools/guantu_gate.py`（首次固化基线；之后每次应 `exit 0`，引入新未同步节点即 `exit 1`）。
