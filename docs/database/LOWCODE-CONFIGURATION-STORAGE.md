# 低代码配置版本与数据归属架构

> LC-DATA-01 · V1.0 · 2026-10-01 · 逻辑目标模型。实际持久化来源为 `docs/database/DATABASE-ARCHITECTURE.md#1-存储分层总览`；本文不新增DDL或迁移运行数据。

<a id="ownership"></a>
## 1. 配置、交易和投影分开

| 逻辑实体 | owner/内容 | 一致性与保留 |
|---|---|---|
| 配置对象 | 配置owner；稳定ID/kind/scope | 可变草稿指向revision，受乐观版本约束 |
| 配置版本 | owner；spec/schema/hash/原因 | 发布后不可变；历史按依赖与审计保留 |
| 发布包及成员 | 发布模块；精确配置与能力版本 | 依赖闭包冻结；同一release不替换成员 |
| 作用域生效指针 | 发布模块；环境/租户/项目 | 本地事务切换，expected_version冲突保护 |
| 执行快照引用 | 执行owner；release/hash/plan版本 | 与业务任务接纳一致；重启可核对 |
| 权限/身份/秘密引用 | IAM与秘密管理owner | 配置存引用；实时撤权优于旧快照许可 |
| 配置审计与发布证据 | 审计/发布owner | 追加、脱敏、保留等级，不能覆盖 |
| 图谱/搜索/缓存 | kg/kb/运行适配owner | 可重建投影，含源revision与游标 |

这是逻辑对象而非新增八张表指令。实现先核对现有meta、DSQL、配置、模块注册、审计与outbox表，复用语义一致的存储。原有SQL/流程内版本不可被第二配置中心悄悄重编号；发布包引用其owner版本。

## 2. 写入、索引与恢复

唯一性按owner+config_id+scope定义；版本唯一按config_id+revision；发布成员含依赖schema/compiler版本。常用查询索引考虑tenant/scope/kind/status/version；禁止靠JSON全表扫描做授权。大包/制品可由对象存储持有，事务库保存hash与引用，实际引擎由部署档选择。

草稿写→校验记录→发布包写→指针切换是明确的事务边界；跨库引用不能宣称单事务原子性，应先完成包持久化和引用检查，再切权威指针，失败保持旧指针。缓存与投影更新可最终一致，但运行加载验证包hash和版本，不能使用混合成员。

重启按指针和包重建缓存；指针损坏、包缺失、hash不符时拒绝新执行并给出可恢复诊断。不得默默使用任意最新草稿或切换租户数据源。

## 3. 迁移与保留

配置结构升级、业务DDL迁移、配置值变更是三种变化：分别记录schema迁移器、数据库迁移版本、配置revision。结构不可兼容时旧任务继续旧解释器/快照或受控停机迁移；不要让一份新schema重解释旧任务历史。

删除先停止新引用，再检查在用任务/模板/发布包依赖，保留期到达后由受权流程清理；tombstone传播到投影。包回滚只切指针；破坏性DDL与外部写入回滚另做备份/迁移/补偿。

ID、时间、布尔、状态字典遵循实际owner适配；mox_sys的MySQL目标规范不能直接当SQLite现状schema。生命周期策略引用 `docs/database/mox_sys/module-contract.md#3-数据生命周期`。
