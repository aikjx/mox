## 1. 问题定义（Problem）

当前项目虽然已沉淀 **18 份企业级文档 + 15 份专题 + 4 大规范 + 北极星总纲 + 产品手册**，并通过 129 GREEN 基线、T13-SLO/T14-HA 企业级验证，但仍存在以下 8 类**文档层根问题**（非代码 bug，属于"全项目设计没有统一收口成一套唯一可读版本"问题）：

| # | 问题 | 影响 |
|---|---|---|
| D1 | **定名漂移**：README / CLAUDE / 文档中并存"OUS 算子统一系统 / 璇玑 / 关图 / mox"四个近义产品名，缺少唯一对外定名。 | 新人 onboarding 成本 2×；对外话术分裂。 |
| D2 | **北极星不唯一**：`14-总纲` 是 08-18 版、产品手册是 v3、今日输出了新 TOP-MASTER 方案，三者对产品分层/目录/流程 存在非完全一致描述（重叠但未机器级对齐）。 | 设计 ADR 无法唯一溯源；越权修改难以判定。 |
| D3 | **路径老化**：`00-INDEX`、`14`、`CLAUDE.md` 仍写"crates/、frontend/"，实际代码在 `platform/services/、frontend-ui/`。 | 文档失效引用 = 隐性依赖风险。 |
| D4 | **联盟模式缺统一建模**：`standards/expert-alliance-flow-standard.md` 定义专家联盟；`modules/primiflow-design` 定义流程设计；`architecture.md§19` 定义璇玑内核；`product-handbook§二` 定义优化方法论——**四者是同一"三联盟（算法/开发/产品）"体系的四个切面，未被统一建模为一套闭环迭代模式**。 | 持续优化方法论无法被产品化、无法被 AI 机读执行。 |
| D5 | **10 条业务流程（BP-01~BP-10）尚未写入 docs/enterprise**：今日总设计的 BP 仅存在于对话层，缺少机读权威档案。 | 不满足 §四"唯一业务执行标准"声明。 |
| D6 | **工程目录优化方案（§七.2）未登记为 ADR**：`storage-engine` 新增、`backend-node → edge-node` 重命名、`tools/info-graph` 入 workspace、前端 28 视图子目录化、根垃圾文件收纳 —— 缺少 ADR 与 docs 落地。 | 不满足"变更留痕 + 可追溯"企业要求。 |
| D7 | **三档验收标准（L0/L1/L2）与 9 里程碑 M0~M8 未登记进 docs/enterprise/05 + 10**：版本/路线图/交付清单不完整。 | V1.0 发布无唯一验收基线。 |
| D8 | **5 年生态战略 Y0~Y5 未被登记进 docs**：缺少"五年兼容承诺 + 演进不变式"，架构可能被短期过渡方案腐蚀。 | 不满足 §1.2 ⑨"可规模化"标准。 |

本 Spec 的目标：**用 1 次文档归一重构，把以上 8 类问题从根上消除，使 docs/ 成为"全项目唯一事实源"**。

### 2.2 目标（Goals）

- G1：建立**唯一对外产品名** + **唯一北极星总纲** + **唯一治理入口**，三个"唯一"永不漂移。

- G3：把今日输出的「六层产品架构 / 八层图谱建模 / 19 边族 / BP-01~10 / 9 里程碑 / 11 结构问题治理方案 / 10 风险 / 5 年演进」**全部沉淀到 docs/enterprise/**，与现有 00~17 编号衔接，形成 00~19 连续编号文档集。
- G4：所有文档**路径、模块名、crate 名**与仓库实际结构 100% 对齐；消除"文档说 crates/，实际代码 platform/services/"类问题。
- G5：文档集的任何一句话都能溯源到 **代码锚点 OR 测试基线 OR 其他权威文档**，禁止孤立断言。

### 2.3 非目标（Non-Goals，显式声明不做）

- NG1：**不在本次工作中修改代码结构**（本次只改 docs；目录重构 / backend-node 重命名 / workspace 新增 storage-engine / 收纳根垃圾文件——这些属于 Implementation 后续任务，本次 Spec 只负责把 **ADR + 设计 + 验收口径** 写入文档，供后续实施作为唯一授权依据）。

- NG3：不重写已有测试基线数字（649 passed / 129 GREEN / T13 / T14）——只引用、不对其做修改。
- NG4：不修改 `frontend-ui` 与 Rust crate 的源码。若文档需要引用新目录结构，只在文档中以"ADR-规划"标注，不等于代码已变。
