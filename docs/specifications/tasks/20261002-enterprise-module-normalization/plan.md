# 企业模块归一与消息发送实施计划

2026-10-02。用户授权范围：platform/frontend-ui 全域需求、模块关系与业务流程归一，逐模块真实开发；禁止 mock。

## 本轮交付

1. 建立业务能力登记源：覆盖现有业务域及共享基座，需求编号、职责、输入输出、依赖、权威文档、验收条件与当前边界齐备。
2. 从登记源生成模块卡、模块关系图和每模块业务流程图，检查路径、编号、依赖引用与生成漂移。复用 CODE-CATALOG/API-REGISTRY/PORT-REGISTRY，不复制数量和端口事实。
3. 修正模块导航和核心概览的旧事实引用；不修改历史验证结论，不将旧 mock 测试升级为真实验收。
4. 消息发送闭环：真实 in_app API、稳定幂等请求、未知结果重试、可信身份切换失效、实际 message_id 回执。复用已有通知读入口，跨用户授权由 IAM 后端裁决。
5. 执行登记源测试、真实消息 HTTP 回归、前端契约/组件测试与生产构建、新 AGENTS 门禁；报告和完整日志进入 reports。

## 开发顺序

基座/可信身份 → 授权与审计 → 真实查询/命令 → 页面与交付回执 → 持久化作业与恢复 → 知识与工具接缝 → 跨主机与运营验收。各模块通过各自权威台账的退出条件后才能升级状态；不会按建目录、注册路由或测试数量自动判定企业级完成。

## 后续工作

目录授权分页、任务租约与 fencing、真实模型/工具、低代码发布、知识加工与图投影、OSS 往返、外部 outbox、数据同步、跨主机灾备/SLO 分别按依赖推进。新登记源维护需求和逻辑关系，现状和证据仍引用已有模块主源；不另立第二套运行状态数据库。
