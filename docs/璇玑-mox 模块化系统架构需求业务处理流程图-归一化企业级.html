0 · 归一化总纲（Single Source of Truth）

四条不可妥协原则，是"整理优化 / 归一化 / 企业级"的唯一解释基准。

① 归一化

四类流程图（业务/算法/权限/资源）在内存里是同一个 FlowGraph，差异仅体现于节点/边的 Dimension 着色与约束。不存在"四套图各自优化再合并"——那产生数据孤岛与冲突。物理节点唯一，维度只是标签，故"改一个节点，mox 模块化系统架构同步"天然成立。

② mox 模块化系统架构

每个节点同时被双璇玑十四维（业务七维 + 开发七维）评估；优化结论必须同时满足mox 模块化系统架构约束，不做单维最优而牺牲其他维。

③ 最优算法处理

最终求解交给 flow-ai 已验证算法栈（冒险分析并行化 + CPM 关键路径 + RCPSP 资源调度 + 冲突自动修复 + Dijkstra 关系网最短路）。本层只负责把mox 模块化系统架构约束正确翻译成引擎能吃的输入，不重造算法。

④ 可治理

多租户隔离、RBAC 权限、不可篡改审计、流程版本与审批、SLA/成本预算——任何"出码/执行"动作前必须过治理闸门。

一句话定位：七个（+七个）领域专家在归一化 IR 上并行诊断，裁决器按"权限/安全优先"mox 模块化系统架构归一，flow-ai 引擎做已验证最优求解，⛨璇玑验证网关与治理闸门把关后出码——一张图，mox 模块化系统架构最优，企业可治理。

flow-ai 最优求解

optimize：CPM 关键路径 + RCPSP 调度 + 伪依赖剪除 + 冲突自动修复 + 代码生成（emit_code）+ LLM 算力路由（ModelTier）。
→
S6

⛨ 璇玑验证网关

verify 5 项阻断级数学/语义检查（topology / data_dep / conflict / gains / code_rt），最高权限，任何 RBAC/合规不可覆盖。
→
S7

治理闸门 Govern

审计链（哈希链不可篡改）+ 版本状态机（Draft→Review→Approved→Deprecated）+ SLA + 成本预算 + RBAC 审批。
→
S8

出码 / 出图

emit：代码工程 + 拓扑快路径 + 可视化（Three.js 力导向）+ 指标；仅 Approved 且未否决版本可出码。
G2⛨ 璇玑否决（最高优先级）：任一阻断级检查失败 → vetoed=true → 治理闸门强制 Blocked。任何权限/合规结论均不可覆盖本层。专家 veto=true 级风险、裁决冲突升级，亦并入否决。
G3治理闸门：approved = !algorithm_veto ∧ status.can_emit() ∧ blocking==0 ∧ sla_ok ∧ budget_ok。五条件任一不满足即拒；未批准版本仅允许 dry-run。
G1裁决闸门：硬约束（Blocking 级）一律落地，优先于一切软约束（保证权限/安全不可被性能优化绕过）；同优先级冲突平手升级为 Risk(Blocking) 交人工/审批。

2 · 双璇玑十四维专家矩阵

业务璇玑（七维，蓝）与开发璇玑（七维，紫）并行、互不依赖。约束 = 归一化合并最小单元；优先级：Permission/Security > Resource > Data > Business > Observability > Algorithm（开发七维参与同优先级仲裁）。

维度璇玑专家（owner）核心职责典型产出（约束）属性
Business业务业务专家领域规则校验、分支完整性、失败兜底缺 else 警告、必走审批分支软
Algorithm业务算法专家关键路径瓶颈、复杂度、缓存命中建议缓存/拆分、标记 O(n²) 节点；Suggestion::Offload(tier)软
Permission业务权限专家RBAC、越权、合规脱敏（政务等保）MustGuard(desensitize)、Risk(Blocking) 合规硬
Resource业务资源专家算力/连接池/并发，翻译租户配额ResourceCap(browser,1)、MustSerialize硬
Security业务安全专家注入、PII 外发、提示词越狱MustIsolate、Risk(Blocking) 泄露硬
Data业务数据专家血缘、schema 漂移、幂等MustOrder（血缘保序）、幂等建议硬

Performance开发性能专家热点、分配、并发安全性能分、瓶颈标记软
Testing开发测试专家覆盖率、断言、边界测试缺口、强制单测建议软
Documentation开发文档专家注释、README、TraceMatrix 生成文档缺口（PT-DOC）软
Maintainability开发可维护性专家变更影响面、腐化趋势可维护性分、重构优先级软

归一化收口：MCP 工具 / Skill / Loop / LLM 不是外接插件，而是归一化 IR 的第一类公民，参与与企业内部节点完全相同的mox 模块化系统架构约束与最优求解。

4 · 全链路可靠可控矩阵

每一层都有明确的"控制点 / 检查项 / 权威级 / 失败动作"。可靠性来自分层闸门，可控性来自审计链与版本状态机，明确性来自可机读报告。

链路层控制点（闸门）检查项权威级失败动作
S1 需求接入关图 REQ 根 / Bind 骨架REQ 可达性（GR-E6 偏离）、悬空边（GR-E2）关图规范偏离节点挂账，增量阻断
S2 归一化G0 归一化闸门IR 可拓扑排序、维度着色完整、孤儿=0流水线拒绝进入诊断

⛨ 璇玑 5 项检查（任一阻断级失败即否决）

  • topology（阻断）：原始节点全保留 + 真数据依赖可达性守恒
  • data_dep（阻断）：剪除伪依赖不破坏真数据依赖；并行层无 RAW 冒险
  • conflict（阻断）：0 阻塞冲突 + 异常边落点有效
  • gains（软）：speedup≥1 且并行不慢于串行
  • code_rt（软）：代码⇄流程图往返一致（仅告警）

审计链（可控性底座）

  • AuditEvent{who,when,flow,decision,diff} 追加写
  • 哈希链 prev_hash → hash，verify() 防篡改
  • 版本状态机：Draft→Review→Approved→Deprecated
  • RBAC：run/edit/approve/view-audit 四权分离
  • 多租户：namespace 隔离 + 配额→ResourcePool 上限

5 · 关图承载与 CI 门禁（可追溯闭环）

璇玑的"需求→代码"链由关图六维绑定承载，CI 以信息关联关系图为唯一基准，强制"变更必须同步图"。

六维绑定承载（REQ→COD）

REQ 根（D01~D13 / R01~R08）经 Bind 边绑定到主责 crate 入口（crates/*/src/lib.rs），再细化 REQ→FUN→BIZ→ALG→TSK→COD 六维一一绑定，导出 TraceMatrix。偏离检测（GR-E6）：核心节点不可达任何 REQ 根即视为无需求溯源。基线覆盖率 96.6%，绝对下限护栏 COVERAGE_FLOOR=90.0。

CI 强制合规 8 项（非零即阻断）

  1. 图文件纳入版本管理且非空
  2. 无悬空边（GR-E2）
  3. 无重复 id（GR-E4）
  4. 所有边带 evidence（GR-E3）
  5. 核心节点无孤儿（GR-E1）
  6. 无未建模隐性依赖（GR-E6）
  7. 文档引用全部有效（GR-E7）
  8. 新变更 sync 漂移 = 0（GR-E8）

全链路"可靠可控明确"闭环：需求有根（REQ）→ 处理有归一化 IR → 优化有已验证引擎 → 正确性有 ⛨ 璇玑最高权限否决 → 出码有治理闸门与审计链 → 演进有关图同步漂移门禁。任一层均可机读、可复核、可阻断。
