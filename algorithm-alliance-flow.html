① → ⑩ 全维分析需求业务处理主流程

编排器 programming_pipeline 包裹内核 alliance_optimize。任一闸门失败按护栏 G‑E 回退最近安全点，三证（⑥verify ＋ ⑧一致 ＋ ⑨Approved）齐全方可出码。

需求归一化 护栏 G-A

原始意图 / 大模型抽取 → NormalizedRequirement（可判定需求书：目标/输入/输出/约束/禁忌/署名）。草稿或未声明禁忌 → 禁止建模出码。

↩ 回退点 Normalized：AI 草稿 / 模糊约束，止于此处不出码

循环护栏 LoopGuard

消费 ctx.registry.loops。无界 / 未登记循环默认否决；无界需 safety_approver，人在环需 operator/approver。

↩ 回退点 Modeled：循环不安全，禁止出码

流程图建模 FlowGraph

业务/算法/权限/资源四图同体（同一 FlowGraph，维度仅作标签）。auto_dimension 完成维度着色，进入内核。

七专家并行审查 业务七维

插件化运行时（Harness）瀑布扩展点驱动：algorithm / business / data / observability / permission / resource / security 并行产出 ExpertOpinion。开发七维经 CodeIR 同引擎分析。

归一化裁决 reconcile 归一核心

十四维观点 → 单一 ReconciledPlan：冲突预扫描（同级同类→Blocking 升级）、按优先级物化约束、合并租户配额、采纳建议（排除与硬串行冲突的 Parallelize）。

flow-ai 最优求解

apply_rules 注入合规规则 → optimize：并行化 / 关键路径 / RCPSP 排程 / 冲突消解 / 代码生成。model_routes 并入算力路由。

⛨ 璇玑验证网关 最高权限

5 检查（topology / data_dep / conflict 阻断级；gains / code_rt 仅告警）＋ 专家否决级风险 ＋ 裁决冲突升级 → algo.vetoed。任何 RBAC/合规不可覆盖。

↩ 回退点 Optimized：vetoed → BLOCK，禁止出码

出码 Emit 仅三证齐全

独立调用 codegen 生成代码（必在 ⑥ 通过之后，封堵未过验证网关即出码红线）。有界循环 max_iter 桥接到 LoopStart 节点。

双向映射校验 护栏 G-C·二证

节点级 def 齐全校验：每个可执行节点必须有对应 def py_ident(id)(ctx:)；code.rejected 直接判不一致（M2 硬红线）。

↩ 回退点 Emitted：双向断裂，拒绝出码

治理闸门 govern 护栏 G-C·三证

approved = !algo_veto && status.can_emit() && blocking==0 && sla_ok && budget_ok。尊重璇玑否决。

↩ 回退点 Governed：未 Approved，禁止出码

交付 + 审计闭环 safe_to_emit

产物：代码 + 治理报告（专家分/优化/璇玑/闸门）+ 防篡改审计哈希链 AuditChain。署名（G-D）贯穿全程。

双联盟十四维（归一化分析视角）

同一 Expert 引擎并行分析；业务七维管「做什么/是否合规」，开发七维管「怎么做/是否优质」，非冗余互补。

③ 归一化裁决状态机

只翻译约束为 flow-ai 可识别的边/规则，不求解。

阶段动作输出
冲突预扫描同级同类别→升级Blocking；互补→溯源；串行vs并行→语义相反Reconcile
优先级物化按 priority() 升序，高优先级覆盖低优先级软约束图+边
约束落地Guard插入/Mutex串行/Isolate/Audit/Cap/Compliance/Route硬约束
配额合并租户 ResourcePool 取 min资源池
采纳建议排除与硬串行冲突的 Parallelize，其余采纳adopted_suggestions

⑥ ⛨ 璇玑验证网关 5 检查

阻断级失败或汇集专家否决/冲突升级 → algo.vetoed → 治理必 BLOCK。

检查阻断级守恒语义
5a topology阻断节点全保留；真数据依赖可达性守恒
5b data_dep阻断真依赖剪除须有路径保留
5c conflict阻断0 阻塞冲突；异常边落点有效
5d gains仅告警speedup≥1 且并行不慢于串行
5e code_rt仅告警代码⇄流程图往返工具节点守恒

企业级治理属性

五护栏（不能「问了 AI 就处理」）＋ 回退点 ＋ 治理闸门公式。

G-A

AI 产出默认草稿·未确认，不得直接执行/出码

G-B

每个动作映射到已确认节点＋流程＋规范条款

G-C

verify＋⑧一致＋⑨Approved，三证不全禁止出码

G-D

AI 产出必须署名（模型/专家视角），禁止无来源

G-E

任一闸门失败回退最近安全点，禁止将错就错

治理闸门判定

approved = !algo_veto && status.can_emit() // 仅 Approved 可出码 && blocking == 0 // 无阻断级冲突 && sla_ok // scheduled_ms ≤ quota.sla_ms && budget_ok; // scheduled_ms ≤ quota.max_cost_budget*1000
