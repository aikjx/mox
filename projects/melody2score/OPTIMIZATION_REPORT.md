## 二、简谱质量问题根因诊断

针对用户指出的四类问题，深入分析根因：

### 2.1 问题一：减时线（下划线）排版混乱

**现象**：多个八分音符各自单独画下划线，而非共用一条减时线。

**根因分析**：

1. **jianpu-ly 默认 beam 行为**：jianpu-ly 的 `q`（八分）和 `s`（十六分）前缀标记每个音符的时值，但 beam（减时线连线）的自动分组依赖于 LilyPond 的默认行为
2. **休止符打断 beam 组**：音符间的休止符 `q0` / `s0` 会切断 beam 分组，导致前后的八分音符各自独立画线
3. **跨小节音符被拆分**：`_build_jianpu_text` 中跨小节长音用 `~` 延音线连接，但每段独立生成 `q` 前缀，可能破坏 beam 视觉连续性

**代码定位**：`core/jianpu_render.py` 第 169-286 行 `_build_jianpu_text()`

**优化方向**：
- 利用 jianpu-ly 的 `KeepLength` 机制或显式 beam 分组
- 优化休止符插入策略，避免不必要的短休止打断 beam 组
- 确保同一拍内的相同时值音符自动连成一条减时线

### 2.2 问题二：附点位置排版瑕疵

**现象**：附点与音符、减时线挤在一起，印刷错位。

**根因分析**：

1. **音符密度过高**：当小节内音符较多（如十六分音符密集）时，LilyPond 自动间距计算可能压缩附点空间
2. **beam 组内附点音符**：附点八分音符 `q1.` 在 beam 组中，附点位置可能与 beam 线产生视觉冲突
3. **字体/渲染 DPI 影响**：低 DPI 下细线条与附点的像素对齐问题

**代码定位**：`core/jianpu_render.py` 第 102-138 行 `_dur_token_for()`

**优化方向**：
- 调整 LilyPond 排版参数，增加附点音符的最小水平间距
- 提高默认 DPI（从 150 提到 200+）改善渲染质量
- 验证 jianpu-ly 附点音符的排版规范

### 2.3 问题三：X 0 音+休止反复交替

**现象**：大量出现 "音 + 八分休止 + 同音" 的模式，谱面细碎。

**根因分析**：

1. **音符分割边界效应**：`analysis.py` 的 `segment_notes` 中，VAD 切边 + 置信度阈值可能把连续长音切成"音-隙-音"三段
2. **后处理合并条件偏严**：`postprocess.py` 的 `merge_consecutive_repeats` 要求 `gap <= 0.05s` 且两段都 `< 0.25s`，对较长的间隙不合并
3. **量化阶段不做语义合并**：`quantize.py` 只做时值量化，不处理"被短休止分隔的同音"合并

**代码定位**：
- `core/analysis.py` 第 215-243 行 `segment_notes()` 最终过滤
- `core/postprocess.py` 第 74-112 行 `merge_consecutive_repeats()`
- `core/quantize.py` 第 93-136 行 `quantize_notes()`

**优化方向**：
- 放宽后处理合并条件：对"音高相同 + 间隙 < 0.1 拍 + 间隙为短休止"的模式也合并
- 新增量化后"同音短休止合并" pass
- 引入音乐记谱优化：连续的音-休-音模式，如果是同音且休止很短，合并为附点或延音

### 2.4 问题四：高低音符号混乱

**现象**：低音点错位、高音符号畸形。

**根因分析**：

1. **文本简谱 vs 图片渲染不一致**：
   - 文本简谱（`score.to_jianpu`）：高音用前缀 `.`，低音用后缀 `_`
   - 图片渲染（`jianpu_render`）：高音用 `'`，低音用 `,`
   - 两套表示方式不统一，容易混淆
2. **文本简谱的 `_` 歧义**：低音点后缀 `_` 与减时线下划线 `_` 字符相同，在纯文本环境中无法区分，导致"低音点看起来像减时线"的视觉混乱
3. **渲染字体问题**：如果 LilyPond 字体不完整，可能导致高低音点渲染畸形

**代码定位**：
- `core/score.py` 第 53-111 行 `to_jianpu()`
- `core/jianpu_render.py` 第 72-78 行 `_oct_marks()`

**优化方向**：
- 统一文本简谱的高低音点表示：高音用 Unicode 上点 `̇`，低音用 Unicode 下点 `̣`
- 或采用 HTML 标签方式：`<sup>.</sup>1`（高音）、`1<sub>.</sub>`（低音）
- 确保图片渲染的字体配置正确

## 三、优化实施方案

### 优化一：减时线（beam）分组优化

**目标**：同一拍内的连续八分/十六分音符共用一条减时线，符合出版级简谱规范。

**实施要点**：
1. 分析 jianpu-ly 的 beam 分组机制
2. 在 `_build_jianpu_text` 中按拍分组，确保同拍内的相同时值音符连续
3. 优化休止符处理：极短休止（< 十六分）吸收到相邻音符，避免打断 beam

### 优化二：节奏记法优化

**目标**：减少不必要的"音+休止"交替，让谱面更简洁、更符合记谱惯例。

**实施要点**：
1. 新增"同音短休止合并"逻辑：相同音高 + 短休止（< 0.125 拍）→ 合并为一个长音
2. 优化后处理合并条件：放宽间隙阈值，从 0.05s 调整为 0.08s
3. 引入"休止符优化"：连续多个短休止合并为一个标准时值休止

### 优化三：文本简谱规范化

**目标**：文本简谱的高低音点、减时线、附点表示更清晰，无歧义。

**实施要点**：
1. 高音点：从前缀 `.` 改为 Unicode 组合上点 `̇`（如 `1̇`）
2. 低音点：从后缀 `_` 改为 Unicode 组合下点 `̣`（如 `1̣`）
3. 减时线：用下划线字符 `_` 前缀（如 `_1` 表八分），与低音点彻底区分
4. 附点：保持 `.` 后缀，但确保与高低音点不混淆

### 优化四：附点排版与渲染质量提升

**目标**：附点位置清晰，不与减时线/音符拥挤。

**实施要点**：
1. 提高默认渲染 DPI：从 150 提升到 200
2. 增加 LilyPond 排版间距配置
3. 验证附点音符在 beam 组内的渲染效果

## 五、风险与注意事项

1. **jianpu-ly 兼容性**：修改 jianpu-ly 输入格式需验证对所有时值类型的支持
2. **时值精度**：合并休止符可能轻微改变音符时长，需确保在量化误差范围内
3. **Unicode 支持**：文本简谱使用 Unicode 组合字符需确认终端/编辑器的渲染支持
4. **向后兼容**：优化不应破坏现有 API 契约，新增功能以可选开关方式提供

## 六、已实施优化详情（v3.0 版本）

### 6.1 节奏记谱优化（已实施）

**修改文件**：
- `core/quantize.py` — 新增 `optimize_rhythm()` 函数
- `core/jianpu_render.py` — 新增 `_optimize_event_rhythm()` 函数
- `core/score.py` — `to_jianpu()` / `to_musicxml()` 集成节奏优化

**优化内容**：

| 优化项 | 算法 | 阈值 | 效果 |
|--------|------|------|------|
| 同音短休止合并 | `note + 短rest + 同note` → 合并为一个长音 | rest ≤ 0.125 拍（八分的一半） | 消除"5 0 5"这类分割伪影 |
| 极短休止吸收 | < 0.0625 拍的微休止吸收到前一音符 | rest < 1/32 拍 | 消除谱面细碎的十六分休止 |
| 事件流级别合并（渲染层） | 事件流中 `note+rest+note` 同音合并 | rest ≤ 1 单位（0.25拍） | 图片渲染谱面更整洁，beam 更连续 |

**集成位置**：
- 文本简谱 / MusicXML：量化后调用 `optimize_rhythm()`
- 图片渲染：`_build_jianpu_text()` 事件流构建后调用 `_optimize_event_rhythm()`

### 6.2 文本简谱高低音点规范化（已实施）

**修改文件**：`core/score.py`

**新增参数**：`to_jianpu(..., unicode_octave=False)`

**两种模式对比**：

| 模式 | 高音点表示 | 低音点表示 | 减时线表示 | 附点表示 | 歧义问题 |
|------|-----------|-----------|-----------|---------|---------|
| 兼容模式（默认） | 前缀 `.`（如 `.1`） | 后缀 `_`（如 `1_`） | 前缀 `_`（如 `_1`） | 后缀 `.` | 低音点 `_` 与减时线 `_` 字符相同 |
| Unicode 规范模式 | 组合上点 U+0307（如 `1̇`） | 组合下点 U+0323（如 `1̣`） | 前缀 `_`（如 `_1̇`） | 后缀 `.` | 无歧义，四类标记位置完全不同 |

**使用方式**：
```python
# 兼容模式（默认，向后兼容）
jianpu = score.to_jianpu(notes, key, bpm)

# Unicode 规范模式（出版级，推荐）
jianpu = score.to_jianpu(notes, key, bpm, unicode_octave=True)
```

### 6.3 渲染质量提升（已实施）

**修改文件**：
- `core/jianpu_render.py` — 新增 `_inject_lilypond_tweaks()` 函数，默认 DPI 150→200
- `core/score_sheet.py` — 默认 DPI 150→200

**调优内容**：

| 调优项 | LilyPond 设置 | 效果 |
|--------|--------------|------|
| 分辨率提升 | `--png -dresolution=200` | 文字线条更清晰，减少锯齿 |
| 音符间距 | `SpacingSpanner.base-shortest-duration = 1/16` | 避免附点与减时线拥挤 |
| 均匀拉伸 | `SpacingSpanner.uniform-stretching = ##t` | 音符间距更均匀美观 |
| Beam 斜率 | `Beam.positions = #'(2 . 2)` + `Beam.damping = #0.5` | 减时线更平直，减少倾斜错位感 |
| 行宽缩进 | `line-width = 180mm` + `indent = 0mm` | 更适合屏幕阅读的版式 |
| 中文字体 | Noto Sans CJK SC / Microsoft YaHei / SimSun | 中文标题/歌词不乱码 |
| 标题页头 | `\header { title / composer }` | 标题、作曲者信息自动显示 |

**注入方式**：jianpu-ly 生成 .ly 后，在 `\score` 块前注入 `\header` + `\paper` + `\layout` 块。
注入失败静默回退，不影响主流程。
