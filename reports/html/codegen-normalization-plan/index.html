一、愿景与一句话定位

一句话定位：mox 是一块通用系统母版（mox_sys）+ mox 模块化系统架构知识图谱 + AI 持续优化闭环的业务系统生成平台。任何行业拿它"装领域包 → 选模块模板 → 装插件 → AI 一键生成并不断调优"，业务系统即成型，不再从零造轮子。
1 块母版
mox_sys 内核（身份/租户/组织/IAM/审计/文件/图谱）
∞ 插件
Plugins / MCP / 算子商城，统一契约即插即用
N 模板
归一化 TPL：单表/树表/主子表/图谱/工作流
AI 闭环
分析→生成→验证→优化→再生成
全行业
金融/医疗/政务/零售 = 领域包，非重造

为什么能"不重复造轮子"：所有业务系统共享同一套底层能力（用户、租户、权限、审计、文件、流程、图谱、AI）。差异只在领域包（domain pack）与模块模板（template）。mox 把"建系统"从"写代码"降级为"装配 + 配置 + AI 生成"，把"优化系统"从"人肉重构"升级为"AI 持续分析与自动调优"。

架构自上而下分为六层，越往下越稳定、越通用；越往上越业务、越可插拔。每一层都有唯一权威来源（SSoT）。

三、无限插件体系（即插即用）

mox 的"无限插件"不是口号，而是已有三类插件承接面，统一走 meta 模块契约，安装/禁用/升级互不影响：

插件形态现有落点归一化契约能力
AI 插件PluginsView / getAiPlugins / sendPluginMessageplugin manifest + SPI注册/消息/拓扑/AI 路由
MCP 兼容工具McpView / mcpListTools / mcpCall / aiMcpMapMCP schema标准工具协议接入任意外部能力
算子商城MarketView / marketUpload / aiMarketSearch → OperatorsViewoperator manifest算子注册/执行/推荐，沉淀为可复用能力
领域包iam/meta/ea/kg/ai（module-registry）module_code + SemVer平台/领域模块安装/禁用/迁移
"无限"的机理：插件面只定义契约（manifest + 接口），不绑定实现。新增一类能力 = 写一份 manifest + 实现 SPI，经 verify 门禁后即上架到对应市场（插件市场 / MCP / 算子商城 / 模块市场）。治理闸门保证"无限"不会失控——任何插件必须过合规、安全、权限三关。

四、模块模板库（归一化 TPL）

把"建系统"拆成有限几种业务形态模板，每种模板自带后端骨架 + 前端页面 + 路由菜单 + 文档，对齐现有 ProjectsView 范式。模板即"轮子"，全行业复用。

TPL 编号业务形态生成产物对齐现有模块
TPL-01单表 CRUD后端 service+controller / 前端列表+表单 / 路由菜单ProjectsView / ResourcesView
TPL-02树表树形组织 + 父子 CRUDGraphView 节点树 / 资源管理
TPL-03主子表主表 + 明细表联动TaskView（任务+子步骤）/ 工作流
TPL-04图谱实体节点/边 + 3D 画布 + 自动入图GraphView / MoxFusionView
TPL-05工作流DAG 定义 + 执行 + 实例WorkflowView / primiflow
TPL-06AI 对话域ChatView 子类 + 会话/消息持久化ChatView / CaomeiView

模板扩展机制：新增一类形态只需新增 gen/tpl-XX.rs + 分派 match 追加 1 个 arm；TDD 先 RED 后 GREEN，产物字节级对比；出码必经 verify + 治理闸门。

⑤ 再生成

反馈入图
阶段现有能力作用
① 分析aiFullAnalysis / algorithmAnalysis / aiResourceAnalysismox 模块化系统架构诊断、性能/结构分析
② 生成aiFullComplete / aiGenerateDoc / aiGenerateFlowDiagram / aiGenerateErd出码、出文档、出图

④ 优化InfiniteOptimizerView(无穷维度优化) / aiOptimize / moxOptimize / getInfiniteBenchmarks / applyBestConfig自动寻优、A/B 对比、一键应用最优配置
⑤ 再生成aiDevTestFix / aiOptimizeDoc / aiFusionGovern缺陷修复、文档优化、融合治理
闭环不退化原则：每次优化产出都必须回 verify 门禁；优化结果（best config / 新代码）作为"证据"挂入知识图谱（evidence_id），形成可溯源的演进链，避免 AI 优化"黑盒不可审计"。

六、mox 模块化系统架构全知识图谱

依据 docs/database/mox_sys/relation-model.md，mox 采用 SQL 交易真相 + 图谱语义投影双轨。图谱不是装饰，而是系统的"记忆与推理层"：

关系层保存什么真相来源
交易关系用户/租户/订单/任务/审批SQL owner module
语义关系expert→has_capability、资源继承、相似案例kg graph projection
证据关系来源表/文件/事件/版本/模型/置信度mox_sys_evidence
检索关系embedding/倒排/图算法分数可重建索引

投影链：SQL → outbox event → graph projector → idempotent upsert → checkpoint/rebuild。节点由 graph_id + entity_type + entity_key 唯一确定（entity_key 为稳定业务键，不暴露自增 ID）。关系代码一律小写 snake_case（如 task_depends_on_task、expert_has_capability）。

mox 模块化系统架构含义：所有模块、插件、模板、AI 优化产出、业务单据，最终都投影成"实体—关系—证据"图谱。系统因此具备跨模块语义记忆：新项目生成时可复用历史案例，AI 优化时可检索相似方案——这正是"不用重复造轮子"的知识底座。

九、行业零重复造轮子（领域包）

不同行业 = 不同的领域包（domain pack），装在同一个 mox_sys 母版上。底层能力（用户/租户/权限/审计/流程/图谱/AI）完全复用，不重写。

行业领域包内容复用底座差异化模板
金融信贷/风控/对账/监管报送mox_sys + iam + auditTPL-03 主子表 + TPL-05 工作流
医疗问诊/病历/排班/医保mox_sys + kg + eaTPL-04 图谱 + TPL-01 单表
政务审批/事项/证照/监管mox_sys + iam(sso) + auditTPL-05 工作流 + TPL-02 树表
零售进销存/会员/营销/订单mox_sys + ea + aiTPL-03 主子表 + TPL-06 AI 域
零重复造轮子的本质：行业差异被数据化、配置化、模板化，而非代码化。新增一个行业 = 装包 + 填模板参数 + AI 生成业务页面，平均从"数月研发"降到"配置即上线"。

SSoT 铁律：① 命名统一 {前缀}-{两位序号}-{中文短名}.md；② 状态/类型/关系代码一律英文短码 + 版本化字典，二值字段为 Y/N；③ @doc-link 代码反向引用；④ 跨模块只引用稳定 ID / 事件 / 图谱关系，不直接依赖对方私有表；⑤ 核心交易数据在事务库，图谱/向量/检索为可重建投影。

十二、总结

系统价值

  • 底座一次建成，行业无限复用：mox_sys 母版解决身份/租户/权限/审计/流程/图谱/AI 共性，行业只装领域包。
  • 无限插件 = 契约即插即用：Plugins / MCP / 算子商城 / 模块市场四类面，统一 manifest + SPI，治理闸门防失控。
  • 模块模板 = 轮子标准化：TPL-01~06 覆盖主流业务形态，生成产物字节级可验证。
  • AI 持续优化 = 系统会自进化：analyze→generate→verify→optimize→regen 闭环，产出可溯源入图。
  • 全知识图谱 = 系统有记忆：实体—关系—证据投影，跨模块复用历史案例与方案。
