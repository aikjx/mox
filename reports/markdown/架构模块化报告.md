### 1.3 组件复用率评估

- **通用组件数量**：8 个（已落地）
- **业务组件数量**：19 个（`src/components/` 下非 common 目录）
- **视图页面数量**：68 个
- **高频重复模式覆盖率**：8/12 = **66.7%**（已有通用组件覆盖的模式数 / 总识别模式数）

### 1.4 结论与建议

**现状**：通用组件库已具备 8 个高质量组件，覆盖了最核心的 UI 模式。但实际项目中多数页面仍直接使用 Element Plus 原生组件，通用组件渗透率较低。

**高优先级建议**：
1. 新增 `FormDialog.vue`（表单弹窗）—— 14 个页面重复实现，抽取收益最高
2. 新增 `DetailDrawer.vue`（详情抽屉）—— 9 个页面重复实现
3. 新增 `StatCard.vue`（统计卡片）—— 7 个页面重复实现，Dashboard 等页面可直接复用

**中优先级建议**：
4. 逐步将现有页面的 el-table + 分页替换为 `DataTable` 组件
5. 逐步将确认弹窗替换为 `ConfirmDialog` 组件

## 二、Composable 标准化

### 2.1 Composable 清单与模式检查

`src/composables/` 下共 **9 个** composable 文件：

| Composable | 路径 | 返回模式 | loading | error | 规范性 |
|-----------|------|---------|---------|-------|--------|
| `useTheme` | `useTheme.js` | { theme, toggle, setTheme } | 无 | 无 | 工具型，无需 loading/error |
| `useKnowledgeBase` | `useKnowledgeBase.js` | { data, loading, error, methods } | ✅ | ✅ | **完全规范** |
| `useMessageActions` | `useMessageActions.js` | { methods } | 无 | 无 | 工具型（纯操作函数） |
| `useProject` (projectContext) | `projectContext.js` | { currentProject, projects, methods } | 部分 | 部分 | 数据型，loading/error 不完整 |
| `useAlliance` | `workspace/useAlliance.js` | { data, loading, error, methods } | ✅ | ✅ | **完全规范** |
| `useGraphCanvas` | `workspace/useGraphCanvas.js` | { canvasRef, methods } | 无 | 无 | 画布操作型，无需 loading/error |
| `useTaskOrchestration` | `workspace/useTaskOrchestration.js` | { tasks, loading, error, methods } | ✅ | ✅ | **完全规范** |
| `useWhiteboard` | `workspace/useWhiteboard.js` | { whiteboardRef, methods } | 无 | 无 | 画布操作型 |
| `useWorkspaceData` | `workspace/useWorkspaceData.js` | { data, loading, error, methods } | ✅ | ✅ | **完全规范** |

### 2.2 标准化覆盖率

- **数据型 composable（需 { data, loading, error, methods } 模式）**：5 个
  - 完全规范：4 个（useKnowledgeBase、useAlliance、useTaskOrchestration、useWorkspaceData）
  - 部分规范：1 个（projectContext / useProject —— loading/error 状态不完整）
- **工具型 composable（纯函数/操作，无需 loading/error）**：4 个
  - useTheme、useMessageActions、useGraphCanvas、useWhiteboard

**数据型 composable 规范覆盖率：4/5 = 80%**  
**整体 composable 合理率：9/9 = 100%**（工具型无需强制 loading/error）

### 2.3 不规范项详情

**projectContext.js（useProject）**：
- 问题：`loadProjects()` 和 `ensureProjectContext()` 函数有 try/catch，但错误仅 `console.error`，未暴露 `error` 状态给组件
- 影响：组件无法根据 error 状态展示用户可见的错误提示
- 建议：补充 `error` ref，在 catch 中设置 `error.value = e.message`
