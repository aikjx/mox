# Melody2Score 原曲播放器与识别精度修复记录

日期：2026-09-12。范围：projects/melody2score 的桌面应用、自带 Web 页面、播放引擎及识别解析链路。

## 修复内容与原因

1. **原曲播放器**：桌面原曲由 QMediaPlayer 解码和播放，提供暂停/继续、停止、进度拖动、时间和音量。文件、样例直接使用原音频，保留原采样率与声道，不再经过识别用的 22050Hz 单声道解码。录音使用自动清理的临时文件。原曲与钢琴回放互斥。Web 页面增加原生 audio controls，支持文件、录音、样例，切换时释放 Blob URL。
2. **播放数据丢失**：旧生产者在 write 超时后直接进入下一块，忽略尚未写入的字节。现在保留偏移并重试，首块也按预充容量分段，避免大块填满缓冲后无法启动消费。
3. **并发与完成状态**：环形缓冲改成生产者和消费者分别维护的单调游标；避免读位置与共享 used 计数不一致。取消后不再挂回旧会话，旧会话清槽与新播放互斥；等待实际缓冲耗尽后再完成，而非按剩余时长猜测结束。
4. **采样率与声道**：soundfile 备用路径读取真实源采样率，先混合声道，再重采样到识别采样率。48kHz 双声道 440Hz 测试保持 1 秒、16000 样本和 440Hz。
5. **连续同音漏音**：起音切分的音符保留边界；多次识别共识传播多数边界证据；后续合并不跨这些边界，保护短重复音和静音分隔音。
6. **绝对音高**：不再默认把高音/低音旋律移回 C3–C5。新增 normalize_octaves=False；只有显式启用才按原逻辑移调，同时加入缓存配置标识。
7. **发行依赖**：取消 PyInstaller 对 QtMultimedia 和 QtNetwork 的排除。此次验证为源码环境，尚未重建或验证冻结 EXE。

## 实测证据

39 项独立测试通过。最终播放组 29 项、识别与新增回归组 12 项，其中 2 项重复执行；真实声卡开关已启用，无未验证的跳过项。

| 检查 | 结果 |
|---|---|
| 连续同音对照夹具，预期 3 个音 | HEAD 原实现输出 2 个；修复后输出 3 个 |
| 高音真实 PCM，经 pYIN 与生产解析链路 | MIDI 76、78、79 原八度保留，octave_shift=0 |
| 小星星端到端 | 14 音序列、重复音、时值、C 大调、简谱及 BPM 容差断言通过 |
| 消费暂停 350ms，超过旧写超时 | 20480 字节 PCM 顺序及内容完全一致 |
| 原生媒体解码与播放 | 7.560 秒样例，无媒体错误，播放位置前进到 2357ms |
| 暂停、拖动、继续 | 暂停位置稳定；拖动到 4000ms；恢复后到 4370ms |
| 样例路径 | 有效样例可读；../README.md 被拒绝 |

原生媒体进度验证静音运行，用于检查解码与时钟，不等同于主观听感评价。真实声卡播放冒烟另行通过。自动化测试覆盖播放数据完整性、线程取消、缓存与采样率、识别解析、原生控件、路径约束；Python 编译、Web 内联 JavaScript 语法、git diff --check 通过。

```powershell
python projects/melody2score/app/gui.py
```

## 精度结论与边界

这些证据证明了具体漏音、移调与解码问题的修复，不代表全部歌曲达到某个总体准确率。此次没有跑完整 144 样例矩阵，也没有用带标注的真实多人声/伴奏录音评估。既有系统的 BPM 硬范围、声源分离和基于规则的后处理仍可能影响复杂音乐；高/低音还受用户配置的 fmin/fmax 约束。后续全量基准应分别统计绝对 MIDI、音级、音符 precision/recall、起止时间误差、BPM 与调式，避免用音级命中率掩盖八度或重复音错误。
