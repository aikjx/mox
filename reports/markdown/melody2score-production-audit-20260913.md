# Melody2Score 生产就绪审计

日期：2026-09-13。结论：可以继续优化；目前适合受控试用，尚无证据支持作为无人复核的生产转谱系统验收。本轮为代码审计与最小复现，未修改业务代码。此前 51 项测试通过不覆盖下述所有缺陷。

## 已复现缺陷

证据：[production-audit.json](../data/melody2score-ai-20260912/production-audit.json)。

1. `enterprise_api.py::_notes_to_vexflow`：120 BPM 下 0.75 秒为 1.5 拍，输出 duration=hd（附点二分），而 total_beats=1.5，表示不一致。应修正附点四分表示并核对实际前端渲染契约；所有支持时值必须做数值与渲染往返验收。
2. `core/postprocess.py::drop_too_short_or_long`：输入 start=0,end=8,dur=8，输出 end=6,dur=8，既截断真实长音候选又留下矛盾字段。应统一时间字段，不根据固定六秒上限自动改写声音事实；谱面跨小节用连音线表达。
3. `core/pitch.py::_run_with_timeout`：10ms 超时已抛出，150ms 工作仍执行完毕。超时只是停止等待，不释放计算资源。应以可终止工作进程实现超时，限定并发与队列，并测试超时后资源回收。
4. 企业 API 的配置构造和识别参数未暴露 ai_review；桌面/独立 Web 已有的功能尚未在企业入口贯通。

## 代码确认与待验证风险

- 两个 Web 入口在 async 路由中同步解码；推理移入线程不等于整条请求不阻塞。应将解码和推理均交给受控任务执行器，用并发时健康检查延迟验证。
- 两个入口直接读取完整上传；所查路由没有明确的应用层文件字节数、解码时长及专用推理队列上限。网关是否提供限制未在本轮核实，不能据此声称整个部署完全没有保护。
- BPM 代码硬限制 40–160。注释声称源于历史用户约束，不能擅自删掉；应改为显式场景策略，通用模式另行评测，超范围返回说明。
- AI 复核只检查已输出音符的音高，不能验收漏音、节奏、休止、调式和整谱正确率。
- 当前神经环境继承系统包，尚未形成独立锁定依赖、模型校验和干净机器安装验收；旧 EXE 尚未重建。

## 精度证据边界

144 个合成样例 / 1773 个参考音符上，pYIN 严格音符 F1=99.66%，CREPE tiny=98.95%。噪声和混合伴奏各仅 3 个合成样例 / 39 个音符，AI 分别为 97.37% 和 82.93%。这些数值不是实录歌曲准确率，也不是整谱正确率。当前没有独立真实录音留出集，不能给出生产精度结论。详见[先前验证报告](melody2score-ai-accuracy-20260912.md)。

## 下一轮实施与验收顺序

1. 修正上述时值和时间字段缺陷，贯通企业 API 的复核参数。验收：每个支持时值、长音、跨小节与重复音有对应回归；输入输出时间字段一致；三入口对相同配置与文件返回一致的核心结果。
2. 建立真实录音金标准：逐音标注绝对 MIDI、起音、止音、休止、拍号、节奏和目标声部；两人独立标注并裁决分歧。按歌曲、歌手、录音来源划分训练/开发/测试，避免同一旋律跨音色泄漏；冻结测试集后再优化。
3. 分别报告音符 precision/recall/F1（绝对 MIDI、起音容差50ms、一对一）、含止音指标（容差 max(50ms,参考时长20%)）、八度错误率、节奏准确率及整曲零错误比例；按清唱、单乐器、伴奏混合分别出结果，不用总体平均掩盖最差场景。
4. 对模型路由、声源分离和后处理分别做消融对比。只有独立测试集改善且无不可接受的场景退化才切换默认策略，不能预先承诺更大模型收益。
5. 建立质量校准与拒绝自动定稿机制：输出明确的证据状态和需复核时间段。产品可以明确说无法确认；不能将这种输入强行标记为正确。
6. 完成有界上传/解码/队列、进程超时取消、错误隔离、模型预热及可复现安装。锁定硬件、最大音频时长和并发后，测 p50/p95/p99 延迟、峰值内存、失败率、取消回收时间；目前无基线，不能编造延迟或容量承诺。

“100%”只能描述冻结测试集上观察到的结果，不能推出任意未来音频都正确。生产交付应同时给出支持范围、实际指标和不能自动定稿的条件。
