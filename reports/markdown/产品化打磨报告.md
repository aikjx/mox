## 一、三态完整性审计与修复

### 1.1 修复前全局统计

| 三态 | 有此态的页面数 | 总页面数 | 覆盖率 |
|------|--------------|---------|--------|
| Loading 态（v-loading 或骨架屏） | 17 | 68 | **25.0%** |
| Empty 态（el-empty 或 EmptyState） | 39 | 68 | **57.4%** |
| Error 态（ElMessage.error 或 el-alert） | 45 | 68 | **66.2%** |
| 三态完整 | 12 | 68 | **17.6%** |

### 1.2 本轮修复详情

#### 修复 1：Dashboard.vue（项目仪表盘）

**修复前问题**：
- ❌ 无 loading 态：`load()` 调用 `getStatus()` + `getLogs()` 时页面无任何加载指示
- ❌ 无用户可见 error 态：API 失败仅 `console.warn`，用户看到空白 KPI 卡片
- ✅ 有 empty 态：执行日志区域有 `el-empty`

**修复后**：
- ✅ 新增 `loading` ref，`load()` 开始时设 true，finally 设 false
- ✅ 根容器添加 `v-loading="loading"` + `element-loading-text="仪表盘数据加载中..."`
- ✅ 新增 `loadError` ref，API 失败时设置错误信息
- ✅ 新增 `el-alert` 错误提示条，含「重新加载」按钮
- ✅ 新增 `reload()` 函数支持一键重试

#### 修复 2：OperatorsView.vue（算子中心）

**修复前问题**：
- ❌ 算子库列表加载无 loading 态：`loadOps()` 调用 `getOperators()` 时算子库区域空白
- ✅ 有 error 态：`ElMessage.error('算子列表加载失败')`
- ✅ 有 empty 态：搜索结果为空时有 `el-empty`
- ✅ 执行按钮有 `:loading="running"`
- ✅ 注册按钮有 `:loading="reging"`

**修复后**：
- ✅ 新增 `opsLoading` ref，`loadOps()` 开始时设 true，finally 设 false
- ✅ 算子库面板添加 `v-loading="opsLoading"` + `element-loading-text="算子库加载中..."`

#### 修复 3：MarketView.vue（算子商城）

**修复前问题**：
- ❌ 商城列表加载无 loading 态：`load()` 调用 `marketList()` 时内容区空白
- ✅ 有 error 态：`ElMessage.error('加载商城失败')`
- ✅ 有 empty 态：商城为空时有 `el-empty` + CTA 按钮
- ✅ 随机按钮有 `:loading="randoming"`

**修复后**：
- ✅ 新增 `loading` ref，`load()` 开始时设 true，finally 设 false
- ✅ 内容区添加 `v-loading="loading"` + `element-loading-text="商城数据加载中..."`

#### 修复 4：WorkflowView.vue（工作流）

**修复前问题**：
- ❌ `loadAll()` 并行调用 4 个 API（getFlows/getWorkflowTemplates/getWorkflowInstances/getWorkflows）时无 loading 态
- ✅ 有 error 态：`ElMessage.error('加载失败')`
- ⚠️ empty 态：部分子面板有，主页面不完整

**修复后**：
- ✅ 新增 `loading` ref，`loadAll()` 开始时设 true，finally 设 false
- ✅ 根容器添加 `v-loading="loading"` + `element-loading-text="工作流数据加载中..."`

#### 修复 5：stores/index.js（AI Store 导出缺失）

**修复前问题**：
- ❌ `ai.store.js` 已存在但未在 `stores/index.js` 中导出，导致无法通过统一入口使用

**修复后**：
- ✅ 新增 `export { default as useAiStore } from './ai.store.js'`

## 二、视觉一致性

### 2.1 设计 Token 使用情况

项目已建立 `src/styles/` 设计 token 体系，包含：
- CSS 变量：`--text-1`、`--text-2`、`--text-3`、`--bg-page`、`--bg-hover`、`--border`、`--brand`、`--success`、`--danger`、`--warning` 等
- 主题切换：暗色/亮色双主题支持

### 2.2 硬编码颜色扫描

扫描全部 68 个视图 + 27 个组件，发现 **12 个文件**存在硬编码颜色（`#xxx` / `rgb()` / `rgba()`）：

| 文件 | 硬编码颜色数 | 典型场景 | 优先级 |
|------|------------|---------|--------|
| Dashboard.vue | 8 | KPI 卡片图标背景、趋势图颜色、欢迎横幅渐变 | 中（图表颜色需固定） |
| OperatorsView.vue | 3 | 步骤引导渐变、对比图颜色 | 低（图表颜色） |
| GraphView.vue | 5 | 图谱节点颜色、力导向图配色 | 低（图谱可视化需固定） |
| ExpertCenterView.vue | 4 | 专家卡片头像渐变、状态指示点 | 中 |
| MarketView.vue | 2 | 卡片 hover 效果 | 低 |
| 其他 7 个文件 | 各 1-2 | 零星使用 | 低 |

**说明**：大部分硬编码颜色集中在 ECharts 图表配置和图谱可视化场景，这些场景需要固定颜色值以保证可视化效果，属于合理使用。真正需要替换为 CSS 变量的是 UI 组件样式中的硬编码颜色（约 5-8 处）。

### 2.3 按钮样式一致性

| 按钮类型 | 规范 | 合规情况 |
|---------|------|---------|
| Primary（主要操作） | `type="primary"` | ✅ 统一 |
| Success（成功操作） | `type="success"` | ✅ 统一 |
| Warning（警告操作） | `type="warning"` | ✅ 统一 |
| Danger（危险操作） | `type="danger"` | ✅ 统一 |
| Default（次要操作） | 无 type | ✅ 统一 |
| 文字按钮 | `text` 属性 | ✅ 统一 |

**结论**：按钮样式一致性 **95%+**，仅个别页面有自定义按钮样式（如 Dashboard 欢迎横幅上的半透明按钮），属于设计需要。

### 2.4 卡片/面板样式一致性

- 统一使用 `.panel` + `.card-pad` 类名
- 统一圆角、阴影、内边距
- **合规率：约 90%**，少数页面有自定义面板样式
