> **核验日期**：2026-09-03  
> **核验范围**：`frontend-ui/src/api/` 下全部 19 个 API 模块文件（http.js/index.js 为基础设施不计入）  
> **核验方法**：抽取（方法+路径+参数+响应）→ 定位（网关原生/代理目标服务 handler）→ 比对（方法/路径/参数/响应信封四维）→ 判定

## 二、P0 级问题清单（功能性阻断，必须优先修复）

### P0-1：actuator.api.js 双重前缀 BUG（13 个接口全部 404）

| 项 | 详情 |
|----|------|
| **影响范围** | actuator.api.js 中 13/14 个接口（仅 `openLogTail` 直接 fetch 不受影响） |
| **根因** | `actuatorHttp` 实例 `baseURL='/actuator'`（http.js:318），但所有调用路径又以 `/actuator/` 开头，axios 组合后实际请求 `/actuator/actuator/*`，与后端路由 `/actuator/*` 不匹配 |
| **证据** | 前端 actuator.api.js:28-44；后端 actuator.rs:679-692（路由注册在 `/actuator/*`） |
| **受影响端点** | index, health, info, env, metrics, mappings, api/:id, api/:id/enable, api/:id/disable, loggers(GET/POST), logs(GET/DELETE) |
| **修复方案** | 将 13 个调用路径去掉 `/actuator` 前缀（如 `actuatorHttp.get('/health')`），或将 `actuatorHttp` 的 baseURL 改为 `''` |

### P0-2：KB 全域路径前缀不匹配（21 个接口实际不可达）

| 项 | 详情 |
|----|------|
| **影响范围** | kb.api.js 中 21/24 个接口（仅 kbSearchEntities/kbLinkEntity/kbUnlinkEntity 经 kb_ext.rs 路径正确） |
| **根因** | `mox_kb_svc::handlers::build_kb_router()`（handlers.rs:438-457）注册路由为 `/kb/*`（**无 `/api` 前缀**），网关 lib.rs:136 直接 `.merge(kb)` 未做路径嵌套。前端 `baseURL='/api'`，实际请求 `/api/kb/*`，axum 无法匹配，落入代理 fallback→编排器→404 |
| **证据** | mox_kb_svc handlers.rs:438-457 vs 前端 kb.api.js 全部路径；网关 lib.rs:136 |
| **受影响端点** | documents CRUD、analyze、batch-analyze、categories、tags、search、versions 全套、graph-link、stats、history 等 |
| **修复方案** | 方案A：将 handlers.rs 中所有路由路径从 `/kb/*` 改为 `/api/kb/*`；方案B：网关 lib.rs 改用 `.nest("/api", kb)` 替代 `.merge(kb)` |

### P0-3：`/api/ai/engine/*` 路径前缀架构级错位（多端不可达）

| 项 | 详情 |
|----|------|
| **影响范围** | 前端 ai.api.js 的 `getEngineFlowGraph`；alliance.js 的 `getAllianceCapabilities`、`runAllianceFullSSE`；以及网关 kg_ai 的 4 个标准引擎端点（process/analyze/capabilities/metrics）和编排器 ai_engine 的 9 个子端点对前端均不可达 |
| **根因** | 网关 kg_ai 路由（http_adapter.rs:770-773）注册在 `/ai/engine/*`（**无 `/api` 前缀**）；编排器（main.rs:566）`.nest("/ai/engine", ...)` 同样无 `/api` 前缀。前端 `baseURL='/api'`，请求为 `/api/ai/engine/*`，经代理转发后前缀不匹配，必然 404 |
| **证据** | http_adapter.rs:770-773；编排器 main.rs:566；ai_engine.rs:42-77；前端 ai.api.js:60, alliance.js:7-67 |
| **修复方案** | 方案A：编排器将 ai_engine nest 从 `/ai/engine` 改为 `/api/ai/engine`，网关 kg_ai 路由同步迁移；方案B：网关代理在转发时剥离 `/api` 前缀（需谨慎，影响全局） |

### P0-4：`/api/voice/health` 路径前缀不匹配

## 三、P1 级问题清单（契约不一致，路由可达但行为异常）

### P1-1：Market review 请求体字段不匹配（3 个接口）

| 项 | 详情 |
|----|------|
| **影响范围** | operators.api.js 的 `marketApprove`/`marketReject`；market.api.js 的 `reviewMarketTemplate` |

## 十、核验方法论与质量保障

### 核验流程

每个接口均走完四步流水线：
1. **抽取**：从前端 `export const` 定义中提取 HTTP 方法、完整路径（含 baseURL 归约）、请求参数/体、期望响应字段
2. **定位**：先检索网关原生路由模块（system.rs/alliance.rs/actuator.rs/monitor.rs/notification.rs/workspace.rs/projects_ext.rs/experts_ext.rs/misc.rs/kb_ext.rs/routes.rs），再检索代理目标服务（编排器 main.rs/ai_router.rs/market.rs/automation.rs、PrimiFlow server.rs、mox_kb_svc handlers.rs、kg service http_adapter.rs）
3. **比对**：方法一致性、路径精确匹配（含路径参数）、请求参数/体字段对齐、响应信封格式匹配
4. **判定**：四档判定（✅已实现/⚠️不一致/❌未实现），每个判定附 file:line 证据

### 质量保障措施

- **4 个并行子代理分片**，避免单代理上下文溢出导致的遗漏
- **分片边界互斥且完整覆盖**：19 个 API 文件全部分配，无遗漏无重叠（notification unread-count 跨分片冲突已解决）
- **每个判定必须有 file:line 证据**，无证据的推断明确标注
- **legacy 后端不计入当前架构**：仅在 `platform/legacy/` 中存在的实现判定为未实现，因其未被网关路由注册引用
- **排除构建产物**：所有检索排除 `target/`、`dist/`、`node_modules/`、`.git/`
- **跨分片冲突检测**：汇总阶段对相同端点的不同判定进行交叉验证
