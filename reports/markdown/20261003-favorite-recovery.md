# 专家收藏权威读取与刷新恢复验证

本轮交付 EA-OBJ-10/11：SQLite 批量权威读取、同标签页持久待确认请求恢复与身份/请求代际保护。功能和流程权威为 [对象契约](../../docs/expert-alliance/22-expert-object-contract.md)，本报告只记录验证。没有新增业务 mock、模拟成功回执或降级假数据。

## 实现范围

- Rust 增加 `POST /api/experts/favorites/query`，每批最多 100 个 ID；SQLite 同一读事务复用语句，按可信租户检查全部对象，404/503 显式返回。进程缓存不参与判定。
- 前端当前页加载先确认原待确认键，再拉取真实快照；最多 200 位专家分为至多两个批次，每批独立快照。请求序号、身份代际与写版本拒绝过期响应。
- sessionStorage 只保存原 UUID 和专家 ID，按租户/用户隔离。命令发送前先落本地记录；刷新重建实际 store 仍沿用原键；确认后删除。损坏记录和存储失败阻断新命令，不静默丢弃待确认意图。
- 接口元数据源 actuator.rs、生成 API 注册表、前端端点表和四张实际 Mermaid 流程图同步；不建立第二份状态权威。

## 真实验证

证据目录：[data/20261003-favorite-recovery](../data/20261003-favorite-recovery/summary.json)。每条命令保存完整日志、退出码和工作目录；失败尝试同样保留。

| 验证 | 范围 |
|---|---|
| Rust 收藏仓储 7 项 | 原子切换、并发幂等、回执失败回滚、重开数据库读取、跨租户对象拒绝、真实缺列读取故障 |
| Rust 真实 HTTP 1 项 | 实际 JWT/生产 router/TCP/临时 SQLite；两租户同 ID 读取不同状态，批量上限、404、503与软停用重载 |
| 实际前端联调 | Vite SSR 加载真实 Pinia、AuthStore、Axios 与联盟 API；TCP 代理先让 Rust 提交再丢响应，重建前端实例后恢复同一键；确认后 journal 清理，重新实例读取持久状态无写操作；200 位批量读取；损坏 journal 不发新命令 |
| Node 5 项 | 真实 UUID、不可变请求、错误分类与实际 HappyDOM sessionStorage 的命名空间、容量、损坏/重复记录校验 |
| 契约与治理 | 真实源码/端点/词汇契约、生产构建、模块边界、导入绑定、脚本路径、生成接口账与 Mermaid 实际解析 |

联调为 store/传输/后端验证，不是实际浏览器 DOM 操作；故障代理转发生产路由实际响应，未生成业务成功返回。数据库故障注入仅作用于测试临时数据库。

## 失败与未完成边界

首次故障注入重命名整表，被数据库初始化自动重建表打断；改为重命名真实列后，故障触发 503，恢复列后回归通过。初次命令路径和构建工作目录错误已修正，保留原退出日志。首次登记忘记同步固定数组长度，账本识别到声明 249/解析 250 的不闭合；修正长度并重生成后闭合。

额外严格 `-D warnings` 检查未通过：依赖知识图谱算法有 56 项 lint 错误；限定网关的严格检查也有既有未使用变量/导入等告警。未添加 allow、未降低 workspace 门禁；常规 Clippy 与严格检查分别记账，不能称全仓 lint 全绿。

仓内历史 `alliance-experts.store.test.js` 使用服务替身，仍包含“没有收藏读取/仅会话级”的旧断言，需要迁移到真实 fixture。本轮不扩充业务 mock，不把旧服务替身测试或其他作者的旧全量结果作为本次验收证据。全量 Vitest/全仓构建/远程 CI 没有完成本轮复核。

生成 API 注册表时也带出了后端已经登记的两个 webhook 运维接口。旧前端账将其列为“欠登记”，本轮按真实职责迁为“本业务模块不挂载的运维面”，没有制造未调用的 API 接线。85% 实际接线覆盖率门禁保持原阈值；由于运维页面尚未开发，当前实际覆盖 72/85，仍不足 85%，故契约门禁不能宣称全部通过，也不能将本轮作为可发布结论。

收藏仍为租户共享状态；本地数量和“只看收藏”仅作用于当前已加载页。跨标签页协调、关闭标签页后的恢复、全租户收藏分页、个人收藏、回执清理/保留窗口、实际浏览器 DOM 验收和跨主机一致性尚未交付。不能声明全部功能完成或企业生产验收通过。
