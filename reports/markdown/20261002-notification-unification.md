# 通知入口与事务收件箱归一验证

2026-10-02。功能契约唯一来源为[消息中心](../../docs/modules/message-center/README.md)。本批开发包含 notification.rs、消息仓储的批量已读/未读分类统计、通知前端和真实 HTTP 回归。

旧通知状态没有租户与收件人字段，曾读取全局集合并以整集投影保存已读。现停止读取无归属旧集合；列表、单条/全部已读和未读计数全部使用已有事务主源与可信身份。旧数据库集合和 JSON 文件未删除、未伪造归属。

真实 HTTP 用例创建两个租户、同租户不同用户的实际站内消息；验证分页、完整未读计数、越权拒绝、分页算术溢出拒绝和重复已读时间稳定。真实 SQLite 触发器拒绝批量更新时，消息及回执均回滚，HTTP 返回 503。

前端复用已有通知入口，补充分页、全箱未读徽标、详情、键盘操作、账号切换清空与旧请求拒绝回写；移除点击通知后无依据跳转 AI/任务页面。请求失败展示错误与重试；批量已读不自动重试。类别列表是当前页筛选，徽标是完整收件箱统计。

最终结果保存在 `reports/data/20261002-notification-unification/summary.json`，原始证据包括 tests.log、frontend-build.log、frontend-gate.log、clippy.log、doc-links.log。全目标检查期间发现其他模块收藏数据结构已变更而旧测试构造尚未同步；保留 clippy-red.log，按当前源码复核，不回退其他人的修改。

检查时网关 3080 未监听；本批前端验证限于构建和模块门禁，未通过 mock 后端或假登录补足浏览器业务验收。跨用户发送、组织/IAM 授权映射、历史归属迁移、跨主机集群和外部渠道仍未完成。

最终专项回归 13 项通过；Clippy 全目标编译通过（存量警告仍在），前端构建、模块/时间格式/文档链接/目录门禁通过。网关装配显式注入 enterprise.message_center，同一收件箱实例供企业消息与通知入口复用，不依赖各模块分别读取环境变量猜测数据库位置。
