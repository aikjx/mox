# 知识业务写入与全链路文档归一化

本轮修复了前后端版本语义分裂：编辑先读取完整文档，以一个 PUT 提交正文、备注与预期内容版本，服务原子归档旧正文并推进一次版本。列表摘要不再作为空正文的编辑来源；冲突返回 409 并保留未保存表单。旧客户端仍可不携带预期版本，尚未强制所有入口采用条件写入。

分析、批处理、创建版本及回滚保存使用完整原始快照比较，防止期间内容或 ACL 修改被迟到结果覆盖；普通 update 的既有存储错误类型继续保留。标签同计数时按名称排序，避免重复查询顺序不稳定。此比较是同一服务状态实例内的保护，不是跨进程 CAS、持久化 generation 或跨存储事务。

文档已统一入口与状态权威：资源知识 README → 架构/数据/API 契约 → BUSINESS-FLOWS 当前实现链路与目标流程 → IMPLEMENTATION-STATUS 实施台账 → DELIVERY-MATRIX 20 维交付检查。总表已将现有知识授权、共享撤权和检索过滤归回实现项；历史验收报告保持原时点。流程图明确身份、授权、主源、加工、图投影、检索、撤权与恢复，并标出文件源版本、独立 KB 迁移、会话权限及队列等断点。
