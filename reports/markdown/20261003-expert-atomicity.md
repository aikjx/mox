# 专家管理事务一致性验证（2026-10-03）

本轮修复注册、更新与软删除的存储失败假成功。注册与禁用把专家单行和事件信封在同一 SQLite 事务提交；提交成功后才更新内存与广播。更新复用同一单行写入，不新增事件类型、表或依赖。三个管理入口使用阻塞线程执行提交段。

## 验证与证据

- 真实 JWT、TCP、临时 SQLite；新测试不启动事件日志消费者，验证成功回执之前事件已经持久化。
- 专家 INSERT、UPDATE 和事件 INSERT 触发器真实拒绝，验证 503、回滚、原内存保留及无成功广播；事件插入静默忽略也不能假成功。
- 独立连接新增同租户行后更新既有专家，该行保持；异租户删除 404，普通用户管理 403，软删除后查询 404。
- 初始红测记录旧实现拒绝 INSERT 却返回 200。首次修复测试发现新增行的 JSON ID 不正确，修正测试数据后通过；失败日志保留。
- 两项前端契约仍匹配旧保存语句，更新为检查单行提交、enabled 持久化及提交早于投影和广播，未降低原要求。
- 旧单元写测试只播种内存；改为独立临时 SQLite 播种真实记录，保留原合并和软删除断言。
