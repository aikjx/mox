# 企业模块需求归一与消息发送验证

2026-10-02。主题入口：[企业功能需求](../../docs/modules/enterprise-capabilities/README.md)。报告记录本轮改动与验证，不替代模块实现主源。

## 交付范围

从实际 platform/domains 和现有模块权威建立 26 个逻辑能力、78 条显式编号需求，关联代码归属、事实所有权、前置能力、每模块目标流程、当前核验边界和优先级。生成模块卡、前置关系图；另整理 8 条跨模块业务主链，明确授权、失败、未知结果、版本与恢复接缝。需求和关系只有 registry.json 一份编辑主源；生成文档漂移必须修正主源并重新生成。

登记校验器检查全部实际域覆盖、代码和文档路径、编号碰撞、未知依赖、前置环及生成漂移。检查通过不证明能力已部署或全部功能完成。概览引用端口/API/代码目录主源，移除过期端口、路由数量和没有证据的全绿描述；修正模块导航误指向上级 README 的链接。

CI frontend-governance 加入登记一致性、登记器测试和发送/凭证/审计 Node 契约测试。代码目录生成器补入 src/modules 文件，避免模块化页面和契约被漏记；本地生成漂移检查通过。未运行远程 CI。

开发独立消息发送模块 `/messages/send`：实际 API、当前用户自收或真实收件人 ID、文本正文、去重排序、真实 UUID 幂等尝试、显式未知结果重试、actual message_id 成功回执、身份切换和销毁请求失效。复用 IAM 授权和事务收件箱，不替换业务服务。页面仅开放 in_app，外部渠道、定时发送和运营能力保持待开发。

服务端拒绝空白/超长标题和正文、空白/超长收件人 ID；模板渲染后也校验。新增真实临时 IAM/收件箱文件、JWT、TCP HTTP 测试：拒绝零写入，Unicode 最大边界成功，原键重试同消息 ID、仅一条提交。修复前测试真实失败（空标题返回 200）；失败记录和复查日志保留。

## 证据与限制

专项结果：21 项 Rust 真实存储/HTTP 回归、12 项 Node 契约、2 项实际 Vue/Element Plus 组件回归和 6 项需求登记器测试通过；35 张图经实际 Mermaid 解析。前端生产构建、Clippy、生成目录/需求漂移、前端模块化、locale、接口绑定、反馈/框架导入、主题、路径和相关自检通过。组件回归针对共享分页表格，不冒认新发送页面浏览器验收。

门禁保留已有 Clippy 建议、284 项端口 WARN、215 项文档反引号提示与26 项前端注释提示；退出码通过不等于这些存量提示消除。范围内 diff 和 Rust 格式已验证。

命令、退出码和完整日志归档于 [证据目录](../data/20261002-enterprise-capabilities/)，最终汇总见 [summary.json](../data/20261002-enterprise-capabilities/summary.json)。Node 仅测实际契约与不可变命令，无业务替身；既有 mock 隔离测试不计真实业务验收。公式自检首次遇到 Windows GBK 输出异常，复查固定 UTF-8 环境，不修改判据或阈值。

未验收：新发送页面完整浏览器流程、跨页面草稿恢复、发送人结果对账查询、目录选人、限流/容量/保留、外部消息 outbox、真实 OSS/模型成功链路和跨主机灾备。全部模块需求已经登记并关联，不意味着全部功能模块已开发完成。其他模块继续按其退出条件逐项推进。
