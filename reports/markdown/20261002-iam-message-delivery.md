# IAM 跨用户消息交付验证

日期：2026-10-02。模块事实主源：[消息中心](../../docs/modules/message-center/README.md)。范围为真实站内消息，未使用 mock 业务服务，也未将组织示例员工当作收件人目录。

## 已开发

- 生产宿主注入真实 IamRepository，发送身份来自已验签 JWT，逐次校验真实租户、发送人与所有收件人。
- 跨用户要求启用的 message:send 权限或实际超级用户；不使用 JWT 角色和权限缓存，停用角色、权限或用户立即影响后续请求。
- IAM → 收件箱固定锁顺序，IAM BEGIN IMMEDIATE 保持至业务提交；支持同主机不同连接间的撤权顺序约束，未声称跨主机一致性。
- 单批输入最多 100 个 ID，去重投递；全批消息、独立回执和发送人幂等键一次提交。任一收件人写入失败，整批及幂等占位回滚。
- 每个收件人拥有独立已读状态，payload.receiver_ids 仅含自己，发送人无隐含收件箱访问权。
- 发送人作用域幂等表与一次性迁移标记兼容旧自收消息，不清除历史消息、回执与已读状态。
- 消息及通知的查询、计数、单条和批量已读复用 IAM 启用校验；仍持有未过期 JWT 的停用用户无法访问消息。

## 验证

专项使用生产路由、真实 JWT 验签、真实 TCP 和 SQLite 文件。新增用例通过两个独立 IAM 数据库连接和两个 HTTP 服务处理 12 个并发发送请求，确认同一发送人幂等键只产生一个批次。另一个发送人使用同名键独立投递。

实际删除角色权限关联后，相同幂等请求返回 403；跨租户或停用收件人返回统一 403。实际 SQLite 触发器在第二个收件人回执插入时拒绝写入，确认第一个收件人未残留消息，移除触发器后原键可成功使用。旧库表示重建后重试返回原 message_id，改变请求返回 409。

最终 15 项专项测试全部通过：delivery_truth 3、inbox_http 4、inbox_persistence 6、trusted_tenant_http 2。Gateway Clippy all-targets 退出 0，仍有既有告警；本次没有关闭或降低规则。范围内格式与差异检查通过。文档链接门禁退出 0，保留既有 215 条路径告警；临时新增报告未落盘时的断链记录也保留在首次日志中，最终日志确认已解决。

最终命令和退出码以 [summary.json](../data/20261002-iam-message-delivery/summary.json) 为准；日志和源文件哈希存于同目录。本批未修改前端，既有通知页面构建证据继续引用上一批 [通知归一报告](20261002-notification-unification.md)。构建通过不等同于浏览器完整验收。

## 实际限制与后续

普通用户 message:send 需配置真实 IAM 权限与绑定；现有内存 API 权限目录尚不能管理这些授权，管理界面/API 归一仍待开发。未完成发送页面、按租户/发送人限流、长期容量与保留、负载 SLO、灾备与故障转移。IAM 与收件箱要求不同 SQLite 文件，当前不支持同文件双连接布局。

未验证断电、IAM 撤权与提交的随机故障注入、跨主机集群、真实 SMTP/LLM/OSS 正向交付或完整登录浏览器业务链路。现有 12 并发 HTTP 验证证明同主机连接间事务行为，不是生产吞吐承诺。外部渠道和定时发送继续返回 501；不能据此报告整个企业系统已经完成。
