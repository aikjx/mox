# 专家联盟事件订阅归一化增量

日期：2026-10-02。范围：联盟事件契约、前端真实传输、后端 SSE 缺口语义、架构与业务恢复流程。未修改已有 Webhook 投递算法，不声称全联盟生产验收完成。

## 实现与设计

- 修复原生 fetch 错误路径、缺少 Bearer、AbortController 未传入请求等问题。
- 将协议传输与 Vue 身份生命周期分开，端点沿用 contract 目录，认证沿用现有 store；旧连接和身份切换结果隔离。
- 增加严格 UTF-8/JSON 分帧、1 Mi 字符单帧上限、异常响应检查和明确关闭回调。
- 后端保留真实业务事件 ID；慢消费者获得 StreamGap 恢复指令，不泄漏其他租户活动数量，不发送空对象伪装业务事件。
- [主题契约](../../docs/expert-alliance/21-event-delivery-contract.md) 给出模块关系图、业务恢复流程图、7 项可验收要求、与企业登记的关系及未完成项；已关联当前架构和唯一索引。

## 验证口径

原始命令、工作目录、退出码和日志存放于 [证据目录](../data/20261002-alliance-event-contract/)。Node 的 HTTP 服务是实际 TCP 服务，没有替换 fetch 或伪造 ReadableStream；Rust 缺口测试使用真实 broadcast 和生产 SSE body，既有端到端测试继续使用真实 HTTP、JWT、SQLite。没有新增 mock。

最终检查及结果以同目录 `summary.json` 为准。先记录失败再修复：新增测试缺少实现时失败；模块化检查发现两个跨目录相对导入，已改为 contract 的统一出口，没有降低门禁。

扩展运行已有契约测试最终为 116 通过、4 失败：旧断言与当前后端源码不一致，涉及 favorites 声明格式、分发审计调用、软删除持久化调用和固定行号锚点。失败日志完整保留，不跳过或删除断言，不把本轮验证标成全仓通过。首次从仓根运行未加载前端配置，随后按前端配置重跑；端点消费扫描要求字符串字面量，已保留端点名常量修复该项。

## 剩余边界

订阅 composable 尚未接入业务视图，前端完整浏览器链路未验收。业务与事件不是原子 outbox；不支持持久队列、跨实例交付或 Last-Event-ID 重放。Webhook 仍需真实管理授权、出站目标策略、签名、订阅持久化、幂等及死信恢复。本轮实测成功不能证明这些能力已经完成。远程 CI 未运行。
