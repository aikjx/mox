## 2. 开发完成的本轮功能

以前 Webhook 全局串行投递，一个慢接收端会拖住后续租户；同步 SQLite 写入和长持有注册表锁也会冻结异步工作线程。真实慢 TCP 接收端等待释放时，后续快租户超过 500ms 仍未收到，失败证据保留在 [performance_red_ready.log](../data/20261003-architecture-performance/performance_red_ready.log)。首次测试准备遗漏订阅就绪等待，先得到另一份 setup 失败；修正测试准备后才得到上述确定的生产阻塞证据，未把准备问题归为业务缺陷。

新增有界跨事件并发 dispatcher，复用既有 FuturesUnordered/HTTP client，默认 8、允许 1–64，在途重试也占用槽；只保留一个事件目标快照，不无限 spawn 或按目标重复序列化。广播落后现在有真实告警。管理员读写/分页及事件日志存储通过 spawn_blocking，提交后只短暂修改热投影；不会在 SQLite 忙锁等待时占住注册表。join 失败明确提示未确认，授权和存储失败路径保持原契约。

实现与业务流的唯一权威为 [事件契约 §6](../../docs/expert-alliance/21-event-delivery-contract.md#6-2026-10-03-有界投递与存储调度增量)，配置归 [部署模板](../../docs/expert-alliance/09-deployment-templates.md)。没有新依赖、模拟服务、削弱断言或全量微服务重构。

有空闲槽时慢目标与快目标可以并行；全部槽饱和仍排队，没有租户公平或隔舱保障。并发不保证同订阅有序完成，不能用迟到事件覆盖当前业务状态；配置 1 可保留串行行为。日志/广播仍不是事务 outbox，没有持久队列、投递幂等、签名、死信、DNS 钉住或重放。本轮没有将这些未开发项升级为完成。

## 3. 真实测量和融合测试

性能测试使用单线程 Tokio、真实 Axum TCP 接收端、生产 dispatcher、实际 JWT 管理路由、临时 SQLite，以及另一 OS 线程上的 IMMEDIATE 写锁。慢目标始终在快目标到达后才释放；六个慢事件下接收端实际峰值不超过配置 2。真实创建请求和异步事件日志同时等待写锁时，运行时仍处理 HTTP 探针。30 次样本与中位数/p95/最大值由 [结构化摘要](../data/20261003-architecture-performance/summary.json) 从最终原始日志计算，不手填“最优”指标。

最终样本的快目标延迟中位数 **0.4445ms**、nearest-rank p95 **0.646ms**、最大 **1.969ms**；SQLite 写锁下探针 **63ms**（包含测试故意等待的 50ms）。仅说明该本机受控场景的阻塞修复，不与生产负载或其他产品作速度比较。

这些是本机单场景调度测量，不能外推公网 RTT、持续吞吐、p99、生产负载或跨主机 SLO。当前仍有单事件大 fanout、全量热投影查询、饱和公平、事件总线丢失和线程池压力风险；outbox 和容量演练是后续实际交付要求。

## 4. 后续按依赖开发

1. 持久业务提交和事件 outbox 同事务，消费租约/fencing、投递幂等与失败恢复；先处理业务 repository 的当前 best-effort 写入边界，再开发后台可靠消费，不能把广播落盘叫作 outbox。
2. 文件源/知识版本统一关联与 KB 主源迁移；两租户授权、共享撤权、源删除和失效加工隔离通过后，再接检索/图谱/联盟工具。
3. 知识加工持久队列、发布版本与来源证据，真实 OSS 协议往返和对象位置迁移；配置缺失不冒充成功。
4. 模型/工具真实执行、动态配置发布、数据同步、项目/语音/市场逐要求测试，然后完整浏览器、跨主机、压测、灾备和发布回滚。

用户的全功能企业目标保持开放；本轮关闭的是具体阻塞和结构核对项，所有模块的独立退出条件仍由真实证据决定。
