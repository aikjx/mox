## 3. P1-1 — GraphView 渐进加载

### 3.1 问题定性

原 GraphView.vue 在 `<script setup>` 顶层同步 `import ForceGraph3D from '3d-force-graph'`，导致：
- three + 3d-force-graph + 附属资源 ≈ 1.3MB，被塞进 GraphView 懒加载 chunk 本体
- 用户点击导航进入 `/graph`，必须先下载 1.3MB + 解析 + 初始化力学 → **白屏时间约 3-5s**（低端机更长）

### 3.2 四阶段渐进加载实现（GraphView.vue）

**阶段 0（Skeleton）**：挂载后立即渲染 `<svg id="graph-skeleton">`（纯 SVG 画布，0 额外依赖，< 5ms 呈现骨架）。  
**阶段 1（Module）**：`setStage('module')` → 启动 `import(/* webpackChunkName: "3d-force-graph" */ '3d-force-graph')` 动态 import。  
**阶段 2（Layout）**：在 3D 库加载前，先对节点执行 **`applyCircularLayout()`**（静态圆形布局 + 按层级分圈），保证用户"先看到一张稳定的 2D 关系图"。  
**阶段 3（Physics）**：库就绪 + 3D Canvas 挂载后 → **延迟 260ms** 再 `d3Force('link', ...).d3Force('charge', ...)` 启动力学。  

用户体感路径：**骨架 → 静态关系图 → 稳定后力学动画**（任何一步未完成用户都有可感知内容，不再白屏）。

### 3.3 构建产物验证（chunk 清单节选）


✅ **GraphView 同步包从 1,339 KB → 15.09 KB，降幅 = 98.9%（88.8×）。**
✅ 1.3MB 3D 资源作为独立异步 chunk，首次访问首页不下载。

### 3.4 向后兼容

| 3 | **前端鲁棒性（缓存 rejected Promise）** | `GraphView.vue loadForceGraph3DModule()` | 动态 import 失败后 `_fgLoaderPromise` 缓存 rejected，下一次 reload() 永久失败（必须整页刷新） | `.catch(() => { _fgLoaderPromise = null; throw err })`：失败时清空缓存，允许用户再次点击重试。 |
| 4 | **前端 P1-1 优化效果打折（串行≠并行）** | `GraphView.vue reload()` | 注释写"并行"，但代码先 `await fetchTask` 取数完成后才调 `loadForceGraph3DModule()` 下 1.3MB chunk → 实际上是**串行**，浪费 P1-1 节省的网络时间 | `fetchTask` 和 `load3dTask` 同时启动，用 `Promise.all([fetchTask, load3dTask])` 等待。最差情况与串行相同；最好情况可节省 ≈ 60% 等待时间。 |
| 5 | **判分覆盖不足（宽松变体遗漏）** | `ai-engine-real-benchmark.js` date_exact 判分 | `mVariants` 只有 `8月`，对真实用户回答 `2026 年 8 月 24 日` 带空格的回答 loose 判分失败；`"号"` 变体 `24号` 也 loose 挂 | mVariants 追加 `8 月 / 08 月`（空格变体）；dVariants 追加 `24 日 / 08 日 / 24号 / 24 号 / 08号 / 08 号`。gradeDateExact 11/11 严格+宽松逐例判对 ✅ |
| 6 | **E2E 死代码（永远 false 表达式）** | `10-key-pages@P0.spec.js` ok 断言 | `Array.from(page.title + '').some(() => false)` 永远 false，误导维护者以为有第三种判定路径 | 删除死代码，注释说明"title 正则命中 / 文本长度 > 120 二选一"即可。 |

### 9.2 A3 深度优化建议（非阻塞 · 可纳入下一轮 P2）

| ID | 项 | 类别 | 说明 | 收益评估 |
|---|---|---|---|---|
| A3-1 | **GraphView stage 细粒度超时保护** | 体验优化 | fetchTask 卡 API 时，`setStage('fetch')` 可能停留 >10s；建议为每个 stage 设超时阈值（10s/15s），超时后自动弹 "正在加载…" 提示或降级静态骨架 | 感知体验更顺滑，避免用户以为白屏 |
| A3-2 | **GraphView fg 对象用 shallowRef + 清理** | 内存优化 | 当前 `fg = null` 是普通变量，但 ForceGraph3D 返回对象内部还挂 three.js 的 renderer/camera/scene；在 `onBeforeUnmount()` 里应 `fg?.graphData({nodes:[], links:[]})` + `fg?._destructor?.()` + `fg = null` 显式释放 1.3MB 资源 | 反复进出 `/graph` 路由不会泄露 three renderer 内存 |
| A3-3 | **边类型统一为枚举常量** | 代码一致性 | `relation-registry.js` 的 `type:` 目前是字符串；建议改为 `const EDGE = { DEP: 'depends_on', DEL: 'delegates_to' ... }` 常量引用，避免又出现"serves_note"之类自定义漏网 | 杜绝边类型漂移；verifyFullChain 能通过"未知边类型 → 直接 fail"闸门 |
| A3-4 | **gradeAnswer 做 wrapper 单元测试** | 可测试性 | 今 gradeDateExact 通过 verify_grade.js 验证；但整个 `gradeAnswer()` 有 8 种 type（number_exact/choice_exact/keywords_any/code_keywords/string_exact/instruction_lines/instruction_lines_count/json_schema）。建议产出 `test-gradeanswer.js` 覆盖全部 8 种 | 防止未来题库扩展时 regression 被漏过 |
| A3-5 | **Playwright 多浏览器 + 路由全集** | 覆盖率 | 当前仅 chromium P0 10 页 smoke + 白名单化 NetworkErr；可加 WebKit + Mobile + 24 条业务路由覆盖，并起本地 mock server (msw) 代替真实后端 | 覆盖率从 ~30% 提升 → 100% 路由绿 |
| A3-6 | **engine-universe 边重复检测** | 可靠性 | verifyFullChain 目前不校验 from/to/type 重复边；但实际 81 条边存在"重复等价边"风险（如 equivalent_to 被声明两次，浪费流量）| 新增 check：`重复边计数 = 0`，与边类型枚举检查一起作为 P2 闸门补充 |
